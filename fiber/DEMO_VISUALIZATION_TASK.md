# Постановка задачи: демонстрационная визуализация «снаряд пробивает сеть из нитей»

Написано для: разработчика, который будет реализовывать демо-сценарий и визуализацию поверх
готовой системы нитей (см. `fiber/IMPLEMENTATION_REPORT.md`, `fiber/SPH.md`).

## 1. Цель

Нужна наглядная демонстрация совместной работы Solid и Fiber на сцене среднего размера
(100–1000 SPH-частиц твёрдого тела + 2 нити), задействующая по возможности все типы
взаимодействий нити: растяжение связи (Fiber-Bond), контакт нить-нить (Fiber-Fiber-Contact),
контакт нить-тело (Fiber-Solid-Contact) и разрыв связи (Postprocessing). Существующие
регрессионные/e2e-тесты для этого не подходят — они рассчитаны на проверку инвариантов
(3-й закон Ньютона, предельные переходы), а не на визуальное представление, и используют
сцены на 5–7 бусин.

Результат — короткая анимация (GIF или MP4), показывающая: снаряд из SPH-частиц подлетает
к сети из двух перекрещенных нитей, сеть тормозит/деформирует снаряд, нити натягиваются
(видно по цвету) и, если превышен порог `l_break`, одна из связей рвётся на глазах.

## 2. Сценарий

- **Снаряд** — компактное тело из 100–1000 SPH-частиц (например, куб или шар из решётки,
  как в `tests/bc2_mini3d_geometry.hpp::build_geometry()` или упрощённо, по образцу
  `build_plate()` из `tests/test_e2e_fiber_solid.cpp`, но объёмное, а не плоское). Материал —
  тот же, что уже используется для похожих сцен (алюминий, `itype=body=4`, как в
  `build_plate()`). Начальная скорость — по направлению к сети, порядка десятков м/с (подбирается
  так, чтобы деформация нитей была заметной, но расчёт не расходился; ориентир — параметры
  контакта из `test_e2e_fiber_solid.cpp`).
- **Сеть** — 2 прямые нити, пересекающиеся под углом (например, крестом, как в
  `test_e2e_fiber_contact.cpp`, но длиннее — 10–20 бусин на нить вместо 7, чтобы деформация
  была видна на анимации), расположенные перпендикулярно траектории снаряда так, чтобы он
  прошёл сквозь точку их пересечения.
- **Материал нитей** — параметры того же порядка, что в `test_e2e_fiber_contact.cpp`
  (`E≈2e7`, `nu=0.3`, `d≈1мм`, `rho≈1200`), но `eps_break` (порог разрыва, задаёт `l_break`)
  должен быть подобран так, чтобы разрыв **произошёл** при заданной скорости снаряда — это
  открытый параметр, требующий подбора в реализации (не обязательно рвутся обе нити).
- **Открытый вопрос реализации — закрепление концов нитей.** В `FiberState`/`FiberTopology`
  нет отдельного механизма "заделки" (fixed boundary): все бусины — обычные частицы со своей
  массой, которые двигаются под действием сил. Чтобы сеть визуально вела себя как закреплённая
  (а не улетала целиком от удара), предлагается искусственно увеличить массу концевых бусин
  каждой нити на 1–2 порядка — дешёвый приём "псевдо-анкера". Финальные значения массы/числа
  утяжелённых бусин на конце — подбираются экспериментально при реализации; в этом документе
  фиксируется только сам приём, а не конкретные числа.

## 3. Как построить сцену — переиспользуемые части

Отдельного генератора геометрии для fiber-сцен в проекте нет — обе e2e-нити строятся вручную
функцией `append_chain(FiberState&, FiberTopology&, base, object_id, material_id, beads, mass_each)`
внутри самих тестов (`tests/test_e2e_fiber_contact.cpp`, `tests/test_e2e_fiber_solid.cpp`),
её стоит скопировать/обобщить, а не писать заново.

Два равноценных способа задать сеть:
1. Вручную через `append_chain` (быстрее для скрипта-прототипа, не проверяет продовый парсер).
2. Через файл нитей формата `fiber_input.cpp` (`MATERIAL id E nu d rho eps_break` /
   `FIBER material_id point_count` + точки) и `fiber::load_fiber_file()` — предпочтительнее,
   т.к. задействует реальный продовый путь загрузки (`SimulationConfig::fiber_file`,
   `src/input.cpp:399-406`), который в e2e-тестах не используется и потому менее проверен
   на практике. Рекомендуется выбрать этот способ, если не найдётся веских причин иначе.

Для геометрии снаряда — решётка по образцу `tests/bc2_mini3d_geometry.hpp::build_geometry()`
(узлы `x=(i+0.5)*dx`, отбор по радиусу для сферы/цилиндра или без отбора для куба,
`sys.resize()`, `inzializ_index()`, заполнение `mass/rho/itype/hsml`, обязательно `sys.body[k]`).

Конфигурация симуляции — обычный `SimulationConfig` (см. `include/simulation_config.hpp`),
`dim=3` (обязательно для нитей, проверяется `check_fiber_requires_dim3()`), `fiber_file`
указывает на файл сети, `contact_force_type` и `ode_solver` — значения по умолчанию, если нет
причин их менять; `save_t` подобрать так, чтобы получилось 30–100 кадров на весь пролёт.

## 4. Расчётный драйвер

В отличие от e2e-тестов, которые пишут собственный локальный цикл интегрирования
(`FiberOnPlateIntegrator`, `FiberBondContactIntegrator`), демо должно использовать **продовый**
путь: `time_integration(cfg, model, n, dt, time, delta_x, &guard)` для `fiber::Model`
(include/time_integration.hpp), т.е. обычный main-цикл симуляции, что дополнительно послужит
проверкой продового пути на сцене нового размера (100–1000 частиц), которая раньше не
прогонялась.

**Важно и потребует доработки:** согласно отчёту о внедрении, `fiber::fiber_output()`
(include/fiber/fiber_output.hpp) **не вызывается автоматически** из `time_integration` —
только обычный `output()` для Solid/SPH (`src/output.cpp`, вызывается из
`src/time_integration.cpp:239` по условию `time >= next_output_time`). Чтобы получить кадры
нитей для визуализации, реализация должна либо вызвать `fiber::fiber_output(model, itimestep, time)`
рядом с существующим вызовом `output()` (та же частота `save_t`), либо в собственном
внешнем цикле вокруг `time_integration`, если менять `src/time_integration.cpp` нежелательно.
Выбор — на усмотрение реализации, но фиксация должна быть **той же периодичности**, что и
обычный вывод, чтобы кадры обоих форматов совпадали по номеру шага/времени.

## 5. Формат вывода (уже готов, ничего создавать не нужно)

- `sph_output_<N>.txt` — обычный текстовый кадр Solid/SPH-частиц (`src/output.cpp`, формат
  описан в `docs/03-reference/file-formats/dat-output.md`): колонки
  `x y z vx vy vz rho p u c sigma_i e_pl D hsml sxx syy szz sxy syz sxz` (индекс с 1).
- `fiber_output_<N>.txt` — кадр нитей (`src/fiber_output.cpp`):
  ```
  TIME <t> STEP <itimestep> N_PARTICLES <n> N_BONDS <nb>
  # id object_id material_id x y z vx vy vz
  PARTICLES
  <n строк>
  # i j l0 l l_break elongation
  BONDS
  <nb строк>
  ```
  Разрыв связи виден напрямую: у связи из `N_BONDS` на предыдущем кадре пропадает строка в
  `BONDS` следующего кадра (или `topology_version` в модели увеличивается — если понадобится,
  можно завести отдельный счётчик событий в самом драйвере демо).

## 6. Требования к визуализации

Готового инструмента для рендеринга сцены (SPH-частицы + нити) в проекте нет — писать с нуля.

- Python-скрипт, читающий пары кадров `sph_output_<N>.txt` + `fiber_output_<N>.txt` по номеру
  N и строящий 3D-анимацию через `matplotlib` (`mpl_toolkits.mplot3d`, `FuncAnimation`,
  сохранение через `PillowWriter` в GIF или `ffmpeg`-writer в MP4).
- SPH-частицы снаряда — облако точек (`scatter`), цвет — по давлению `p` или модулю скорости
  (колонки уже есть в `sph_output_*.txt`).
- Нити — отрезки между бусинами по списку `BONDS` (не просто по порядку id — после разрыва
  список бондов меняется), цвет отрезка — по `elongation = l/l0 - 1` (например, зелёный →
  жёлтый → красный по мере приближения к порогу разрыва); разрыв связи виден как исчезновение
  отрезка между соответствующими кадрами.
- Один фиксированный ракурс на всю анимацию (в момент подбора сцены можно проверить несколько
  и оставить наиболее наглядный — сбоку, чтобы был виден пролёт и провисание сети).
- Скрипт может быть учебным/одноразовым — не требуется встраивать в CMake/ctest.

## 7. Критерии приёмки

- Анимация наглядно показывает: приближение снаряда → контакт с сетью (заметная деформация,
  натяжение нитей по цвету) → торможение/прохождение снаряда → (если подобран `eps_break`)
  видимый разрыв как минимум одной связи.
- Должно быть заметно взаимодействие именно двух нитей друг с другом в районе пересечения
  (Fiber-Fiber-Contact), а не только с снарядом.
- Расчёт не расходится (не NaN/не разлёт частиц на десятки метров) в пределах промоделированного
  времени — базовая физическая правдоподобность, формальная проверка энергии не требуется.
- Сцена и конфиг демо не должны менять существующий продовый код физики/схемы взаимодействий;
  если пункт 4 потребует правки `src/time_integration.cpp` (добавление вызова `fiber_output`),
  это должно быть единственное такое изменение и не должно повлиять на `ctest -L regression`
  (14/14 без перегенерации эталонов — см. `fiber/IMPLEMENTATION_REPORT.md`, раздел 1).

## 8. Вне скоупа

- Производительность/GPU/параллельная визуализация.
- Тангенциальное трение в контактах (не реализовано в проекте вовсе, см. `fiber/SPH.md`).
- `sle=2` (не реализован на новом пути).
- Интерактивность (вращение сцены мышью, real-time просмотр) — только заранее отрендеренная
  анимация.
- Встраивание сценария/визуализации в тестовую инфраструктуру (ctest) — это демо-артефакт,
  не регрессионный тест.
