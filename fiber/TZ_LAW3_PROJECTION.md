## 0. Задача в двух фразах

Нормальную силу законов контакта нитей 1–3 (в первую очередь закона 3) перенести из RHS в отдельную
стадию между выбором шага и трением. Там она решается как проекция скорости: после шага пары на активных
контактах не сближаются. Цель — убрать туннелирование (дрейф проникания) **без** вброса энергии, который
давало выталкивание `--impulse-push-tau`.

Результат работы — код за ключом, модульные тесты, прогон регрессии, серия на сцене Guo 1T и отчёт с
таблицами (§6).

## 1. Правила

1. **Ветка.** Базовая — `fiber_divergence_diag` (в ней есть коммит `6f1b63f`, детерминированное суммирование).
   Проверить: `git merge-base --is-ancestor 6f1b63f HEAD`. Работать в новой локальной ветке
   `fiber_contact_projection`.
2. **Коммиты — только локально. `git push` не делать** без явного разрешения Владимира.
3. **По умолчанию поведение прежнее.** При выключенных новых ключах счёт должен быть **побитово** таким же,
   как до изменений. Это главный критерий регрессии.
4. **Эталоны регрессии не перегенерировать** (`regression_golden`, `--emit-golden`, файлы в `tests/data/regression/`).
   Если регрессия упала при выключенном ключе — это ошибка в коде, а не повод обновить эталон.
5. **Существующие тесты не отключать и не ослаблять** их допуски.
6. **Выталкивание не использовать** (`--impulse-push-tau` > 0 запрещён владельцем с 2026-10-21). В режиме
   проекции он должен давать ошибку разбора.
7. **Детерминизм.** Только `parallel_for` + `ContributionWriter` + `reduce_contributions_into`, как в
   `fiber_friction.hpp`. Никаких atomics, mutex, хеш-таблиц с недетерминированным порядком.
8. Комментарии и сообщения коммитов — по-русски, в стиле окружающего кода.
9. **Если что-то из плана не получается или противоречит коду — остановиться и описать**, а не обходить.
   Особенно: побитовая несовместимость при выключенном ключе, рост δ в тесте статики, положительная работа
   контакта.

## 2. Этап A. Реализация

Делать по `LAW3_VARIANT1_VELOCITY_PROJECTION.md` §4–§5. Кратко:

### A1. Ключи

| Ключ конфига | CLI `guo2019_shot` | Значения | По умолчанию |
|---|---|---|---|
| `fiber_fiber_contact_predictor` | `--ff-contact-predictor=0\|1` | 0/1 | 0 |
| `fiber_solid_contact_predictor` | `--fs-contact-predictor=0\|1` | 0/1 | 0 |
| `fiber_contact_projection_iters` | `--contact-proj-iters=N` | 1…100 | 8 |
| `fiber_contact_projection_warm` | `--contact-proj-warm=0\|1` | 0/1 | 1 |

- Разбор — `src/input.cpp` (рядом с `fiber_fiber_contact_type`, строки ~235–265), чекпоинт —
  `src/checkpoint.cpp:273–280`, CLI — `tools/guo2019/guo2019_shot.cpp` (`parse_args`, `print_usage`),
  значения в `shot.txt`.
- Predictor = 1 действует только при законе 1–3 на этом виде контакта; при законах 0 и 4 — ошибка разбора
  или явное предупреждение (выбери одно и опиши).
- Predictor = 1 и push_tau > 0 — ошибка. Predictor = 1 и γ ≠ 1 — предупреждение, γ игнорируется.

### A2. Нормальные слоты

В `compute_fiber_contact_contributions` (`fiber_contact.hpp`, ~780) и `compute_fiber_solid_contact`
(`fiber_solid_contact.hpp`) при predictor = 1:
- для **каждого** контакта с `geom.contact` (δ > 0) заполнить слот (бусины, веса, нормаль, δ, μ, ключ пары),
  даже при μ = 0;
- вкладов нормальной силы в ускорение **не** писать;
- `pair_dt_limit` = `contact::kNoLimit`.

### A3. Стадия проекции

Новый заголовок `include/interactions/fiber_normal_projection.hpp` по образцу `fiber_friction.hpp`:
формулы одного контакта отдельно от обхода, счётчики c_k/c_s (обобщить `compute_friction_counts`), учёт
зажимов как в `apply_clamp_friction_counts`, K итераций Якоби с накопленным зажатым импульсом,
тёплый старт по ключам пар (сортированный массив + бинарный поиск, P^{(0)} = P^{prev}·h/h_prev).

Место в `src/time_integration.cpp`: после `if (fiber_dt_limit < dt) dt = fiber_dt_limit;` (~588), до
стадии трения (~591). База скоростей — `solver.fiber_velocity_update(fb, dt)` и
`solver.solid_velocity_update(sys, dt)`, у частицы шара учитывать XSPH `av`, как в трении.

После стадии: ускорения в `solver.fiber_rhs.dv` / `solver.solid_rhs.dvx`, N = P/h в слоты трения,
дальше трение как есть.

### A4. Учёт энергии и диагностика

- **Канал энергии.** Работа нормальных импульсов стадии должна идти в существующий канал
  `D_contact_fiber` (`include/energy_log.hpp`, `src/time_integration.cpp` ~486–536, ~700), тем же способом
  (`work_mid_fiber` / `work_mid_solid`, после проекции зажимов). Не путать с работой трения.
- Добавить отдельный столбец **приращения за шаг** или считать максимум положительной работы стадии за
  шаг (`W_proj_pos_max`), чтобы ловить отдельные шаги с вбросом.
- **В `monitor.csv`** (раз в `n_diag`): число активных нормальных слотов, max c_k, max c_s,
  остаток после K итераций `proj_resid = max_c (ṗ_c^{n+1})⁺` и он же в долях `h·N_c/m_red`,
  доля слотов с тёплым стартом.
- **В `shot.txt`:** новые ключи и итоговые максимумы остатка; существующие `max_delta_ff/d`, `max_delta_fs/d`,
  `n_tunnel` не менять.

### A5. Модульные тесты

Новый `tests/test_fiber_contact_projection.cpp`, регистрация в `CMakeLists.txt` по образцу
`fiber_friction_test` (метка `3d`). Тесты Т1–Т7 из `LAW3_VARIANT1_VELOCITY_PROJECTION.md` §7:

| Тест | Что | Порог прохода |

## 5. Этап D. Энергия не возрастает

По `energy_log.csv` прогонов C1–C5 (столбцы описаны в шапке `include/energy_log.hpp`):

1. **Работа контакта.** `D_contact_fiber` не должен убывать: приращение между строками ≥ −10⁻⁶·E0.
   Отдельно — максимум положительной работы стадии за шаг (`W_proj_pos_max`, §A4).
2. **Баланс.** `residual` — невязка баланса, `(E_mech − E_mech0) + все потери − источники`. Положительный
   `residual` означает, что энергии в системе больше, чем допускает баланс, то есть энергию что-то вносит.
   Критерии для C1:
   - max(residual)/E0 ≤ max(residual)/E0 у C3 (закон 4) + 0,5 % E0;
   - нет скачков: приращение residual между соседними строками лога ≤ 0,1 % E0;
   - для сравнения: с выталкиванием `D_contact_fiber` уходил в минус до −5,6…−37,5 % E0 в отдельных
     выстрелах (отчёт 2026-10-22 §5.3а), то есть контакт вносил энергию; в C1 `D_contact_fiber` должен
     оставаться ≥ 0 всё время.
3. **Ряды:** E_mech(t), D_contact_fiber(t), residual(t) для C1, C2, C3 на одном графике каждый.
4. Если появился вброс — найти шаг и контакты (по `W_proj_pos_max` и диагностике c_k), проверить
   гипотезу о перекомпенсации при нескольких контактах на бусину (`LIT_TUNNELING_LAW3.md` §2.3) и
   описать. Не исправлять подбором параметров без согласования.

Дополнительно (если хватает времени сервера): те же четыре V0 = 79·(1 + k·10⁻¹²), k = 0…3, с C1.
Это показывает разброс исхода при подавленном туннелировании и без вброса энергии
(`TUNNELING_REPORT.md` §4.3, §5).
