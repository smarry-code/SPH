* ===========================================================================
* Конфигурация расчёта для сцен Guo 2019 (tests/guo2019_scene.hpp,
* tests/test_e2e_guo2019.cpp, tools/guo2019/guo2019_shot.cpp).
*
* Разбирается той же функцией parse_sph_config(), что и боевой
* Initial_Conditions.txt (как tests/data/bc6_initial_conditions.txt): тест
* проходит через реальный путь загрузки конфигурации.
*
* Параметры решателя те же, что у BC6 (ТЗ Guo 2019 §3.6).
*
* Чего здесь НЕТ и почему:
*   t_total, save_t -- задаются кодом: smoke (20 мкс, кадр раз в 2 мкс) и
*     серия выстрелов (t_max по конфигурации, кадр 25 мкс) различаются;
*   delta_x, геометрия, moni_particle, maxn -- строит сцена в коде;
*   ode_solver при необходимости переопределяется из кода.
* ===========================================================================

* Метод аппроксимации давления
pa_sph = 2
* Метод поиска соседних частиц (2 = link_list)
nnps = 2
* Алгоритм обновления длины сглаживания
sle = 1
* Тип ядра сглаживания (1 = кубический сплайн)
skf = 1
* Число Куранта
CFL = 0.1
* Константа усреднения скоростей (Monaghan 1992)
epsilon = 0.25
* Псевдовязкость
alpha = 1.0
beta = 1.0
etq = 0.01

* Контакт «частица-частица»: тип 1 (Герц, min(F1,F2)). Рекомендация
* contact/11-contact-report.md §11. Работает между шаром (body 1) и пластиной
* (body 2); Fiber-Solid и Fiber-Fiber идут отдельным конвейером нитей.
contact_force_type = 1

* Масштаб штрафной силы Kp (тип 1): 1.0, как умолчание SimulationConfig
* (у BC6 ключ закомментирован по той же причине: на результат не влияет).
contact_penalty_scale = 1.0

* Решатель по времени: 0 = предиктор-корректор (PC).
ode_solver = 0

* Изоляция SPH-пар по телам (ТЗ Guo 2019 §4.2): пары реальных частиц с
* разным body в SPH-суммах не участвуют, шар и пластина взаимодействуют только
* через контакт. Без этого шар «приваривается» к пробке растяжением. Требует
* contact_force_type != 0 (иначе тела не видят друг друга вовсе).
sph_same_body_only = 1
