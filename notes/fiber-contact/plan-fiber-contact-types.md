## 0. Что изменилось относительно v1 (прочитать первым)

Всё ниже проверено по коду `318342c`.

| # | В v1 | На самом деле / решение v2 |
|---|---|---|
| 1 | `dt_ref_f = CFL·L/(c_f+|v|)` «как у связей» | У связей другой критерий: осцилляторный `0.8/√(E·A/l0 / m_red)` ≈ `0.57·l0/c_f`, без CFL (`fiber_bond.hpp:154-175`). Нити не входят в `compute_cfl_timestep`, поэтому CFL-вариант нарушает инвариант `dt_applied ≤ dt_ref`, на котором стоят формулы (`ext_force.cpp:78-80`). При CFL = 0.1 вязкая ветка pinball режет шаг до `0.16·L/c_f`, это примерно в 3.5 раза меньше шага связей. **v2: `dt_ref_f` = предел шага связей у бусин сегмента** (§2). |
| 2 | Для точечного контакта взять `l0` из топологии | У изолированной бусины нет связей, а в `FiberMaterial` нет `l0` (`fiber_system.hpp:157-166`). **v2: виртуальная связь длины `d`** (§2). |
| 3 | При разлёте `fn = 0` только у типов 2–3 | У pinball тоже: `f1 = 0` при `ṗ ≤ 0`, и `fn = min(f1, f2) = 0` (`contact_force.hpp:57-63`). Значит, **все три типа дают ноль в покое и при разлёте**: нет силы у неподвижного контакта, трение пропадает, отскока нет (контакт неупругий). Отсюда меняются тесты и риски (§6, §8). |
| 4 | Тип 3 получает «применяемый шаг» | В момент RHS новый шаг ещё не известен: `dt` пересчитывается после RHS (`time_integration.cpp:284-286`). Ядру доступен **шаг предыдущего цикла**, как и в Solid–Solid (`single_step.cpp:138,163`). Принять так же и написать в комментарии. |
| 5 | Про `PairGeom::r` ничего | Swegle делит на `g.r` и возвращает 0 при `r ≤ 0` (`contact_force.hpp:79-84`). В Fiber–Fiber бывает `D = 0` (оси пересекаются, `fiber_contact.hpp:536-560`), и Swegle молча отключится. **v2: `g.r = r_1 + r_2`** (сумма радиусов, всегда > 0) для обоих контактов (§2). |
| 6 | `dt_limit` для типов 1–3 пересчитать в отдельном проходе | Текущие `*_dt_limit` не получают скоростей, `dt`, `cfg`, `c`. Тройной пересчёт (kernel, dt_limit, диагностика) с новыми входами легко рассогласовать. **v2: ядро записывает `res.dt_limit` в слот на primitive, предел шага берётся редукцией по слотам** (§3.4). Путь типа 0 не трогать. |
| 7 | `sys.c` «проверить актуальность» | Проверено: `sys.c` пишется в конце `single_step` (`single_step.cpp:192`), до контактов нитей. Но `sys.hsml` к этому моменту уже обновлён `update_smoothing_length` (`time_integration.cpp:208`), а Solid–Solid видел старый `h`. Расхождение мелкое, его достаточно записать в комментарии. |
| 8 | «F2 pinball и Герц нитей отличаются на постоянный множитель» | Посчитано: для одного материала `F2/F_Hertz = 3(1−ν)/8` (≈ 0.26 при ν = 0.3). Pinball на герцевской ветке примерно в 4 раза мягче Герца нитей, значит проникание будет глубже. Записать в документацию, множитель не подгонять. |
| 9 | Номера строк | Сверены, исправлены ниже. `apply_defaults` на строке 109 (не 115). |

Остальное в v1 верно: формулы `ṗ` и знаки нормалей, `m_q` через `fiber_contact_side_inv_mass`, `m_red` для типа 0 без весов, `G_eff`, `R_eff = R_star`, раскладка по весам, баланс импульса, места вызова.

## 1. Решения (зафиксированы, не пересматривать без владельца)

1. Раздельные ключи для Fiber–Solid и Fiber–Fiber. `contact_force_type` (Solid–Solid) не трогать.
2. Два этапа: сначала Fiber–Solid, потом Fiber–Fiber. После каждого этапа зелёный коммит.
3. Значение ключа `0` = Герц (как сейчас), а не «выключено». В отличие от `contact_force_type`. Писать это в каждом комментарии у ключа.
4. При всех новых ключах = 0 результат побитово прежний (сравнение с `OMP_NUM_THREADS=1`).
5. Формулы сил не дублировать: только `contact::penalty_force` из `include/contact_force.hpp`. Сам этот файл не менять.

## 2. Общие определения (общие для обоих этапов)

Для пары «сторона 1 / сторона 2» заполняются `contact::PairGeom g` и `contact::PairProps pr`.

| Величина | Fiber–Solid (сегмент `a,b`, вес `λ`; частица `s`) | Fiber–Fiber (A: `a0,a1`, `s`; B: `b0,b1`, `t`) |
|---|---|---|
| нормаль `n` | от нити к Solid (`geom.n`) | от B к A (`geom.n`) |
| `g.p` | `geom.delta = r_f + r_s − D` | `geom.delta = r_a + r_b − D` |
| скорость точки | `v_q = (1−λ)v_a + λv_b`; без `b`: `v_a` | `v_A = (1−s)v_a0 + s·v_a1`, `v_B` аналогично; при `a1 = −1` только `v_a0` |
| `g.pdot` | `−n·(v_s − v_q)` | `−n·(v_A − v_B)` |
| `g.v_rel` | `|v_s − v_q|` | `|v_A − v_B|` |
| `g.r` | `r_f + r_s` (решение v2, см. §0 п.5) | `r_a + r_b` |
| `pr.m_red` | `m_q·m_s/(m_q+m_s)`, `m_q = 1/fiber_contact_side_inv_mass(a, b|−1, λ)` | `m_A·m_B/(m_A+m_B)` через ту же функцию |
| `pr.g_eff` | `G_f·G_s/(G_f+G_s)`, `G_f = E_a/(2(1+ν_a))`, `G_s = shear_modulus_by_itype`; при `G_s ≤ 0` → 0 | `G_a·G_b/(G_a+G_b)` по `a0`, `b0` |
| `pr.r_eff` | `R_star` (уже есть) | `R_star` (уже есть) |
| `pr.c_pair` | `min(c_f, sys.c[s])`, `c_f = √(E_a/ρ_a)` | `min(c_a, c_b)` |
| `pr.dt_ref` | `min(dt_ref_f, solid_contact_pair_dt_ref(cfg, sys, sys.c, s))` | `min(dt_ref_A, dt_ref_B)` |

Материал стороны нити: бусина `a` (Fiber–Solid, решение 4 в шапке `fiber_solid_contact.hpp`) и `a0`/`b0` (Fiber–Fiber), как у Герца.

Скорости: `fb.vx` и `sys.vx` в момент вызова обе в фазе предиктора (`solver.predict` до `single_step`, `time_integration.cpp:194`). Так и написать в комментарии ядра.

### `dt_ref` нити (решение v2, вместо CFL-варианта v1)

Свести в одну функцию в `fiber_contact_law.hpp`, чтобы замена определения была одной правкой:

```
dt_bond(i,j)  = 0.8 / sqrt( (E·A/l0) / (m_i·m_j/(m_i+m_j)) )   // ровно член compute_fiber_bond_dt_limit
dt_bead[k]    = min по связям, касающимся k, от dt_bond          // массив на шаг, O(nbonds)
              = 0.8 / sqrt( (E·A/d) / (m_k/2) )  если связей у k нет  // виртуальная связь длины d
dt_ref_side   = min(dt_bead[k0], dt_bead[k1])   // k1 = −1 → dt_bead[k0]
```

Почему так. Глобальный шаг уже не больше `min dt_bond` (`time_integration.cpp:238,286`), поэтому `dt_applied ≤ dt_ref` выполняется, как у Solid–Solid, и вязкая ветка pinball (`1.6·dt_ref/Kp`) при `Kp ≤ 1` шаг не режет. Исключение составляют только изолированные бусины: у них виртуальная связь в глобальный шаг не входит. Это записать в шапке.

`dt_bead` считать один раз на шаг (после `compute_fiber_bond`) и передавать указателем в параметрах шага. Нужен только при типе ≠ 0. Если агент считает CFL-вариант v1 лучше, он записывает причину и измеренный минимальный шаг для обоих вариантов, а молча не меняет.

## 6. Риски и правила остановки

| Риск | Что делать |
|---|---|
| **Нет силы в покое** (все типы 1–3 при `ṗ ≤ 0`). Нить, лежащая на теле под нагрузкой, будет «проседать», пока проникание не наберёт сближение; трение пропадает на шагах с `fn = 0`. | Измерить в e2e: рост `δ/d` во времени у статического контакта и долю шагов с `fn = 0` у активной пары. Если `δ/d > 0.5` или трение заметно дребезжит, **остановиться и сообщить владельцу**: это свойство законов, а не ошибка реализации, и решать, нужен ли упругий остаток, должен владелец. |
| **Шаг.** Swegle на упругой ветке даёт `dt_limit = 0.8·dt_ref` и может опускать шаг ниже шага связей. | Записывать мин. `dt` и долю шагов, ограниченных контактом нитей. `kOscSafety` не трогать. |
| **Тип 3 и отставание `dt`.** Сила строится по `dt_prev`, а шаг применяется новый. Если шаг уменьшился, гасится меньше, чем `γ`; если вырос, гасится больше. | Комментарий в коде. В e2e печатать `max(dt_new/dt_prev)`. |
| **Тип 3 не сходится по шагу** (см. шапку `impulse_force`). | Не делать выводов о сходимости по разрешению для типа 3. |
| **Скачки точки контакта** (несколько контактов на пересечение). | Метрика ряби / смен знака, не скрывать. |
| **Знаки нормалей** разные у двух контактов. | Только тестами сближения/разлёта, не рассуждением. |
| **OpenMP.** | Побитовые сравнения только при `OMP_NUM_THREADS=1`. |
| **Сигнатуры.** | Аргумент по умолчанию последним; собрать все цели CMake, включая `guo2019_shot` и `tests/clamp_*.hpp`. |
