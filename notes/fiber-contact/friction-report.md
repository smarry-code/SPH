## 2. История и мотивация

### 2.1. Исходное трение Кулона в kernel и дребезг

Первая версия (`notes/fiber-contact/fiber-friction-implementation.md`) считала трение внутри kernel нормального контакта:

$$
\mathbf F_t = -\mu N\,\frac{\mathbf v_t}{\|\mathbf v_t\|},\qquad \|\mathbf v_t\|>\varepsilon_v=10^{-8}\ \text{м/с}.
$$

Это динамический закон Кулона без памяти. Диагностический прогон (c) сценария `test_e2e_cross_friction` (две крестовые нити, `μ = 0.2`, касательная скорость `v_t0 = 0.05` м/с) показал **дребезг**: относительная касательная скорость центральных бусин меняла знак каждые 1–2 шага, размах (0.086 м/с) превышал начальную скорость (0.05 м/с). Разбор — `notes/fiber-contact/friction-chattering-analysis.md`. Механизм:

- Закон Кулона разрывен по `v_t`. Пока оценка $A\,\Delta t = \mu\,\Sigma N\,(1/m_P + 1/m_Q)\,\Delta t$ больше `|u|`, явная схема не может остановить скольжение: сила `μN` каждый шаг перебрасывает `u` через ноль, возникает двухшаговый цикл `{u, u − AΔt}`; трение в цикле не рассеивает энергию (работа на двух шагах имеет разные знаки и суммируется в ноль).
- В схеме PredictorCorrector знак силы берётся от **предсказанной** скорости `u* = uⁿ + (Δt/2)aⁿ⁻¹`, а не от скорости, от которой считает корректор. Предиктор переносит половину прошлого толчка и переворачивает знак раньше самой скорости, поэтому цикл смещён от нуля: средняя скорость скольжения не опускается ниже `AΔt/2`, а на части шагов трение толкает по направлению движения.
- Размах цикла растёт вместе с нормальной силой (`Aₙ ∝ ΣN(t)`), на фронте роста `ΣN` из нормального контакта в касательное движение перекачивается энергия.

Примеры чисел из разбора (до исправления): пары `(0.009, 0.069)`, `(−0.008, 0.078)` м/с; остаток после разгрузки `+0.0075` м/с при Δt и `−0.0164` м/с при Δt/5 (разного знака — зависимость от шага); 8 смен знака силы трения за 16 шагов контакта. При быстром скольжении (`|v_t| ≫ AΔt`) дребезга нет: случай (b) с `v_t0 = 2` м/с.

### 2.2. Кратный учёт одного пересечения (7–9 primitives)

В разборе дребезга обнаружилась вторая причина: масштаб `AΔt` завышен кратностью контакта. В старой схеме Fiber-Fiber-Contact (по Meyer: primitive — пара бусин, веса `w_ij` — вдоль одной нити) одно геометрическое пересечение двух прямых нитей порождало **7 одновременно активных primitives** (в тестах допускалось до 9, `test_diagnostics_pairs_per_intersection` — до 20). Для прямых нитей у любой пары бусин в радиусе поиска ближайшие точки осей совпадают, и все семь пар давали одно и то же `D` (с точностью 1e-8 м). Следствия:

- эффективная жёсткость узла в несколько раз больше герцевской, кратность зависит от угла скрещивания, радиуса поиска и шага бусин, то есть жёсткость зависит от разрешения;
- `compute_fiber_contact_dt_limit` оценивал шаг по жёсткости одного primitive и недооценивал реальную;
- трение умножалось на ту же кратность (в таблице разбора `AΔt` совпадает с фактическим толчком на шагах 229–236 с точностью 1–2 %, что подтверждает: трение всех семи primitives приходит на две центральные бусины).

Главное следствие вышло за пределы трения: старая схема **рождала энергию**. На крестовой сцене (`d = 1` мм, `l0 = 2` мм) скорость отскока центральной бусины P составила +1.199 м/с (превышает даже предел упругого обмена скоростями), полная энергия после удара +72 %. В демо «4 слоя» на старой схеме кинетическая энергия к концу прогона выросла в 2.5 раза (`pierce`) и в 21 раз (`stop`).

### 2.3. Почему потребовались задачи 1–4 и в каком порядке

Порядок задан в начале `notes/fiber-contact/fiber-friction-projection.md`:

| № | Задача | Зачем | Зависимости |
|---|---|---|---|
| 1 | Пара сегментов (нить–нить) | один контакт на пересечение: убирает кратность, завышавшую `AΔt`, жёсткость и рождение энергии; даёт параметры `s`, `t` и точку контакта, на которых строится трение | — |
| 2 | Исправление нормального контакта нить–Solid | владение узлом и радиус по текущей длине; меняет нормальный контакт, поэтому должна быть сделана **до** трения Fiber–Solid (регрессия трения при `mu_fs = 0` сравнивается с уже исправленным контактом) | независима от 1 (общая идея правила владения и константа прижатия `η`) |
| 3 | Трение нить–нить как проекция | устраняет дребезг: импульс трения ограничивается так, чтобы остановить касательное скольжение, но не больше `μNh`; трение вынесено из RHS | после 1 и 2; стадия проектируется так, чтобы задача 4 добавила второй вид контактов без переделки |
| 4 | Трение нить–Solid | тот же механизм, единая стадия, один проход Якоби, mass splitting для обоих видов, `mu_fs`, пробная скорость Solid | после 1, 2, 3 |

Последовательность соблюдена: сначала исправлена геометрия нормального контакта (иначе любое трение умножалось бы на неверную кратность и теряло контакты), затем введена стадия трения на корректной геометрии.

## 3. Модель

### 3.1. Контакт «пара сегментов» (нить–нить): что важно для трения

Полное описание — `notes/fiber-model/fiber-problem-statement.md`, «Постановка проекта: пара сегментов», `notes/fiber-contact/fiber-contact-segment-pairs.md`. Кратко:

- **Primitive** — пара отрезков осей `(a0, a1)`–`(b0, b1)` двух разных нитей; сегмент принадлежит первой бусине (`a1 = next(a0)`). Пара с последней бусиной нити отбрасывается, изолированная бусина — точечный сегмент (`a1 == −1`).
- **Ближайшие точки** отрезков (Ericson, *Real-Time Collision Detection*, §5.1.9), параметры `s`, `t` ∈ [0,1], затем прижатие к границам с `η = 10⁻⁹` (`kFiberContactSnapEta`): иначе пересечение в узле попадает то внутрь сегмента, то на его конец (на 20 000 случайных скрещиваний ≈6 % ошибок без прижатия, 0 с прижатием).
- **Точка контакта и нормаль.**

$$
\mathbf q_A=\mathbf x_{a_0}+s\,\mathbf e_A,\quad \mathbf q_B=\mathbf x_{b_0}+t\,\mathbf e_B,\quad D=\|\mathbf q_A-\mathbf q_B\|,\quad \mathbf n=\frac{\mathbf q_A-\mathbf q_B}{D}.
$$

  Нормаль направлена **от B к A**; при почти пересекающихся осях она строится как `e_A × e_B` с ориентацией от середины `B` к середине `A`; при совпадающих/параллельных осях контакт не формируется (`degenerate_count`).
- **Правило владения** (ровно один контакт на пересечение): сторона `A` принимается, если не выполнено «`s = 1` и есть следующий сегмент» (A1), а при `s = 0` и наличии предыдущего сегмента точка пересчитывается для пары `(S_prev, S_B)` и принимается, только если там `s' = 1` (A2); для `B` симметрично (B1, B2). Правило целиком внутри `compute_fiber_contact_geometry`, поэтому kernel, `dt_limit` и диагностика видят одно и то же множество контактов. Исключение: «седло» вогнутой нити даёт 2 контакта в разных точках — это не дубликат.
- **Веса точки контакта**: `(1−s, s)` на стороне A и `(1−t, t)` на стороне B; бусины с нулевым весом вклад не получают.
- **Закон Герца не менялся**: $F=\tfrac43E^\ast\sqrt{R^\ast}\,\delta^{3/2}$, $\delta=d_\mathrm{eff}-D$.
- **Радиус поиска** $r=d_\max+2L_\max$, $L_\max$ — **текущая** максимальная длина связи (параллельная редукция по `topology.bonds`, функция `fiber_max_current_bond_length` общая с Fiber–Solid): связи рвутся только в Postprocessing, внутри шага сегмент может быть длиннее `l0`.
- **`dt_limit`** по эффективным массам точек контакта: $1/m_A=(1-s)^2/m_{a_0}+s^2/m_{a_1}$, $m_\mathrm{red}=m_Am_B/(m_A+m_B)$, $\Delta t=0.8/\sqrt{k_\mathrm{eff}/m_\mathrm{red}}$, $k_\mathrm{eff}=\tfrac32F/\delta$. Трение на `dt` не влияет.

Для трения из этой геометрии берутся: бусины и веса (через `s`, `t`), нормаль `n`, нормальная сила `N = geom.F ≥ 0`, коэффициент `μ`. Kernel нормального контакта **только заполняет слот** `FiberFrictionContact` на каждый primitive (запись по индексу `k`, без гонок); сила трения в нём не считается.

### 3.2. Fiber–Solid с владением узлом (λ)

Подробности — `notes/fiber-model/fiber-problem-statement.md`, «Постановка проекта: владение узлом», `notes/fiber-contact/fiber-solid-contact-fix.md`. Primitive `(a, b, s)`: сегмент нити `a→b` и реальная Solid-частица `s` (или точечный, `has_b = false`, для изолированной бусины). Параметр проекции частицы на сегмент

$$
t=\frac{(\mathbf x_s-\mathbf x_a)\cdot\mathbf e}{\|\mathbf e\|^2},\quad \mathbf e=\mathbf x_b-\mathbf x_a,\qquad
\mathbf q=\mathbf x_a+\lambda\,\mathbf e,\qquad \mathbf n=\frac{\mathbf x_s-\mathbf q}{\|\mathbf x_s-\mathbf q\|}\ (\text{от нити к Solid}).
$$

Правило владения (после прижатия `t` с `η = 10⁻⁹`: `if t > 1−η: t = max(t,1); if t < η: t = min(t,0)`):

| условие | решение |
|---|---|
| 0 < t < 1 | контакт, λ = t |
| t ≥ 1, последний сегмент | контакт, λ = 1 |
| t ≥ 1, не последний | пропуск (узел `b` принадлежит следующему сегменту) |
| t ≤ 0, первый сегмент | контакт, λ = 0 |
| t ≤ 0, не первый | вычислить `t_prev` для `(prev(a), a)`; `t_prev ≥ 1` — контакт, λ = 0; иначе пропуск |

Старое правило без прижатия и проверки соседа теряло контакт целиком, когда частица лежала во внешнем секторе излома нити (оба соседних сегмента отбрасывали её: `t ≥ 1` и `t < 0` одновременно). Параметр `t` считается единственной функцией `fiber_solid_segment_param` (и для своего, и для соседнего сегмента). Радиус поиска: $r_{f,\max}+r^{contact}_{s,\max}+L_{\max}$ с текущей `L_max`. Сила Герца распределяется между бусинами `a` (вес `1−λ`) и `b` (вес `λ`), на Solid действует `+N n`.

Для трения из слота `FiberSolidFrictionContact` берутся: бусины `a`, `b` (или `−1`), частица `s`, `λ`, нормаль `n` **от нити к Solid**, `N`, `μ`.

### 3.3. Стадия трения в шаге

Порядок (`src/time_integration.cpp`):

1. `solver.predict()` (PC: полшага предиктора по `f^{n−1}`);
2. RHS: Fiber-Bond, Fiber–Fiber нормаль + слоты, Fiber–Solid нормаль + слоты → `solver.fiber_rhs.dv`, `solver.solid_rhs.dvx` — **всё, кроме трения**;
3. `dt = min(CFL, контакт Solid, fiber_dt_limit)`;
4. **стадия трения** (только если есть активные слоты, то есть `mu_ff > 0` или `mu_fs > 0`): `fupd = solver.fiber_velocity_update(fb, dt)`, `supd = solver.solid_velocity_update(sys, dt)`; подсчёт `c_k`, `c_s`; один проход Якоби по слотам обоих видов; вклады `reduce_contributions` и `+=` в `solver.fiber_rhs.dv` и `solver.solid_rhs.dvx` (Solid — только реальные частицы `[0, ntotal)`);
5. `solver.advance()`;
6. Postprocessing.

Следствия (записаны в шапке `fiber_friction.hpp`, `fiber-problem-statement.md`, `fiber-plan.md`): RHS нитей перестал зависеть от скорости; в `dv` после стадии лежит полное применённое ускорение, которое следующий предиктор PC использует как `f^{n−1}`; трение не имеет собственной жёсткости и на `dt` не влияет.

### 3.4. Интерфейс решателя: `FiberVelocityUpdate` и `SolidVelocityUpdate`

Проекции нужна **пробная скорость без трения** — в точности та, которую решатель даст в `advance()`. Решатель (`include/ode/ode_solver.hpp`) отдаёт её формулу структурами:

```cpp
struct FiberVelocityUpdate { const std::vector<double>* base[dim]; double h; };
// v^{n+1} = (*base)[d][i] + h * dv[d][i]
struct SolidVelocityUpdate { const std::vector<double>* base[dim]; double h;
                             const std::vector<std::vector<double>>* av; };
// v^{n+1} = ((*base)[d][i] + h * dvx[d][i]) + (*av)[d][i]   (av != nullptr)
```

Значения берутся из приватных `fiber_coeff(dt)`/`fiber_use_base()` и `solid_coeff(dt)`/`solid_use_base()` — тех же, что использует `advance()` (`correct_fiber`/`step_fiber`, `pc_finalize_velocity_position[_with_av]`, `euler_step_position_velocity`). Порядок сложения в Solid именно `(base + h·dvx) + av`, поэтому точное прилипание относительно пробной скорости остаётся точным и после `advance()`.

| решатель | шаг | `base` | `h` | `av` (XSPH) |
|---|---|---|---|---|
| PredictorCorrector | 1-й (нет `f^{n−1}`) | `fb.vx` / `sys.vx` | `dt/2` | `&solid_rhs.av` |
| PredictorCorrector | `n ≥ 2` | `v_min` (скорость **до** полушага предиктора) | `dt` | `&solid_rhs.av` |
| Euler | любой | `fb.vx` / `sys.vx` (`vⁿ`) | `dt` | `nullptr` (у Эйлера XSPH нет) |

Ключевое: база — **не** `fb.vx` после предиктора (там `u*`), а скорость решателя; именно использование `u*` смещало цикл дребезга в PC.

### 3.5. Проекция: пробная скорость, импульс, сила

Для принятого контакта с весами `α_k` (сторона A/нить) и `β_k` (сторона B) пробная скорость бусины `k`:

$$
\tilde{\mathbf v}_k=\mathbf v_k^\mathrm{base}+h\,\mathbf a_k^\text{без трения}.
$$

Нить–нить: относительная скорость точек контакта и её касательная часть

$$
\mathbf u=\sum_A\alpha_k\tilde{\mathbf v}_k-\sum_B\beta_k\tilde{\mathbf v}_k,\qquad
\mathbf u_t=\mathbf u-(\mathbf u\cdot\mathbf n)\,\mathbf n .
$$

Эффективная обратная масса точки контакта с mass splitting (3.6):

$$
W=\sum_A\frac{c_k\alpha_k^2}{m_k}+\sum_B\frac{c_k\beta_k^2}{m_k}.
$$

Импульс и сила трения:

$$
J=\min\!\left(\mu N h,\ \frac{\|\mathbf u_t\|}{W}\right),\qquad
\mathbf F_t=-\frac{J}{h}\,\frac{\mathbf u_t}{\|\mathbf u_t\|}.
$$

Если `μN = 0` или `‖u_t‖ = 0`, то `F_t = 0`. Ветка **прилипания**: `J_stick = ‖u_t‖/W ≤ μNh` — импульс ровно гасит касательную скорость (`Δu_t = h W F_t = −u_t`); ветка **скольжения**: `J = μNh`, `‖F_t‖ = μN`. Сила `F_t` действует на сторону A (`a_k = α_k F_t/m_k`), `−F_t` на сторону B (`a_k = −β_k F_t/m_k`); бусины с нулевым весом вклада не получают.

Свойства: `F_t ⊥ n`; `‖F_t‖ ≤ μN`; `F_t·u_t ≤ 0`; `Σ m_k a_k^f = 0` (линейный импульс сохраняется точно); кинетическая энергия не растёт; результат прилипания не зависит от `h`. Поскольку проекция видит полное ускорение шага без трения, **один коэффициент работает и как статический, и как кинематический**; память контакта не нужна.

Нить–Solid: пробная скорость нити в точке контакта $(1-\lambda)\tilde{\mathbf v}_a+\lambda\tilde{\mathbf v}_b$, пробная скорость частицы $\tilde{\mathbf v}_s=(\mathbf v_s^\mathrm{base}+h\,\mathbf a_s)+\mathbf{av}_s$ (`SolidVelocityUpdate`):

$$
\mathbf u=\big[(1-\lambda)\tilde{\mathbf v}_a+\lambda\tilde{\mathbf v}_b\big]-\tilde{\mathbf v}_s,\qquad
W=\sum_{k\in\{a,b\}}\frac{c_k\alpha_k^2}{m_k}+\frac{c_s}{m_s},
$$

`u_t`, `J`, `F_t` — те же формулы. Знаки (нормаль от нити к Solid): нормальная часть `−(1−λ)N n` на `a`, `−λN n` на `b`, `+N n` на Solid; трение `+(1−λ)F_t` на `a`, `+λF_t` на `b`, `−F_t` на Solid. Момент импульса не сохраняется (раздел 10).

Формулы вынесены в `friction_projection_impulse` (принимает `u`, `n`, `W`, `μ`, `N`, `h`, не знает вида контакта); `fiber_friction_impulse` и `fiber_solid_friction_impulse` лишь собирают `u` и `W`.

### 3.6. Mass splitting

Проекция по Якоби считает импульс каждого контакта так, будто остальных нет. Если бусина входит в `k > 1` активных контактов (узел сетки, два соседних сегмента одной нити, сегмент на нескольких частицах Solid), суммарная поправка в `k` раз больше нужной — перекомпенсация и перескок через ноль (дребезг возвращается). Поэтому перед проходом считаются

- `c_k` — число активных слотов **обоих видов**, в которых бусина `k` имеет **ненулевой** вес;
- `c_s` — число активных слотов нить–Solid с частицей `s`;

и в эффективной массе `1/m` заменяется на `c/m` (формулы `W` выше). Каждый контакт видит только свою долю массы. При `c = 1` умножение на `1.0` точное — результат побитово прежний. Подсчёт — `compute_friction_counts`: `contributions + reduce` с типами `FiberCountDelta`/`SolidCountDelta`, без atomics; векторы `c` переиспользуются между шагами. Цена — недокомпенсирование (прилипание достигается за несколько шагов, см. раздел 10). Диагностики: `shared_bead_count` (число бусин с `c_k > 1`), `shared_solid_count` (число частиц Solid с `c_s > 1`).

### 3.7. Кинематическое тело

Только для тестов: флаг стадии `solid_kinematic = true` означает бесконечную массу Solid — `h = 0`, `base` = заданная скорость тела (`av = nullptr`), `c_s/m_s = 0`, вклады в Solid не эмитируются. Используется, чтобы проверять прилипание относительно заданной скорости пластины. В боевом цикле флаг всегда `false`.

### 3.8. Коэффициенты `mu_ff` и `mu_fs`

- `FiberMaterial` (`include/fiber/fiber_system.hpp`): поля `mu_ff` (нить–нить) и `mu_fs` (нить–Solid) — **последние** в структуре, чтобы не ломалась агрегатная инициализация; по умолчанию 0 (трения нет).
- **Правило смешения для `mu_ff`** — функция `fiber_friction_coefficient(a, b)` (`fiber_contact.hpp`): при одинаковых `mu_ff` возвращается точное значение (без `sqrt`), иначе $\mu=\sqrt{\mu_a\mu_b}$; `(0, 0.5) → 0`.
- **`mu_fs`** берётся по материалу бусины `a` сегмента (как `K_fs`): `fiber_solid_friction_coefficient(fiber_mat, solid_itype)` возвращает `fiber_mat.mu_fs`. У материалов Solid параметра трения нет; если появится, менять только эту функцию.
- **Формат входного файла** (`src/fiber_input.cpp`): `MATERIAL <id> E nu d rho eps_break [mu_ff [mu_fs]]` — `mu_ff` **седьмое**, `mu_fs` **восьмое** необязательное поле. Отрицательное, нечисловое значение или хвостовой мусор (`0.4x`) — ошибка формата (исключение). Поле `mu_fs` не входило в спецификацию: без его разбора включить трение из файла нити нельзя (решение исполнителя, принято пользователем).
- Активный слот создаётся, только если контакт принят и `μ > 0`; при `mu_ff = mu_fs = 0` слотов нет и стадия не выполняется.

### 3.10. Детерминизм и параллелизм

- Проход трения — по **Якоби**: все контакты читают одно и то же `dv` без трения и пишут вклады через `ContributionWriter` в per-thread буферы; порядок обхода на результат не влияет. Обновлений `dv` на месте внутри прохода нет.
- Kernel — `parallel_for` по слотам фиксированного размера (один слот на primitive, запись по индексу `k`) + `rhs::reduce_contributions`; **без mutex, atomics и аллокаций внутри kernel**. Счётчики `c_k`, `c_s` и диагностика (`shared_*`) — тоже через `contributions + reduce`.
- Формулы (`friction_projection_impulse`, `*_friction_impulse`) без `CpuExecutor`, исключений и аллокаций — кандидаты на `__host__ __device__`; слоты — POD без указателей (переносятся в device-память как есть).
- Побитовая воспроизводимость демо — только при `OMP_NUM_THREADS=1`; при нескольких потоках порядок суммирования меняется и кадры расходятся на уровне ULP (унаследованное свойство сборки, присутствует и на эталоне без трения).

## 7. Демо

Все прогоны — на финальном коде ветки `friction`, `OMP_NUM_THREADS=1`. Метрики считаны скриптами `energy_balance.py` и `penetration_check.py` (раздел 11): `E = КЭ снаряда + КЭ нитей + ΔU_int снаряда + U_связей` (потенциал контакта Герца не отслеживается, поэтому во время контакта возможны провалы; рост выше `E0` означает рождение энергии, трение и энергия связи в момент разрыва — настоящие потери); `δ/d` — перекрытие в долях диаметра нити; «прохождений» — пересечения нитей между кадрами.

Число смен знака импульса трения — 0 во всех прогонах с трением (было 8, 30, 6, 4). Число смен знака самой `u` — 1–2 (пересечение нуля на переходе в прилипание; при малом μ — 2).
- Рост амплитуды выше `v_t0`: было `max‖u‖ = 0.086` при `v_t0 = 0.05` (энергия перекачивалась из нормального контакта в касательное движение); стало 0.0487 (меньше начальных 0.05); после прилипания `‖u‖` не превышает 0.011 (Δt) и 0.0087 (Δt/5).
- Зависимость от Δt: остаток был разного знака и величины (+0.0075 и −0.0164), теперь одного знака (−0.0029 и −0.0056), обе на порядок меньше `v_t0`; пик `‖u‖` при обоих шагах ≈ 0.049–0.050; число шагов прилипания растёт как 1/Δt (10 → 36). Полностью независимой от Δt остаточная скорость не стала.
- Случай `v_t0 = 0`: `u` в пределах 1e-16 (раньше точно 0). Быстрое скольжение (b) по-прежнему без смен знака, 36 шагов скольжения, ни одного прилипания.

**Что осталось.**
- Остаточная `u` после контакта не нулевая и зависит от Δt (−0.0029 и −0.0056). Она набирается уже после прилипания, на фазе разгрузки контакта: `u` медленно уходит от нуля до ≈ −0.011. Причина (названа по структуре решения, отдельного прогона, изолирующего её, например с одним слотом, нет): для двух слотов «седла» с разными нормалями в одной точке у изломанной нити шаг ограничен по каждому слоту отдельно, при расхождении нитей остаётся вклад порядка `‖u_n‖·‖Δn‖`. Прямо виден в прогоне «без скольжения» (`v_t0 = 0`): `‖u_t‖` точки контакта доходит до 0.0155 при `u` центральных бусин 1e-16.
- Эйлер: значение −0.1605 — **не дефект трения**: это мгновенное `u` центральных бусин в момент фиксации отскока, а не остаточная скорость. При μ = 0 то же измерение даёт +0.065 (у PC +0.0475); бусины Q после контакта имеют `vy` от −0.18 до +0.16 (продольная волна вдоль Q, фаза зависит от шага фиксации); нормальная скорость P после отскока у Эйлера +0.72 м/с при подлёте 0.5 (у PC +0.50) — Эйлер сам прибавляет энергию колебаниям и контакту. Импульс согласован: трение на Q +1.09e-7 кг·м/с, `Δ(Σ m vy)` Q = +1.170e-7 и P = −1.170e-7, сумма 1e-22. Устойчивая метрика — средняя относительная скорость нитей: PC 0.0336, Эйлер 0.0323, Эйлер Δt/5 0.0338 (без трения 0.0489).
- Проекция не «останавливает» нити навсегда: при разгрузке нормальной силы прилипание отпускается, небольшой остаток скорости при отскоке ожидаем.
- В прогоне без трения `u` после отскока 0.0475 вместо 0.0496 и 15 шагов контакта вместо 16 — следствие перехода на пары сегментов (изменён нормальный контакт), а не трения.

## 10. Известные ограничения и открытые вопросы

1. **Седло на пологом изломе (нить–нить).** На вогнутом изломе нить касается другой нити обоими плечами, контакт остаётся принятым в **двух** близких точках с разными нормалями. Следствия: удвоение нормальной силы (и жёсткости узла) в зависимости от дискретизации; трение каждого слота ⟂ своей нормали, касательные проекции нормального расхождения не гасятся одновременно — остаток `~‖u_n‖·‖Δn‖` (в сцене (c) до 2.9e-2 м/с второй член допуска; в прогоне `v_t0 = 0` `‖u_t‖` точки контакта доходит до 0.0155 при `u` центральных бусин 1e-16). Это причина остатка после разгрузки (−0.0029 / −0.0056). Отдельного прогона с одним слотом, изолирующего причину, **не проводилось**. Варианты: единая нормаль для седла либо явное обнуление по одному направлению; решается отдельной задачей. В демо сети одно перпендикулярное пересечение, но на 1379 из 1654 контактных шагов принято 4 контакта — вероятное, но не проверенное объяснение: «двойное седло» 2×2.
2. **Недокомпенсация / остаток одного прохода Якоби при связанных контактах.** Mass splitting убирает перескок, но прилипание достигается релаксацией за конечное время: в сцене «нить на пластине» рост `‖u_t‖` за шаг ≤ 0.21 % `v_t0`, перескок проекции ≥ −2.3 % `v_t0`, `T_relax ≈ 6e-5 с`. Даже 30 развёрток Гаусса–Зейделя не дают 1e-9·`v_t0` (рост 5.5e-5, перескок −7.4e-5 м/с): остаток связан со структурой связанных контактов, а не с точностью одного прохода. В демо сети 88.5 % шагов трения имеют общие бусины (max 6). Точное решение — итерации (implicit-схема), не реализовано (запрещено спецификацией). Также при меняющемся от шага к шагу числе активных контактов mass splitting усредняет эффективную массу.
3. **Смешанная бусина при разных массах партнёров.** Бусина в контакте и с нитью, и с Solid: счёт `c` по числу контактов точен только при равных массах партнёров; при `m_2 ≠ m_s` перекомпенсация 0.18 % (без splitting 103 %); допуск в тесте 1 %.
4. **Момент импульса не сохраняется.** Точки приложения `±F_t` (точка `q` на нити и центр частицы `x_s` на Solid) разнесены по нормали на расстояние порядка `D`; пара сил создаёт момент `D·‖F_t‖`; у SPH-частиц нет вращательных степеней свободы. Линейный импульс сохраняется точно (тест (d): суммарный `|dp| ≈ 1.5e-24`; у нормальной силы момента нет, она направлена вдоль `n`).
5. **Скорость поверхности Solid — скорость одной частицы `s`** без интерполяции по соседям.
6. **Газ и вода** (`elastic_by_itype` не определён): нормальный контакт, а значит и трение, не формируется.
7. **Решатель RK-4.** Стадия рассчитана на двухстадийный PC или одностадийный Эйлер; для RK-4 неясно, на каком этапе применять проекцию, чтобы не потерять консервативность импульса; не решено (записано в `fiber-problem-statement.md`).
8. **Параллельные нити и линейный контакт.** Параллельные нити дают по контакту на каждую пару перекрывающихся сегментов; суммарная сила зависит от `l0` (ограничение модели, общее с Meyer, не калибруется переходом на пары сегментов). Самоконтакт одной нити не формулируется.
9. **Глубокое проникание `δ/d > 0.3` в ударных демо**: 0.35 (сеть, нить–нить; 0.312–0.346 с трением), 0.66–0.70 (`pierce`). Для контакта Герца это за пределами применимости; контакт при мягком материале (`E = 2e7` в демо сети, `5e7` в «4 слоях») слишком мягок для скоростей 30–35 м/с. Параметры сцены не пересматривались.
10. **`dt_limit` при нескольких контактах на бусину** по-прежнему оценивается по одному контакту (жёсткости складываются) — общее ограничение Fiber-Fiber, Fiber-Solid и Solid-Solid.
11. **Сосредоточенная сила на редкой дискретизации** (`l0 = 2d`) продавливает нить острым изломом в узле; на скольжении без трения нормаль наклоняется (`max|n_y| ≈ 0.30`), нормальная сила передаёт паразитный касательный импульс (0.047 м/с против 4.8e-4 в старой схеме); в (b) около 47 % касательного импульса приходит от наклона нормали.
12. **Остаточный рост энергии при μ = 0** (+1.5 % `stop`, +0.7 % `pierce`) объяснён предположительно (округления явной динамики, параметры сцены), механизм отдельно не исследован; причина старого скачка энергии в `stop` — вероятно, потерянный контакт во внешнем секторе излома (не проверялось отдельно).
13. **Диагностика при `μ_fs > 0`** снята на демо сетки (7.4); для `stop` и `pierce` не снималась.
14. **Эйлер** добавляет энергию в нормальный отскок (+0.72 м/с при подлёте 0.5 м/с против +0.50 у PC) — свойство схемы Эйлера, не трения.
15. **CUDA.** Формулы трения и слоты спроектированы переносимыми (POD, без атомиков), но CUDA-backend для стадии в рамках этих задач не реализовывался (производительность не измерялась).

## 11. Как воспроизвести

Команды — Git Bash / PowerShell из каталога рабочего дерева `C:/dip/sph/SPH-friction`. Сборка — clang++ 64-бит (LLVM) в режиме Release (`build/CMakeCache.txt`).

### 11.1. Сборка и `ctest`

```bash
cmake --build build -j8                              # полная сборка
ctest --test-dir build --output-on-failure           # все 45 тестов, ~190 с
ctest --test-dir build -E full -j6                   # быстрый набор
ctest --test-dir build -R "fiber|ode_solver"         # только тесты нитей и ODE
```

Имена тестов `ctest`: `fiber_model_test`, `fiber_bond_test`, `fiber_break_test`, `fiber_contact_test`, `fiber_friction_test`, `fiber_solid_test`, `ode_solver_test`, `e2e_fiber_contact_test`, `e2e_fiber_solid_test`, `fiber_time_integration_equivalence_test`, `fiber_dim_guard_test`.

### 11.2. Запуск отдельных тестов

```bash
./build/test_fiber_friction.exe        # 212 проверок: стадия трения, нить–нить и нить–Solid
./build/test_fiber_contact.exe         # 165: пары сегментов

Каждый печатает строки `ok`/`FAIL`; код возврата 0 — все проверки прошли. Тесты пишут временные файлы `__fiber_material_*.fib` в рабочий каталог (только `test_fiber_model`).

    ./build/demo_fiber_layers.exe experiments/2026-09-27-fiber-layers-demo/data_ff03_fs03 stop
```

В PowerShell: `$env:SPH_DEMO_MU_FF="0.3"; $env:SPH_DEMO_MU_FS="0.3"; $env:OMP_NUM_THREADS="1"; ...`.

Переменные окружения демо:

- `SPH_DEMO_MU_FF` — `μ_ff` (≥ 0), пишется **седьмым** полем в строку `MATERIAL` файла сети; по умолчанию 0;
- `SPH_DEMO_MU_FS` — `μ_fs` (≥ 0), **восьмое** поле `MATERIAL`; по умолчанию 0; если задана только `SPH_DEMO_MU_FS`, `SPH_DEMO_MU_FF` автоматически 0 (для корректного формата файла);
- `SPH_DEMO_BUDGET_S` — wall-clock лимит `RunGuard` в секундах (> 0); по умолчанию 600 с у `demo_fiber_net` и 900 с у `demo_fiber_layers`.

Побитовое сравнение кадров возможно только при `OMP_NUM_THREADS=1` (раздел 6.1). Хэши: `sha256sum` по отсортированному списку файлов прогона, сравнение с эталонным списком.
