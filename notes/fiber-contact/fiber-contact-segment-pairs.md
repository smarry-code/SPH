# Инструкция: один контакт на пересечение нитей (Fiber-Fiber-Contact «сегмент–сегмент»)

> **Статус (2026-11-14):** реализовано. Контакт нить–нить построен на паре сегментов с одной силой на пересечение и правилом владения узлом (`include/interactions/fiber_contact.hpp`, `fiber_contact_common.hpp`; тесты `tests/test_fiber_contact.cpp`, `tests/test_e2e_fiber_contact.cpp`). Актуальное описание — [05-fiber-contact.md](../docs/04-explanation/models/05-fiber-contact.md).

Задача 1 из 2. Задачу 2 (трение как проекция на уровне скоростей, `fiber/fiber_friction_projection.md`) начинать только после того, как эта задача принята.

## Цель

Сейчас одно геометрическое пересечение двух нитей учитывается несколькими contact primitives. В сценарии `test_e2e_cross_friction` их 7, `test_diagnostics_pairs_per_intersection` допускает до 20. Все они находят **одну и ту же** точку пересечения осей и сводят силу Герца на одни и те же центральные бусины (`fiber/friction_chattering_analysis.md`, §4.1). Из-за этого:

- эффективная жёсткость узла в несколько раз больше герцевской;
- кратность зависит от угла скрещивания, радиуса поиска и шага бусин, то есть жёсткость контакта зависит от разрешения;
- `compute_fiber_contact_dt_limit` оценивает шаг по жёсткости **одной** пары и недооценивает реальную;
- трение (задача 2) умножается на ту же кратность.

Нужно перейти к схеме **«пара сегментов — одна сила»**: primitive — это пара отрезков осей двух нитей, ближайшие точки ищутся с ограничением по отрезкам, а правило владения гарантирует, что каждое пересечение даёт ровно один контакт.

Флаг совместимости со старой схемой **не нужен**: старое поведение просто заменяется.

## 1. Primitive

Сегмент нити $A$ задаётся первой бусиной $a_0$ и её соседом $a_1 = \mathrm{next}(a_0)$:

$$
\mathbf e_A = \mathbf x_{a_1} - \mathbf x_{a_0},
\qquad
\mathbf q_A(s) = \mathbf x_{a_0} + s\,\mathbf e_A,\quad s\in[0,1].
$$

Аналогично для $B$ с параметром $t$.

Новый primitive (замена `FiberContactPrimitive` и `FiberContactCase`):

```cpp
struct FiberContactPrimitive
{
    // Сторона A
    rhs::index_t a0 = 0;
    long long    a1 = -1;      // next(a0); -1 -> точечный сегмент (изолированная бусина)
    long long    a_prev = -1;  // prev(a0); нужен правилу владения (п. 3)
    bool         a_has_next_segment = false; // a1 != -1 && next(a1) != -1
    // Сторона B -- симметрично
    rhs::index_t b0 = 0;
    long long    b1 = -1;
    long long    b_prev = -1;
    bool         b_has_next_segment = false;
};
```

Четыре случая Surface-Surface / Surface-End / End-Surface / End-End **исчезают**. Контакт с концом нити — это просто ближайшая точка при $s=0$ или $s=1$ на крайнем сегменте. Enum `FiberContactCase` удалить вместе со всеми его использованиями.

### Построение из spatial-пары

`build_fiber_contact_search` по-прежнему получает пары бусин $(i,j)$ разных нитей из `find_pairs_parallel`. Каждая сторона пары отображается в сегмент **по правилу «сегмент принадлежит первой бусине»**, как в `fiber_solid_contact.hpp`, решение 2:

| топология бусины $k$ | сегмент стороны |
|---|---|
| `next[k] != -1` | $(k,\ \mathrm{next}(k))$ |
| `next[k] == -1`, `prev[k] != -1` (последняя бусина) | **пара отбрасывается** — этот участок покрывает сегмент $(\mathrm{prev}(k), k)$, он построится из пары $(\mathrm{prev}(k), \cdot)$ |
| `next[k] == -1`, `prev[k] == -1` (изолированная бусина) | точечный сегмент $(k, -1)$ |

Так как пара бусин $\{i,j\}$ приходит из поиска ровно один раз, пара сегментов $\{S_i, S_j\}$ тоже строится ровно один раз. Дубликатов на уровне построения нет, и сортировка или удаление повторов не требуются.

### Радиус поиска

Пара сегментов в контакте должна гарантированно породить spatial-пару своих первых бусин. Если $D_{AB} < d_\mathrm{eff}$, то по неравенству треугольника

$$
\|\mathbf x_{a_0}-\mathbf x_{b_0}\|
\le \|\mathbf x_{a_0}-\mathbf q_A\| + D_{AB} + \|\mathbf q_B-\mathbf x_{b_0}\|
\le L_A + d_\mathrm{eff} + L_B,
$$

где $L$ — **текущая** длина сегмента. Связи работают только на растяжение и рвутся лишь в Postprocessing после шага. Поэтому внутри шага сегмент может быть длиннее $l_0$ и даже чуть длиннее $l^{break}$. Номинальное $l_0$ как оценка не годится.

Новый радиус:

$$
r_\text{search} = d_{\max} + 2\,L_{\max},
\qquad
L_{\max} = \max_{\text{bonds}} \|\mathbf x_i - \mathbf x_j\| \ \ \text{(текущее)}.
$$

$L_{\max}$ считать `exec.parallel_reduce` по `topology.bonds` в `fiber_contact_search_radius`. Сигнатура функции получает `state`. Вывод неравенства записать в комментарий у функции, по образцу `fiber_solid_contact_search_radius`.

Радиус вырастает примерно с $d + l_0$ до $d + 2l_0$, и широкая фаза даёт в несколько раз больше кандидатов. Это приемлемо: точная проверка дешёвая. Число кандидатов вывести в диагностику (п. 7).

## 2. Ближайшие точки двух отрезков

Реализовать одну функцию:

```cpp
// Параметры ближайших точек отрезков [p0,p1] и [r0,r1], s,t in [0,1].
// Вырожденные отрезки (длина ~0) обрабатываются как точки.
inline void fiber_segment_closest_params(const double p0[3], const double p1[3],
                                         const double r0[3], const double r1[3],
                                         double& s, double& t);
```

Алгоритм — стандартный `ClosestPtSegmentSegment` (C. Ericson, *Real-Time Collision Detection*, §5.1.9). Он решает задачу на квадрате $[0,1]^2$ с последовательным ограничением и корректно обрабатывает параллельные и вырожденные отрезки. Порог вырожденности задать **относительным**: $\|\mathbf e\|^2 \le \varepsilon\,L_\text{ref}^2$, где $L_\text{ref}$ — длина другого отрезка или $d$. Абсолютный порог в метрах не использовать.

**Прижатие к концам (snapping).** После вычисления:

$$
s \leftarrow
\begin{cases}
0, & s < \eta,\\
1, & s > 1-\eta,\\
s, & \text{иначе},
\end{cases}
\qquad \eta = 10^{-9},
$$

и так же для $t$. Без этого пересечение точно в узле, частое в тестах и регулярных сетках, классифицируется то как внутренняя точка ($s = 1-10^{-16}$), то как конец. Правило владения ниже тогда даёт двойной или нулевой учёт. Прототип на 20 000 случайных скрещиваний прямых нитей без snapping дал около 6 % неверных случаев, со snapping — 0.

**Требования к функции:**

- одна функция для **всех** вызовов: собственный сегмент и соседние сегменты в правиле владения. Правило опирается на точное сравнение `s == 1.0`, поэтому результаты должны быть побитово воспроизводимы для одинаковых входов;
- без `-ffast-math`, без ручного переупорядочивания выражений. Проект собирается Clang с `-ffp-contract=on` по умолчанию: сжатие в FMA внутри одного выражения детерминировано и не зависит от места inlining. Флаги в CMake не менять;
- без исключений, аллокаций и `std::function`. Функция должна переноситься в CUDA-kernel добавлением `__host__ __device__`.

## 3. Правило владения: один контакт на пересечение

Две последовательные вершины сегментов нити $A$ делят узел $\mathbf x_{a_0}$: он конец $S_{a_{prev}}$ при $s=1$ и начало $S_{a_0}$ при $s=0$. Если ближайшая точка попадает в узел, её «видят» оба сегмента. Если нить в узле изогнута вогнуто к $B$, у неё могут быть **две** честные точки локального минимума расстояния. Это два физических контакта, и оба нужно оставить.

Пусть для primitive $(S_A, S_B)$ найдены $(s,t)$ после snapping. Primitive **принимается**, если выполнены все четыре условия:

| условие | смысл |
|---|---|
| **A1.** если $s = 1$ и `a_has_next_segment`, то **отклонить** | узел $\mathbf x_{a_1}$ принадлежит следующему сегменту $A$ |
| **A2.** если $s = 0$ и `a_prev != -1`, то пересчитать $(s', t')$ для пары $(S_{a_{prev}}, S_B)$ той же функцией; принять, только если $s' = 1$ | узел $\mathbf x_{a_0}$ — общий минимум обоих сегментов, и владелец — $S_{a_0}$. Если $s' < 1$, минимум лежит внутри $S_{a_{prev}}$ и принадлежит ему |
| **B1, B2** — симметрично для $t$ и сегмента $S_{b_{prev}}$ при фиксированном $S_A$ | |

Последний сегмент нити ($s=1$, но `a_has_next_segment == false`) и первый ($s=0$, `a_prev == -1`) принимают свою концевую точку без условий. Это контакт с концом нити (бывший End-случай).

Почему этого достаточно:

- если минимум внутри сегмента, его принимает только этот сегмент. Соседний видит ту же область как свой конец и отклоняется по A1 или A2;
- если минимум в узле, $S_{a_{prev}}$ отклоняется по A1, а $S_{a_0}$ принимает его по A2;
- если $S_{a_{prev}}$ отклонён по A1, то $\mathrm{dist}(S_{a_0}, S_B) \le \mathrm{dist}(\mathbf x_{a_0}, S_B) = D$. Контакт **не теряется**, он переходит к следующему сегменту, а тот обязательно есть среди primitives по радиусу из п. 1;
- узел–узел, как в `test_e2e_cross_friction`, где пересечение точно в центральных бусинах: из четырёх пар сегментов вокруг узлов принимается ровно одна, $(S_{a_0}, S_{b_0})$ с $s=t=0$.

Прототип на Python (20 000 случайных скрещиваний, половина точно через узлы, углы 0.05…π−0.05) проверил три свойства:
- прямые нити: ровно один принятый контакт во всех случаях;
- изогнутые нити с шумом координат 2–30 % от $l_0$: ни одного дубликата (две принятые пары с совпадающими точками контакта) и ни одного случая, когда глобально ближайшая пара сегментов отклонена;
- несколько принятых контактов появляются только у изогнутых нитей с несколькими локальными минимумами. Это физически разные точки.

Стоимость: до двух дополнительных вызовов `fiber_segment_closest_params` на primitive, только при $s=0$ или $t=0$. Для этого primitive и хранит `a_prev`/`b_prev`.

**Где применять.** Правило живёт в одной функции (`compute_fiber_contact_geometry`), поэтому kernel, `dt_limit` и диагностика видят одно и то же множество контактов. Отклонённый primitive возвращает `geom.contact = false` и отдельный флаг `geom.rejected_by_ownership = true` для диагностики.

## 4. Геометрия и нормальная сила

Для принятого primitive:

$$
\mathbf q_A = \mathbf x_{a_0} + s\,\mathbf e_A,\qquad
\mathbf q_B = \mathbf x_{b_0} + t\,\mathbf e_B,\qquad
D = \|\mathbf q_A-\mathbf q_B\|,\qquad
\mathbf n = \frac{\mathbf q_A-\mathbf q_B}{D}.
$$

Сохраняется конвенция проекта: $\mathbf n$ направлена **от $B$ к $A$**, сила на $A$ равна $+F\mathbf n$ (шапка `fiber_contact.hpp`, пункт 1).

Вырожденные случаи:

- $D <$ `kFiberContactMinD` (оси пересекаются): $\mathbf n = \dfrac{\mathbf e_A\times\mathbf e_B}{\|\mathbf e_A\times\mathbf e_B\|}$, ориентированная так, чтобы $\mathbf n\cdot(\mathbf m_A-\mathbf m_B)\ge 0$, где $\mathbf m$ — середины сегментов. Если при этом и $\|\hat{\mathbf e}_A\times\hat{\mathbf e}_B\|$ < `kFiberContactParallelEps` (совпадающие параллельные оси), контакт не формировать и учесть в `degenerate_count` (п. 7). Так же поступает текущий код при совпадающих бусинах;
- точечный сегмент: $\mathbf e = 0$, $s=0$, ориентация по общей формуле.

Закон Герца, $E^\ast$, $R^\ast$, $d_\mathrm{eff}$ **без изменений** (шапка файла, пункт 2). Материал стороны берётся по первой бусине сегмента ($a_0$, $b_0$), как решение 4 в `fiber_solid_contact.hpp`.

## 5. Распределение силы

Точка приложения силы — $\mathbf q_A$ на отрезке, распределение линейное, как в Fiber-Solid:

$$
\mathbf F_{a_0} \mathrel{+}= (1-s)\,\mathbf F,\qquad
\mathbf F_{a_1} \mathrel{+}= s\,\mathbf F,\qquad
\mathbf F_{b_0} \mathrel{-}= (1-t)\,\mathbf F,\qquad
\mathbf F_{b_1} \mathrel{-}= t\,\mathbf F.
$$

Для точечного сегмента вся сила идёт на $a_0$ ($b_0$). Слоты `ContributionMeta`: 0 = $a_0$, 1 = $a_1$, 2 = $b_0$, 3 = $b_1$. Вклад с нулевым весом (при $s=0$ на $a_1$) **не эмитировать**, чтобы не плодить нулевые contributions.

`FiberContactGeometry` заменить: поля `P_ij`, `P_ji`, `w_i`, `w_j`, `*_has_neighbor`, `*_neighbor` удалить, добавить `s`, `t`, `rejected_by_ownership`. Хранить копии индексов бусин в геометрии не нужно, они есть в primitive.

Добавить общую функцию, которую будут использовать `dt_limit` и задача 2:

```cpp
// 1/m эффективной массы точки контакта на одной стороне:
// (1-s)^2/m_0 + s^2/m_1  (точечный сегмент: 1/m_0).
inline double fiber_contact_side_inv_mass(const fiber::FiberState& st,
                                           rhs::index_t k0, long long k1, double s);
```

### Существующее трение

Трение Кулона из `fiber_friction_implementation.md` в этой задаче **не переделывать**, только перевести на новую геометрию: скорость точки контакта считать как $\mathbf v_{c,A} = (1-s)\mathbf v_{a_0} + s\,\mathbf v_{a_1}$, а $\mathbf F_t$ распределять теми же весами $(1-s, s)$ и $(1-t, t)$. `fiber_contact_point_velocity` адаптировать под $(k_0, k_1, s)$. ## 6. `compute_fiber_contact_dt_limit`

Раньше $m_\mathrm{red}$ строилась по якорным бусинам $i$, $j$. Теперь — по эффективным массам точек контакта:

$$
\frac1{m_A} = \frac{(1-s)^2}{m_{a_0}} + \frac{s^2}{m_{a_1}},\qquad
m_\mathrm{red} = \frac{m_A m_B}{m_A+m_B},\qquad
\Delta t_\mathrm{lim} = \frac{0.8}{\sqrt{k_\mathrm{eff}/m_\mathrm{red}}},\quad k_\mathrm{eff}=\tfrac32 F/\delta.
$$

$m_A \in [\min m,\ 2\max m]$, так что для одиночного контакта оценка не жёстче прежней. Главное изменение другое: одна сила на пересечение вместо семи, а значит реальная жёсткость узла теперь совпадает с той, по которой считается $\Delta t$.

Отметить в комментарии известное ограничение: если одна бусина одновременно участвует в нескольких контактах (узлы сетки, плетение), жёсткости складываются, а оценка остаётся по одному контакту. Это то же ограничение, что у Fiber-Solid и Solid-Solid.

## 8. Тесты

Переписать `tests/test_fiber_contact.cpp`. Проверки на `P_ij`/`w_ij` и четыре case удалить, заменив на новые. Все проверки сил — на суммарных вкладах после `reduce_contributions` по **всем** primitives сцены, а не по одному primitive. Именно в этом месте старая схема и ошибалась.

Вспомогательная функция для тестов: `hertz_force(delta, mat_i, mat_j)` — та же формула, что в kernel, чтобы сравнивать с «силой одной пары».

### 8.1. Ровно один контакт на пересечение (главный тест)

Две прямые нити по 7 бусин, скрещивание, проникновение $h$. Перебор:
- угол скрещивания $\theta \in \{90°, 60°, 30°, 10°, 3°\}$;
- положение пересечения: середина сегмента на обеих нитях; **точно в узле** на одной нити; **узел–узел** на обеих (сцена `test_e2e_cross_friction`); на расстоянии $10^{-12} l_0$ от узла (проверка snapping).

Для каждого варианта:
- `contact_count == 1`;
- суммарная сила на нить $A$ по всем бусинам равна `hertz_force(d_eff − D_true) * n` с относительной точностью $10^{-12}$, где $D_\text{true}$ — аналитическое расстояние между прямыми;
- сумма сил на обе нити равна нулю (п. 8.4).

### 8.2. Концы нитей

- конец $A$ лежит на середине сегмента $B$ (бывший End-Surface): один контакт, $s=0$ или $s=1$ на крайнем сегменте, вся сила $A$ на концевой бусине;
- конец к концу (бывший End-End): один контакт;
- изолированная бусина (нить из одной бусины) у середины сегмента $B$: один контакт.

### 8.3. Изогнутая нить

- нить $A$ изогнута в узле **выпукло** к $B$, ближайшая точка — этот узел: ровно один контакт, принят сегментом $S_{a_0}$ с $s=0$;
- нить $A$ изогнута **вогнуто** («седло»), $B$ касается обоих плеч: два контакта с разными точками $\mathbf q_A$. Это не дубликат.

### 8.4. Сохранение импульса

Для сцен 8.1–8.3: $\sum_k m_k \mathbf a_k = 0$ с допуском проекта.

### 8.5. Полнота поиска при растянутых связях

Обе нити растянуты до $l = 1.3\,l_0$ (связи не рвутся, `eps_break` большой). Геометрия выбирается так, чтобы оценка из п. 1 была почти точной: нити **почти встречные** (угол между $\mathbf e_A$ и $-\mathbf e_B$ около $5°$), точка контакта у дальних концов обоих сегментов ($s \approx t \approx 0.95$, но не прижаты к 1), проникновение мелкое ($D \approx 0.95\,d$). Тогда $\|\mathbf x_{a_0}-\mathbf x_{b_0}\| \approx 1.9 \cdot 1.3\,l_0 + D > 2l_0 + d$.

Проверить:
- контакт найден с новым радиусом;
- расстояние между первыми бусинами пары больше номинального радиуса $d + 2l_0$. Это проверка самой сцены: она подтверждает, что тест действительно ловит разницу между текущей и номинальной длиной.

### 8.6. Почти параллельные и параллельные нити

- угол $10^{-4}$ рад, смещение по нормали $< d$: контакты есть, нет NaN/Inf, суммарный импульс ноль, `contact_count` не больше числа сегментов перекрытия;
- совпадающие оси: нет NaN, `degenerate_count > 0`, силы нулевые.

Линейный контакт параллельных нитей даёт по контакту на каждую пару перекрывающихся сегментов, и суммарная сила зависит от $l_0$. Это известное ограничение модели Meyer. Тест фиксирует только отсутствие NaN и сохранение импульса, **не** величину силы.

### 8.7. `dt_limit`

Для сцены 8.1 (90°, середина сегментов) `compute_fiber_contact_dt_limit` совпадает с формулой п. 6, вычисленной вручную.

## 11. Критерий готовности

- для любого скрещивания двух прямых нитей, в том числе через узлы, `contact_count == 1`, а суммарная сила равна силе Герца одной пары;
- ни одного дубликата контакта у изогнутых нитей; глобально ближайшая пара сегментов никогда не отклоняется правилом владения;
- импульс сохраняется в каждом тесте;
- `dt_limit` считается по эффективным массам точек контакта;
- все тесты проходят; изменения сценарных порогов, если были, обоснованы в отчёте значениями до и после;
- документация обновлена по п. 9.
