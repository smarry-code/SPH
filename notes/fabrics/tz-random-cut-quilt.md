# ТЗ для локального Claude Code: ткань «случайная раскройка» в генераторе plain_weave

Репозиторий `smarry-code/SPH`, ветка `fiber_fabric` (коммит 86ef910 или новее). Код на C++17, комментарии и сообщения на русском, в стиле `include/fiber/plain_weave.hpp`.

Прототип на Python (вид сверху, без волнистости по z): `/mnt/project-files/weave-patch/random-cut/random_cut_quilt.py`, картинки `cut_layout.png`, `beads_contacts.png` рядом. Прочитайте его первым: алгоритм раскройки, обрезки нитей и стежков взят оттуда. Анализ текущего генератора: `/mnt/project-files/weave-patch/fiber-fabric-generator-analysis.md`.

## 1. Цель

Прямоугольник ткани W × H замащивается случайными выпуклыми многоугольниками (диаграмма Вороного). Каждый многоугольник это отдельный фрагмент полотняной ткани со своим поворотом и сдвигом сетки нитей. Фрагменты разделены зазором `gap`. Между фрагментами нет общих нитей: они взаимодействуют контактом нить-нить (его считает ядро, генератору ничего писать не нужно) и прошиваются стежками, то есть связями `BOND` между бусинами по обе стороны шва. Результат: файл `.fib` (+ раскладки), который читает `fiber::load_fiber_file`, и скрипт-график.

Существующие режимы (`build_plain_weave`, `--patch/--tile`, сцена Guo 2019) и формат `.fib` не должны меняться. Без новых ключей результат побитово прежний.

## 3. Параметры (структура `RandomCutParams`)

| Поле / ключ CLI | По умолчанию | Смысл |
|---|---|---|
| `base` (все прежние ключи: `--preset`, `--d`, `--pitch`, `--amp`, `--seg`, `--profile`, материал, `--center`) | как в пресете | параметры ткани; `nx`, `ny` игнорируются |
| `--random-cut=N` | нет | число фрагментов N >= 1; включает режим; несовместимо с `--nx/--ny/--patch/--tile` |
| `--size=WxH` (мм → в SI: метры) | 50x50 мм | размер прямоугольника ткани. Единицы как у остальных ключей: метры (`--size=0.05x0.05`) |
| `--seed=S` | 1 | зерно ГСЧ |
| `--gap=<м>` | `d` (0.39e-3 для twaron) | зазор между фрагментами. Должен быть >= `d`, иначе ошибка (разрешить: `--allow-penetration`) |
| `--rot-max=<град>` | 25 | поворот сетки фрагмента равномерно в [-rot_max, +rot_max] |
| `--stitch-step=<м>` | 2.4e-3 | шаг стежков вдоль шва; 0 = без стежков |
| `--stitch-E`, `--stitch-d`, `--stitch-rho`, `--stitch-eps-break` | E 5e9 Па, d 0.2e-3 м, rho 1000, eps_break 0.2 (заглушки, задаёт Mary, см. раздел 9) | материал стежка, пишется как `MATERIAL 1` |
| `--rc=<м>` | 0.9e-3 | радиус контакта только для диагностики (раздел 5.3) |

Выступов (`overhang`) в этом режиме нет: нити обрезаются по границе фрагмента. Зажим: по умолчанию `none`. Если задан `--clamp` и `--clamp-edge`, использовать ту же логику боксов, что в `build_plain_weave` (границы относительно центра), но без требования, чтобы c_e лежал между нитями.

## 4. Алгоритм

### 4.1 Раскройка

1. ГСЧ: `std::mt19937_64(seed)`, вещественные числа получать вручную (`(u64 >> 11) * 2^-53`), не `std::uniform_real_distribution`, чтобы результат не зависел от стандартной библиотеки.
2. N центров равномерно в прямоугольнике [0,W]×[0,H] с минимальным расстоянием `0.55·W/√N`; если за 10^4 попыток не набрались, уменьшать минимум на 3 % и повторять.
3. Ячейки Вороного: многоугольник = прямоугольник, последовательно обрезанный полуплоскостями «ближе к центру i, чем к j» (Sutherland-Hodgman). Одна итерация Ллойда: центры переносятся в центроиды ячеек, ячейки считаются заново.
4. Рабочий многоугольник фрагмента: те же полуплоскости, но каждый биссектор сдвинут внутрь на `gap/2`. Границы самого прямоугольника не сдвигаются (ткань доходит до края).
5. Для каждого фрагмента: поворот `theta` и сдвиг сетки `phase = (fx, fy)` из [0,1), равномерно.

### 4.2 Ткань во фрагменте

Для фрагмента с центром `c`, ортами `u = (cos θ, sin θ)`, `v = (-sin θ, cos θ)`:
- Основа: прямые `c + (j + fx)·p·v + t·u`, уток: `c + (i + fy)·p·u + t·v`, целые `j`, `i`.
- Для каждой прямой найти интервал `[t0, t1]` внутри выпуклого рабочего многоугольника (отсечение параметрической прямой полуплоскостями). Пустые интервалы и интервалы короче `h/4` (h = p/seg) отбросить.
- Бусины на нити: в вершинах решётки фрагмента (пересечения с поперечными нитями, `t` = целое число шагов `p` от начала решётки) и между ними по `seg-1` внутренних бусин с равными хордами, ровно как в `build_plain_weave` (`equal_chords`, полуволна считается один раз и переиспользуется). Профиль `Cos` или `Arcs` по параметру. Бусины, попавшие внутрь `[t0, t1]`, остаются; на концах добавляются бусины точно на границе обрезки (`t0`, `t1`) с z по тому же профилю в этой точке (`Curve::at`). Концевая бусина не добавляется, если до ближайшей остающейся бусины меньше 0.2·h (иначе получится почти нулевая связь).
- z: `cz + sg·A·cos-профиль`, знак `sg` определяется чётностью целого индекса вершины и номера нити в локальной решётке фрагмента (основа `j` стартует со знаком `(-1)^j`, уток `i` со знаком `-(-1)^i`, как в `build_plain_weave`), так что в каждом пересечении основа и уток разнесены по z на 2A. Фаза не согласуется между фрагментами (они не связаны нитями).
- Нить записывается как `PlainWeaveFiber`: `direction` 'x' для основы, 'y' для утка (по смыслу «основа/уток», не по оси), `index` = номер нити внутри фрагмента, `offset` = смещение от центра. Добавить поле или параллельный вектор `fragment_id` на нить. Нумерация `object_id` сквозная: по фрагментам, внутри фрагмента сначала основа, потом уток.

### 4.3 Стежки (шов)

Для каждой пары фрагментов `i < j` с общей границей: отрезок шва = биссектор между центрами `i` и `j`, обрезанный полуплоскостями ячейки `i` без сдвига (длина > 1e-9 м). Вдоль отрезка: `ns = max(1, floor(L/stitch_step))`, точки в серединах `ns` равных частей. Для каждой точки найти ближайшую бусину фрагмента `i` и ближайшую бусину фрагмента `j`; пара = стежок. Дубликаты пар убрать. Порядок стежков детерминирован: по `(i, j)`, затем вдоль шва.

Стежок это `BOND` между глобальными индексами бусин (сквозная нумерация в порядке записи блоков `FIBER`), материал 1, `l0` ядро берёт по начальным координатам. Стежки работают только на растяжение, как в существующем коде.

### 4.4 Проверки внутри генератора

- `gap >= d` (или `--allow-penetration` + предупреждение).
- Минимальное расстояние в плане между бусинами разных фрагментов >= `gap - 1e-9·p`. Иначе `std::runtime_error`.
- Оценка числа бусин до построения (предохранитель 5e7, как в `plain_weave.hpp`).
- N >= 1; при N = 1 фрагмент один и стежков нет.

## 5. Выходные файлы

1. `<out>.fib`: как сейчас (`MATERIAL 0`, блоки `FIBER 0 n`), затем при `stitch-step > 0` строка `MATERIAL 1 <E> <nu> <d> <rho> <eps_break>` и строки `BOND <i> <j> 1`. Формат MATERIAL 1 и BOND ровно как в `cases/guo2019/experiment/guo2019_scene.hpp` (`write_fabric_stack_fib`, строки около 340-353). Для этого расширить `write_plain_weave_fib` необязательным аргументом (по образцу `StitchFibExtra`), по умолчанию поведение прежнее. `CLAMP_BOX`, если есть, пишется как раньше.
2. `<out>.layout.txt` (прежний формат): `write_plain_weave_layout`.
3. `<out>.cut.json` для графика и проверок: `size`, `seed`, `gap`, `p`, `d`, `seg`; список фрагментов (id, центр, `theta`, `phase`, вершины рабочего многоугольника, диапазон нитей и бусин); список стежков (пары глобальных индексов, фрагменты); список контактов диагностики: пары глобальных индексов бусин разных фрагментов ближе `rc` (сетка ячеек `rc`, без O(n^2)). Контакты в `.fib` не пишутся, ядро находит их само.
4. Сводка в stdout: фрагментов, швов, нитей, бусин, стежков, контактов диагностики, min/max `l0`, площади фрагментов, суммарная площадь.

## 6. Тесты (`tests/test_plain_weave_random_cut.cpp`)

1. Детерминизм: два вызова с одним `seed` дают идентичные `pts` и стежки; другой `seed` даёт другие.
2. Площади: сумма площадей рабочих многоугольников + площадь зазоров (сумма длин швов × gap, допуск 1 %) = W·H.
3. Все бусины фрагмента лежат внутри его рабочего многоугольника (допуск 1e-12 м).
4. Расстояние между бусинами разных фрагментов в плане >= `gap` с допуском; для `gap < d` без флага ошибка, с флагом предупреждение.
5. Фрагмент с `theta = 0`, `phase = 0`: в каждом пересечении основы и утка внутри фрагмента `|z_основы - z_утка| = 2A` (допуск 1e-9·A), нет проникания при `2A >= d` для обоих профилей.
6. `l0` внутренних хорд: все в пределах 1 % от номинала, концевые хорды не короче 0.2·h.
7. Стежки: число = сумма `ns` по швам минус дубликаты; в каждой паре бусины из разных фрагментов; расстояние в паре <= `gap + 2·p`; нет стежка внутри одного фрагмента.
8. `.fib` читается `fiber::load_fiber_file`: число бусин и число связей = (бусины - нити) + стежки; материал 1 подцепился.
9. `N = 1`: стежков нет, `.fib` читается.
10. Регрессия: существующие тесты (`plain_weave_test`, `plain_weave_quilt_test`, `plain_weave_cli_test`, `stitch_kt_cli_test`) проходят без изменений; без новых ключей CLI даёт тот же `.fib`, что в 86ef910.
11. CLI-тест: `plain_weave_gen --preset=twaron_ct717 --random-cut=9 --size=0.05x0.05 --seed=3 --out=rc.fib` создаёт `.fib`, `.layout.txt`, `.cut.json`; ошибка при совместном `--random-cut` и `--nx`.

## 8. Критерии приёмки

1. `ctest` проходит полностью, новые тесты зелёные.
2. Для `twaron_ct717`, `--random-cut=9 --size=0.05x0.05 --seed=3` генерация быстрее 5 с, бусин порядка 14 тыс (прототип: 14420 при другой нарезке эквивалентной сетки).
3. График по выходу C++ визуально совпадает со структурой прототипа (фрагменты, обрезанные нити, красные стежки на швах).
4. Короткий прогон в сцене Guo 2019 или в `fabric_checks` на такой ткани (smoke, без разрыва связей на первых шагах): не обязателен для приёмки, но желателен; если делается, описать результат в сообщении коммита.
5. Документ в `docs/` обновлён.

## 9. Вопросы к заказчице (не блокируют, заложены заглушки)

1. Параметры стежка (материал, диаметр, прочность) и шаг стёжки: задаст Mary. В коде значения по умолчанию помечены как заглушки.
2. Нужна ли прошивка нескольких слоёв (пакет 2T/4T) с такой раскройкой, а также совпадают ли раскройки слоёв. Сейчас только один слой; `build_quilt_stitches` рассчитан на одинаковые слои и здесь не подходит.
3. Стежки соединяют ближайшие бусины, а не определённые нити: нужна ли привязка к пересечениям или к вершинам нитей.
4. Мелкие фрагменты (площадь меньше нескольких ячеек решётки) оставлять или объединять: пока оставляются.
5. Нужен ли поворот сетки (`--rot-max=0` отключает) и постоянный ли размер фрагментов.

## 10. Вне объёма

Нити, проходящие через швы; изменение ядра контакта и ядра связей; пластичность и разрушение стежков сверх существующих; подбор физических параметров.
