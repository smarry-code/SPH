## 1. Цель и источник

Нужен **генератор геометрии тканого полотна полотняного переплетения** (plain weave) в формате файла нитей проекта (`.fib`, `fiber::load_fiber_file`). Он заменит ручную подготовку сетки в LS-PrePost и станет входом для будущих e2e по ткани (удар шара по Twaron, статья Guo 2019). Сам e2e-тест с ударом **в это ТЗ не входит**.

Источники:
1. **Скрипт LS-PrePost `Circle_draw.txt`** (владелец проекта; копия прилагается к ТЗ). Строит нить из 130 чередующихся полуэллипсов (полуоси 0.1 и 0.2 мм, шаг центров 0.4 мм, длина ≈ 52 мм). Затем разбивает её на балки, сливает узлы, поворачивает копию на 90° и размножает: по 132 нити в каждом направлении с шагом 0.4 мм, соседние параллельные нити сдвинуты на полволны. Плоскость ткани у него x–z, толщина вдоль y. SPH **не умеет читать** его выход: читалка k-файла знает только `*NODE` и `*ELEMENT_SPH` (`src/input.cpp:148-152`).
2. **Ткань Twaron CT 717** (Guo et al., IJIE 127 (2019) 1–16): полотняное переплетение, слой 0.4 мм, 280 г/м², окно 120×120 мм, зажаты верхняя и нижняя кромки, боковые свободны. Шаг ≈ 8–9 нитей/см и сечение нити ≈ 0.12 мм² — **оценки** автора сводки, в статье прямо не даны.

## 2. Модель нити проекта (ограничения, которые генератор не обходит)

- Нить — цепочка бусин, связи работают **только на растяжение**, изгибной жёсткости нет (`include/interactions/fiber_bond.hpp:93`). Волнистость (crimp) держится только контактом нить–нить.
- Сечение круглое, диаметр `d` задаёт одновременно площадь (масса, жёсткость связи) и радиус контакта. Плоскую нить реальной ткани модель не передаёт: при `d`, эквивалентном по площади, толщина полотна получится около `2d`, а не реальная.
- `l0` связи — расстояние между соседними точками файла (`src/fiber_input.cpp:50-55`). Поэтому ломаная из файла и есть **ненагруженная** конфигурация: сгенерированная ткань не натянута.
- Контакт только между бусинами **разных** `object_id` (`include/interactions/fiber_contact.hpp:225-226`, `:269`). Каждая нить — отдельный блок `FIBER`.
- **Закрепление есть в ядре:** кинематическое условие Дирихле `x = x_0, v = 0` для отмеченных компонент бусин (`include/interactions/clamp.hpp`, `notes/fiber-model/fiber-problem-statement.md`, раздел «Clamp (кинематическое закрепление)»). В файле нитей оно задаётся директивой `CLAMP_BOX <xmin> <ymin> <zmin> <xmax> <ymax> <zmax> [<mask>]` (`src/fiber_input.cpp:27-35`, разбор `:228-321`): все бусины в замкнутом боксе закрепляются по компонентам маски (по умолчанию по всем), несколько директив объединяются по «или», положение директивы в файле не важно. `load_fiber_file` сам заполняет `model.clamps.fiber_mask`; без директив маска пустая. Генератор **пишет** зажим в `.fib` (§3.5). Приём «анкеров» (масса концевых бусин ×50, демо «4 слоя») больше не нужен и генератором не применяется.
- Контакт нитей исправлен (`notes/fiber-contact/friction-report.md`, задачи 1–4): одно пересечение даёт один контакт «пара сегментов». Остаточный случай — «седло» на пологом изломе: нить касается другой обоими плечами и получает два контакта (`friction-report.md` §10 п.1). В полотне пологий излом в каждом узле, поэтому генератор даёт диагностику контакта на исходной геометрии (§5, проверка 7). Исправлять контакт **не нужно**.

## 3. Геометрия

### 3.1. Система координат и обозначения

Плоскость ткани — **x–y**, толщина по **z**, центр полотна в точке `(cx, cy, cz)`, по умолчанию `(0, 0, 0)`. Так ткань согласуется с демо, где снаряд летит вдоль −z. У Circle_draw.txt плоскость x–z: это сознательное отличие.

| Обозначение | Смысл | Ед. |
|---|---|---|
| `d` | диаметр нити | м |
| `p` | шаг между осями соседних параллельных нитей (он же полуволна волнистости) | м |
| `A` | амплитуда волнистости по z | м |
| `n_x` | число нитей основы (идут вдоль x) | — |
| `n_y` | число нитей утка (идут вдоль y) | — |
| `e_x`, `e_y` | выступ нитей основы (вдоль x) и утка (вдоль y) за крайнюю поперечную нить | м |
| `c_e` | граница зажима: расстояние от центра полотна вдоль нити, начиная с которого бусины зажимаемых нитей закреплены (§3.5) | м |
| `k` | число сегментов (связей) на полуволну, целое ≥ 2 | — |

### 3.2. Оси нитей (профиль по умолчанию — косинус)

Позиции нитей: основа `j = 0..n_x−1` на `y_j = cy + (j − (n_x−1)/2)·p`; уток `i = 0..n_y−1` на `x_i = cx + (i − (n_y−1)/2)·p`.

- Основа `j`: `z = cz + A·(−1)^j·cos(π·(x − x_0)/p)`, `x ∈ [x_0 − e_x, x_{n_y−1} + e_x]`.
- Уток `i`: `z = cz − A·(−1)^i·cos(π·(y − y_0)/p)`, `y ∈ [y_0 − e_y, y_{n_x−1} + e_y]`.

В пересечении `(i, j)` основа стоит на `cz + A·(−1)^{i+j}`, уток на `cz − A·(−1)^{i+j}`. Расстояние между осями ровно `2A`, основа сверху при чётном `i + j`. Вдоль каждой нити «над/под» чередуется, соседние параллельные нити в противофазе. Это и есть полотняное переплетение.

**Касание без проникания** в пересечении: `2A ≥ d`. По умолчанию `A = d/2`, то есть касание ровно, как слои в демо (`layer_gap = d_f`).

### 3.3. Профиль «дуги» (для сравнения с Circle_draw.txt)

Опция `--profile=arcs`: ось нити собирается из полуэллипсов, как в скрипте. Центр `k`-й дуги в `x_0 + k·p`, полуось вдоль нити `p/2`, по z — `A`, дуги чередуются вверх и вниз. Точки пересечения находятся на вершинах дуг. Профиль нужен только затем, чтобы воспроизвести скрипт. По умолчанию используется косинус, потому что у дуг на стыках вертикальная касательная и неравномерный шаг бусин.

### 3.4. Дискретизация

- На каждой полуволне ровно `k` сегментов. Бусины стоят **точно в каждой точке пересечения** (на вершинах), промежуточные — равномерно по длине дуги полуволны. Равномерно по параметру `x` ставить нельзя.
- Выступ `e_x` (`e_y`) делится на `max(1, round(e/(p/k)))` сегментов, отдельно по направлениям.
- По умолчанию `k = 4`, `e_x = e_y = p/2` (конец нити на середине полуволны).

### 3.5. Кромки и закрепление (`CLAMP_BOX`)

- `--clamp=none|x|y|xy` задаёт, какие нити зажаты с обоих концов: `y` — нити, идущие вдоль y (вертикальные нити Guo), `x` — вдоль x. По умолчанию `none`.
- `--clamp-edge=<м>` — граница зажима `c_e`, отсчитанная от центра полотна вдоль зажимаемых нитей: закреплены бусины с `|y − cy| ≥ c_e` (для `x` — с `|x − cx| ≥ c_e`). При `--clamp ≠ none` параметр **обязателен**, если его не задаёт пресет; иначе ошибка с понятным текстом. Одно значение на оба направления при `xy`.
- Проверки `c_e` (ошибка без `--allow-penetration` не отключается): для `y` должно быть `y_{n_x−1} − cy + d/2 ≤ c_e`, чтобы в зажим не попали бусины нитей основы и их пересечения, и `c_e ≤ y_{n_x−1} − cy + e_y`, чтобы на каждом конце была хотя бы одна зажатая бусина. Для `x` — то же с `n_y`, `e_x`.
- Генератор пишет **две** директивы на каждое зажатое направление (по одной на конец), всем компонентам (маска не пишется, по умолчанию `xyz`). Для `y`: `CLAMP_BOX X_lo  cy+c_e  Z_lo  X_hi  Y_hi  Z_hi` и зеркальная `CLAMP_BOX X_lo  Y_lo  Z_lo  X_hi  cy−c_e  Z_hi`, где `X_lo..Z_hi` — габариты всех бусин с запасом `d`. Числа — с `max_digits10`, как точки. Директивы стоят после всех блоков `FIBER`, с комментарием над ними (`--clamp`, `c_e`, ожидаемое число зажатых бусин).
- Бокс замкнутый: бусина, попавшая точно на `c_e`, закрепляется. Если какая-либо бусина зажимаемой нити ближе к `c_e`, чем `1e-9·p`, печатается `WARN` с её координатой: результат тогда зависит от округления, `c_e` лучше сдвинуть.
- В `PlainWeave` и раскладке зажатость хранится по бусинам: для каждой нити число зажатых бусин на нижнем и верхнем конце (§4.2). Поле `clamped(0|1)` раскладки остаётся.
- Анкеры и начальные скорости генератор не задаёт. Скорость зажатых бусин в сцене обязана быть ровно 0 (`validate_clamps`, `include/interactions/clamp.hpp:212-227`).

### 3.6. Материал

Одна строка `MATERIAL 0 <E> <nu> <d> <rho> <eps_break> [mu_ff [mu_fs]]` (формат `src/fiber_input.cpp:8-20`): `mu_ff` — трение нить–нить, `mu_fs` — трение нить–Solid, оба по умолчанию 0. Все значения задаются параметрами. `mu_fs` может стоять только после `mu_ff`: если задан `--mu-fs`, а `--mu-ff` нет, пишется `mu_ff = 0` явно. Если оба 0, необязательные поля не пишутся (файл как у старого формата).

### 4.2. CLI

```
plain_weave_gen --out=<файл.fib> [--layout=<файл>] [--preset=<имя>]
                [--d=] [--pitch=] [--amp=] [--nx=] [--ny=] [--seg=]
                [--overhang=] [--overhang-x=] [--overhang-y=]
                [--profile=cos|arcs] [--center=cx,cy,cz]
                [--clamp=none|x|y|xy] [--clamp-edge=]
                [--E=] [--nu=] [--rho=] [--eps-break=] [--mu-ff=] [--mu-fs=]
                [--allow-penetration]
```

- Все величины в СИ. Явный параметр переопределяет пресет. `--overhang=` задаёт оба выступа, `--overhang-x=`/`--overhang-y=` — каждый отдельно и сильнее `--overhang=`.
- Числа в `.fib` пишутся с `std::numeric_limits<double>::max_digits10`. Демо пишут с точностью потока по умолчанию (6 знаков), и `l0` при этом искажается.
- Шапка `.fib` — комментарии `#`: команда запуска, все параметры, итоговые числа (нити, бусины, связи, поверхностная плотность).
- Раскладка (`--layout`, по умолчанию `<out>.layout.txt`): строка на нить — `object_id direction(x|y) index offset clamped(0|1) first_bead last_bead n_clamp_lo n_clamp_hi` (последние два — число зажатых бусин у начала и у конца нити, 0 у свободных). `first_bead/last_bead` — глобальные индексы бусин в порядке загрузки. Формат сверить с `load_fiber_file`: бусины нумеруются подряд по блокам.
- В stdout печатается сводка: число нитей, бусин, связей, зажатых бусин; min/max `l0`; толщина полотна `2A + d`; поверхностная плотность `Σ m / (L_x·L_y)` по площади окна между крайними нитями; **оценка** стоимости как отношение числа бусин к 340 (демо «4 слоя»).
- Параметры проверяются: `d, p, A > 0`, `k ≥ 2`, `n_x, n_y ≥ 1`. Если `p < d` (соседние параллельные нити перекрываются) или `2A < d` (проникание в пересечении), генератор завершается с ошибкой. Флаг `--allow-penetration` превращает эти ошибки в предупреждения.

## 5. Проверки (`tests/test_plain_weave.cpp`)

Прогон на пресете `test` и ещё на одном нечётном варианте (`n_x = 3, n_y = 5`, `A = 0.75·d`, `k = 3`, `e_x = p/2`, `e_y = 1.5·p`, `--clamp=y` с `c_e` посередине выступа утка), чтобы поймать ошибки чётности и перепутанные направления. Все допуски относительные к `p`, если не сказано иное.

1. **Счёт.** Нитей `n_x + n_y`. Бусин в нити `(N_half·k) + 2·n_e + 1`, где `N_half` — число полуволн между крайними пересечениями, `n_e` — сегменты выступа **своего направления** (`e_x` у основы, `e_y` у утка). Связей на одну меньше, чем бусин. Число по формуле сравнивается с фактическим.
2. **Переплетение.** Для каждого пересечения `(i, j)` найти бусины обеих нитей, лежащие в нём. Разность z равна `±2A` с допуском 1e-12, знак `(−1)^{i+j}` как в §3.2. Вдоль каждой нити знак чередуется.
3. **Нет проникания.** Минимальное расстояние между любыми двумя **сегментами** разных нитей ≥ `d·(1 − 1e-9)`. Перебор всех пар на пресете `test` допустим. В отчёт выводится, где достигается минимум (ожидается: в пересечениях, равен `2A`). Если минимум меньше `2A` в стороне от узла, это находка: описать и не ослаблять допуск.
4. **Шаг бусин.** В каждой полуволне длины сегментов равны с допуском 1e-9. Печатаются min/max `l0` по всей ткани.
5. **Круговой путь через парсер проекта.** Записать `.fib`, загрузить `fiber::load_fiber_file` в `fiber::Model`. Координаты бусин совпадают с построенными (точно или до 1 ulp). Число связей равно числу из проверки 1. `object_id` каждой нити совпадает с раскладкой. Сумма масс равна `ρ·πd²/4·Σl0` с допуском 1e-12. `mu_ff`, `mu_fs` материала равны заданным (и 0, если не заданы).
   **Зажим:** при `--clamp=none` `model.clamps.fiber_mask` пуст (`empty()`, не нули). При `--clamp=y` маска размера `nfiber`; ненулевые элементы — ровно бусины нитей вдоль y с `|y − cy| ≥ c_e`, все с маской `interactions::kClampAll`; их число равно сумме `n_clamp_lo + n_clamp_hi` раскладки; у каждой зажимаемой нити хотя бы одна зажатая бусина на каждом конце; ни одной зажатой бусины у нитей вдоль x. Ожидаемая маска строится из `PlainWeave` независимо от парсера. То же для `--clamp=xy` на пресете `test`.
6. **Поверхностная плотность** из сводки совпадает с формулой `Σm / площадь`. Для `twaron_ct717` проверяется только генерация: без прогона цикла, с печатью числа бусин и плотности; ожидание 0.29 ± 0.03 кг/м². Если не совпадёт, это находка, её описывают.
7. **Контакт на исходной геометрии (диагностика).** Для пресета `test` вызвать `interactions::compute_fiber_contact_diagnostics` (`include/interactions/fiber_contact.hpp:860`) на загруженной модели. Печатаются `pair_count`, `contact_count`, `max_penetration`, а также `contact_count` на одно геометрическое пересечение. **Жёсткий гейт** — только отсутствие NaN/Inf. Если `contact_count > 0` при `2A = d`, это ожидаемо: оси нитей в модели — хорды соседних бусин, а не гладкие кривые, и в узле хорды сближаются меньше чем на `d`. На контакте «пара сегментов» ожидается не больше 1 контакта на пересечение; 2 означает «седло» (§2). Печатается `WARN` с числами, тест не падает. Отдельно печатается тот же замер при `A = 0.6·d` (зазор 20 %): при каком зазоре ложные контакты исчезают — полезное число для будущего e2e.
   **7б.** Тот же замер на геометрии пресета `twaron_ct717` (`d`, `p`, материал пресета), но на куске 12 × 12 нитей, при `k = 2` и `k = 4`, каждый при `A = d/2` и `A = 0.6·d` (четыре прогона). По этим числам ТЗ Guo выбирает `A` отдельно для каждого `k` (`guo2019-experiments-tz.md` §2 п.1): пресет `test` для этого не годится, у него `k = 4` и `p/d = 2`, а у Twaron `p/d ≈ 3`. Гейт тот же: только NaN/Inf, остальное печатается.
8. **Профиль `arcs`.** Точки лежат на полуэллипсах из §3.3 с допуском 1e-12. Бусины есть на вершинах.
9. **Ошибки параметров.** `p < d` и `2A < d` без `--allow-penetration` дают исключение с понятным текстом. С флагом генерация проходит, а предупреждение печатается. `--clamp=y` без `--clamp-edge` (вне пресета) и `c_e` вне диапазона §3.5 — исключение всегда, независимо от `--allow-penetration`.

Регистрация в `ctest`: `add_test(NAME plain_weave_test ...)`, метка `3d`, `TIMEOUT 120`. CLI проверяется отдельным `add_test`: запуск `plain_weave_gen --preset=test --out=<tmp>` должен завершиться с кодом 0. Временные файлы пишутся в каталог по образцу `e2e::ScopedWorkDir` (`cases/common/e2e_harness.hpp:80`), рабочее дерево не меняется.

## 10. Открытые решения

У каждого пункта есть вариант по умолчанию: он применяется, если владелец не ответит.

| № | Решение | По умолчанию |
|---|---|---|
| 1 | Генератор на C++ в проекте или скрипт на Python в `tools/` | C++: встраивается в будущие e2e напрямую, не нужен numpy (на рабочей машине его нет) |
| 2 | Диаметр нити для пресета `circle_draw`: в скрипте `s_d = 0.4 мм` подписан как «диаметр», но при `A = 0.1 мм` нити с `d = 0.4 мм` пересекаются уже на старте | `d = 2A = 0.2 мм` (касание), в отчёте указать, что это отступление от подписи в скрипте |
| 3 | Профиль по умолчанию | косинус (§3.2) |
| 4 | Бусин на полуволну `k` | 4. **Оценка** для `twaron_ct717`: ≈ 409 бусин на нить, ≈ 83 тыс. на полотно, в ≈ 245 раз больше демо «4 слоя». При `k = 2` получится ≈ 41 тыс. |
| 5 | Нужен ли конвертер k-файла (`*ELEMENT_BEAM`) → `.fib` для существующих сеток LS-PrePost | нет, генератор его заменяет |
| 6 | Зазор в пересечении: касание `2A = d` или с запасом | касание; число из проверки 7 покажет, нужен ли запас |

| 8 | Выступ и граница зажима `twaron_ct717` | `e_y = 5 мм`, `c_e = 60 мм` (оценки; в статье ширина зажима не задана). `e_x = p/2` — горизонтальные нити кончаются у свободной кромки |
