## 1. Цель и рамки

**Цель.** Дать ядру одно кинематическое условие Дирихле для частиц Solid и бусин Fiber: для отмеченных компонент `d` частицы `i` выполняется `x_{i,d}(t) = x_{i,d}(0)`, `v_{i,d}(t) = 0`. Реализация — проекция ускорений (и XSPH-поправки у Solid) в трёх точках шага и нулевая обратная масса в стадии трения.

**Входит:**
1. Заголовок `include/interactions/clamp.hpp`: данные, построение, проверки, проекция, реакция опоры, утилита разметки.
2. Три вставки в `src/time_integration.cpp` и новые параметры `detail::run_time_integration`.
3. Поля `fiber::Model::clamps`, `fiber::Model::clamp_report`.
4. Директива `CLAMP_BOX` в файле нитей (`src/fiber_input.cpp`).
5. Тесты `tests/test_clamp.cpp` (включая проверку параллельного детерминизма) и документация в `notes/fiber-model/fiber-problem-statement.md`.

**Не входит** (открытые решения, §14): заданная ненулевая скорость зажима; `*BOUNDARY_SPC_NODE` в k-файле; запрет накопления повреждения у зажатых частиц; исключение полностью зажатых примитивов из поиска контактов и из `dt`; проскальзывание в зажиме; сцены экспериментов Guo.

**Главное требование совместимости.** При пустом наборе зажимов все существующие тесты проходят без перегенерации эталонов, а результат побитово совпадает с сегодняшним. Все вставки в цикл — под `if (!clamps.empty())`.

## 3. Постановка

### 3.1. Маска

Для каждой реальной частицы Solid `i ∈ [0, ntotal)` и каждой бусины `k ∈ [0, nfiber)` задаётся маска `C ⊆ {0, …, dim−1}`, хранимая как `std::uint8_t` (бит `d` — компонента `d`). Маска `0` — частица свободна. Маска `kClampAll = (1u << dim) − 1` — полностью закреплена. Биты `≥ dim` запрещены (ошибка при старте).

### 3.2. Операции шага

- **Проекция P** над списком зажатых: для каждой закреплённой компоненты `a_{i,d} ← 0`; у Solid дополнительно `av_{i,d} ← 0` (XSPH, только в точке [1]).
- **Реакция**: до обнуления накапливается `R = −Σ_{i, d∈C_i} m_i·a_{i,d}` отдельно для Solid и Fiber. XSPH в реакцию не входит.
- **Бесконечная масса в трении**: у полностью закреплённых частиц счётчики mass splitting `c_k`, `c_s` ставятся в 0. У частично закреплённых не меняются (ограничение скалярного `c`, `FIBER_CLAMP_SPEC.md` §7 п. 3).

### 3.3. Почему `advance()` не меняется

При `a = 0`, `av = 0` и `v(0) = 0` предиктор и корректор PC (`include/ode/ode_solver.hpp:57-67`, `:75-104`) и Эйлер (`:116-122`) дают `v = 0` и `x += dt·0`, то есть `x` побитово неизменен. Отдельный сброс координат не делается. Если тест покажет, что это не так, это ошибка реализации проекции, а не повод добавлять сброс.

### 3.4. Что с зажатыми частицами Solid не делается

Они остаются в SPH-суммах, контактах и расчёте `dt`; у них продолжают интегрироваться `rho`, `u`, напряжения, `h` (`sle`), работает `apply_material_strength`. Из поиска пар и из каких-либо циклов они **не** исключаются.

## 4. Данные и API (`include/interactions/clamp.hpp`)

Заголовок самодостаточный, в стиле `fiber_friction.hpp`: шапка с описанием, ссылка на `notes/fiber-model/fiber-problem-statement.md` (раздел из §9), `#pragma once`. Ниже — обязательные имена и семантика; внутреннее устройство на усмотрение исполнителя, если выполнены требования §6.

```cpp
namespace interactions {

inline constexpr std::uint8_t kClampAll = static_cast<std::uint8_t>((1u << dim) - 1u);

// Входные маски (плотные). Пустой вектор == зажимов этого типа нет.
struct ClampSet {
    std::vector<std::uint8_t> solid_mask;   // размер ntotal или 0
    std::vector<std::uint8_t> fiber_mask;   // размер nfiber или 0
    bool empty() const { return solid_mask.empty() && fiber_mask.empty(); }
};

// Компактный список для цикла (SoA). Инвариант: index строго возрастает.
struct ClampList {
    std::vector<rhs::index_t> index;   // зажатые частицы
    std::vector<std::uint8_t> mask;    // их маски (!= 0)
    std::vector<rhs::index_t> full;    // подсписок с mask == kClampAll, тоже по возрастанию
    std::size_t size() const { return index.size(); }
};

// Реакция опоры за последний шаг (точки [1] + [3]); пишет ядро, читает сцена/хук.
struct ClampReport {
    double solid_force[dim] = {};
    double fiber_force[dim] = {};
    std::size_t solid_clamped = 0, fiber_clamped = 0;
    double solid_max_h = 0.0;           // max hsml среди зажатых Solid (печать при старте)
};

// Рабочая память стадии: списки + буфер для детерминированной суммы (§6.4).
// Выделяется до цикла по времени; в шаге память только переиспользуется.
struct ClampWorkspace {
    ClampList solid, fiber;
    std::vector<double> item_force[dim];    // размер max(solid.size(), fiber.size())
    std::vector<double> block_partial[dim]; // размер ceil(n / kClampReduceBlock)
};

// Построение списка из плотной маски. Бросает std::runtime_error, если
// mask.size() не 0 и не n, или есть биты >= dim.
void build_clamp_list(const std::vector<std::uint8_t>& mask, std::size_t n, ClampList& out);

// Проверки при старте (§4.2). Бросает std::runtime_error с индексом частицы.
void validate_clamps(const ClampSet& clamps, const ParticleSystem& sys, std::size_t ntotal,
                     const fiber::FiberState& fb);

// Проекция P + реакция. DvArr: std::vector<std::vector<double>> (Solid dvx)
// или std::vector<double>[dim] (Fiber dv) -- достаточно operator[][].
// av == nullptr -- XSPH не трогать. force_out += -Σ m a (добавляется, не присваивается).
template <class DvArr, class AvArr>
void apply_clamp_projection(const rhs::CpuExecutor& exec, const ClampList& list,
                            const std::vector<double>& mass, DvArr& dv, AvArr* av,
                            ClampWorkspace& ws, double (&force_out)[dim]);

// c_k = 0, c_s = 0 для полностью зажатых (списки full).
void apply_clamp_friction_counts(const rhs::CpuExecutor& exec, const ClampWorkspace& ws,
                                 std::vector<double>& bead_count, std::vector<double>& solid_count);

// Разметка области: out_mask[i] |= mask для всех i с lo <= x_i <= hi (замкнутый бокс).
void mark_clamp_box(const rhs::CpuExecutor& exec, const std::vector<double> (&x)[dim], std::size_t n,
                    const double (&lo)[dim], const double (&hi)[dim], std::uint8_t mask,
                    std::vector<std::uint8_t>& out_mask);
}
```

## 6. Параллелизм

Проект требует, чтобы параллелизм жил только в `rhs::CpuExecutor`, а physics-код не содержал `#pragma omp`, mutex и atomics (`notes/fiber-model/fiber-problem-statement.md`, «CPU executor», «Основные требования к interaction kernel»; `include/rhs/cpu_executor.hpp:15-36`). Закрепление обязано следовать тем же правилам и не ломать детерминизм по числу потоков.

### 6.1. Место в конвейере

Закрепление — не interaction type и не kernel. Это отдельная стадия **constraint** над уже сведённым RHS: она начинается после того, как `Reduce` всех вкладов и их сложение в `dvx`/`dv` полностью завершены, и заканчивается до того, как RHS станет входом стадии трения или решателя. В `notes/fiber-model/fiber-problem-statement.md` («ODE solver»: «после полного завершения Reduce сформированный RHS является неизменяемым входом») добавить оговорку про эту стадию (§9).

Требования:
1. Все функции `clamp.hpp` вызываются с главного потока цикла, между стадиями. Не из ветки `task_group` и не изнутри другого `parallel_for` (вложенных параллельных регионов нет).
2. Граница стадии — неявный барьер в конце `exec.parallel_for`/возврат из функции. Отдельной синхронизации не нужно.
3. Executor — `fiber_exec` из `run_time_integration` (`:107`), тот же, что у остальных стадий цикла. Новый `CpuExecutor` не создавать.

### 6.2. Отсутствие гонок по построению

- `ClampList::index` строго возрастает, значит, уникален. `build_clamp_list` строит его однократным проходом по плотной маске по возрастанию индекса; инвариант проверяется в тесте (§10 U1).
- Элемент `k` списка пишет только в ячейки своей частицы: `dv[d][index[k]]`, `av[d][index[k]]`, `count[index[k]]`, и в свой слот `item_force[d][k]`. Множества записи разных `k` не пересекаются, поэтому `parallel_for` по `k` не требует атомиков.
- Solid и Fiber проецируются двумя отдельными вызовами (разные массивы, разные списки). Сливать их в один диапазон не нужно.
- `apply_clamp_friction_counts` ходит по спискам `full`: уникальные индексы, запись только своей ячейки.
- `mark_clamp_box`: `parallel_for` по частицам, частица `i` пишет только `out_mask[i]`.

### 6.3. Порядок относительно стадии трения

Стадия трения читает `solver.fiber_rhs.dv`, `solver.solid_rhs.dvx`, `solver.solid_rhs.av` (пробные скорости, `fiber_friction.hpp:232-234`, `:266-273`) и счётчики `c_k`, `c_s` только на чтение внутри своих kernels. Поэтому:
1. [1] полностью завершается до `fiber_velocity_update`/`solid_velocity_update` и `compute_friction_contributions` — иначе пробная скорость зажатой частицы окажется ненулевой.
2. [2] выполняется после возврата `compute_friction_counts` (она сама делает свой reduce) и до `compute_friction_contributions`.
3. [3] выполняется только после `reduce_contributions` трения и сложения результата в `dv`/`dvx`.

Нарушение любого пункта — гонка чтения/записи между стадиями или неверная физика; тесты §10 F2, S2 его ловят.

### 6.4. Детерминированная реакция

`exec.parallel_reduce` для `double` использовать **нельзя**: он делит диапазон с `schedule(dynamic)` и сворачивает частичные суммы по потокам (`cpu_executor.hpp:110-138`), поэтому результат зависит от числа потоков и планирования.

Реакция считается двухуровневой суммой с фиксированным разбиением:
1. В том же `parallel_for`, что и проекция, элемент `k` до обнуления пишет `item_force[d][k] = −m·a_{d}` для закреплённых `d` и `0` для свободных.
2. Блоки фиксированного размера `kClampReduceBlock = 256` (константа в `clamp.hpp`, не зависит от числа потоков): `parallel_for` по блокам, внутри блока последовательная сумма по возрастанию `k` в `block_partial[d][b]`.
3. Последовательная сумма `block_partial` по возрастанию `b` на главном потоке.

Результат побитово одинаков при любом числе потоков и любом пороге из §6.5. Функцию суммы оформить отдельной (`clamp_fixed_block_sum`), чтобы её можно было переиспользовать и проверить отдельно (§10 U3).

### 6.5. Малые списки

Зажатых частиц обычно мало, а `parallel_for` при `num_workers() > 1` всегда открывает OpenMP-регион (`cpu_executor.hpp:74-93`). Ввести константу `kClampSerialThreshold` (начальное значение 4096, уточнить замером §11): при `list.size() < kClampSerialThreshold` проекция, запись `item_force` и счётчики выполняются обычным циклом на главном потоке. Оба пути обязаны давать побитово один результат (они выполняют одни и те же независимые операции над элементами, а сумма из §6.4 от пути не зависит); это проверяется тестом §10 U2.

### 6.6. Память

- `ClampWorkspace` выделяется один раз до `while`; `item_force` и `block_partial` — по максимальному размеру списков. В шаге никаких аллокаций (правило «память только растёт», как у буферов в `:102-128`).
- В kernel-функциях нет исключений, `std::vector::push_back`, ввода-вывода. Все проверки — в `build_clamp_list`/`validate_clamps` до цикла.

### 6.7. Задел под GPU

Операция над одним элементом (`clamp_project_item`: маска, масса, указатели на компоненты `dv`/`av`, выход `item_force`) оформляется как `inline`-функция без `CpuExecutor`, `std::vector` и исключений — по образцу `friction_projection_impulse` в `fiber_friction.hpp` («кандидаты на `__host__ __device__`»). `ClampList` хранится как SoA плоских массивов. CUDA-реализацию не делать.

### 6.8. Что с параллельностью остального цикла

Стадия не должна менять ни число, ни порядок параллельных регионов остальных стадий. При пустом наборе зажимов ни одна функция `clamp.hpp` не вызывается.

## 7. Файл нитей: `CLAMP_BOX`

В `src/fiber_input.cpp` (разбор ключевых слов, рядом с `MATERIAL` `:111` и `FIBER` `:165`) добавить необязательную директиву:

```
CLAMP_BOX <xmin> <ymin> <zmin> <xmax> <ymax> <zmax> [<mask>]
```

- Координат столько, сколько `dim` (в 3D — шесть чисел, как выше). `<mask>` — непустая строка из букв `x`, `y`, `z` без повторов (в 2D допустимы только `x`, `y`); по умолчанию все компоненты.
- Закрепляются все бусины всех нитей файла, попавшие в замкнутый бокс. Директива действует независимо от своего положения в файле: разметка выполняется после чтения всех нитей через `mark_clamp_box`. Несколько директив объединяются по «или».
- Результат — `model.clamps.fiber_mask` размера `nfiber`. Если директив нет, маска остаётся пустой (не заполненной нулями), чтобы сохранить побитовый путь без зажимов.
- Ошибки формата (не число, `xmin > xmax`, недопустимая буква, повтор буквы) — `std::runtime_error` с номером строки, в том же стиле, что у остальных директив.
- Обновить комментарий-описание формата над `load_fiber_file`.

## 8. Реакция и энергия

- `model.clamp_report` после каждого шага содержит реакцию этого шага (§5.5). Ядро её никуда не пишет; вывод в файлы — дело сцены.
- Работа реакции неподвижного зажима равна нулю. Если сцена считает энергобаланс, член «работа зажима» при этом механизме равен 0 тождественно.
- Баланс импульса: для системы без внешних сил и без XSPH (`cfg.epsilon = 0`) `P^{n+1} − P^n = h·(R_solid + R_fiber)`, где `h` — коэффициент обновления скорости шага (`dt/2` на первом шаге PC, `dt` далее; тот же, что возвращает `fiber_velocity_update(...).h`). Это проверяется тестом §10 F4, S4. С XSPH баланс не точен: обнулённая поправка `av` зажатых частиц — неучтённый вклад; это не ошибка.

### Нити

- **F1. Неподвижность.** Нить с зажатыми концевыми бусинами (несколько с каждой стороны), поперечная начальная скорость средней части, PC и Эйлер. По кадрам вывода (читалка как в `tests/e2e_frames.hpp`) и в конце: `x` зажатых бусин побитово равны начальным, `v` равны `0.0`.
- **F2. С трением.** То же, плюс свободная нить, скользящая поперёк зажатой части (`mu_ff > 0`): неподвижность как в F1, нет NaN/Inf, пары «зажатая–зажатая» не дают силы трения.

Струна.** Предварительно натянутая нить с зажатыми концами, малое поперечное отклонение: период основной моды сходится к `T = 2L·√(ρA/N)` при измельчении (допуск и уровни измельчения выбрать и записать; ориентир — 2 % на самом мелком уровне), энергия нити сохраняется в пределах погрешности интегрирования.

## 14. Открытые решения (не делать без отдельного решения)

1. **Заданная скорость зажима.** Механизм уже сохраняет любую начальную скорость зажатой компоненты; нужно снять проверку §4.2 п. 3 и проверить трение о движущийся зажим (пробная скорость зажатой частицы равна заданной, `c = 0` уже даёт бесконечную массу). Нужна для растяжения образцов.

3. **Запрет повреждения у зажатых частиц** (JH-2 `sys.D`, `src/ppochnost.cpp:138-179`; будущая модель разрушения Al): флаг `freeze_damage`.
4. **Исключение полностью зажатых примитивов** из поиска контактов и `dt` — только если замер покажет, что зажим режет шаг.
5. **Проверки геометрии зоны** (ширина полосы ≥ носителя ядра, зажим всех слоёв по толщине) — это функции сцены; общая утилита — после первой сцены, которой она понадобится.
