# План для Claude Code: ткань-«одеяло» из патчей в генераторе plain_weave

Адресат: Claude Code, работающий в репозитории `smarry-code/SPH` (ветка `Guo2T`, там генератор и сцена Guo 2019).
Все ссылки на код проверены чтением файлов `include/fiber/plain_weave.hpp`, `tools/plain_weave/plain_weave_gen.cpp`, `cases/guo2019/experiment/guo2019_scene.hpp`, `cases/guo2019/experiment/guo2019_case.hpp`, `docs/02-how-to/02-plain-weave-generator.md`. Код не собирался и не запускался.

## 1. Цель

Ткань «одеяло»: прямоугольная сетка из `tile_x × tile_y` одинаковых патчей по `patch_ny × patch_nx` нитей. Нити непрерывны через стыки (решение заказчика, без отдельных «швов»). Размер всей ткани должен совпадать с исходной тканью расчётов Guo 2019 (`--level=base`): 102 × 102 нити, шаг 1.18 мм, окно 101 · 1.18 = 119.2 мм. Для этого патч 34 × 34 и сетка 3 × 3.

Параллельно существует SCL-скрипт для LS-PrePost (`/mnt/project-files/weave-patch/patch_60x60.scl`, строит тот же патч и тиражирует его с склейкой узлов). Генератор в C++ должен давать ту же геометрию, чтобы результаты можно было сверять.

## 2. Что в коде уже есть (важно для дизайна)

1. `fiber::build_plain_weave(PlainWeaveParams)` строит всю ткань сразу: плоскость x-y, толщина по z. Основа `j = 0..nx-1` идёт вдоль x на `y_j = cy + (j - (nx-1)/2)·p`, уток `i = 0..ny-1` вдоль y на `x_i = cx + (i - (ny-1)/2)·p`. Нить одна непрерывная ломаная (`PlainWeaveFiber::pts`), на каждом пересечении бусина (`vertex_bead`), между вершинами ровно `seg` хорд равной длины.
2. Знаки волны: основа `j` стартует со знаком `(-1)^j`, уток `i` со знаком `-(-1)^i`. Фаза зависит только от чётности глобального индекса.
3. Уже непрерывная нить через «стыки» получается сама собой, если задать `nx = tile_y·patch_nx`, `ny = tile_x·patch_ny`. Фаза на стыке верна автоматически. Отдельный сшивающий код не нужен.
4. Выступы нитей за крайнюю поперечную нить: `overhang_x` (по умолчанию `p/2`) и `overhang_y`; зажим пишется двумя `CLAMP_BOX` на направление по границе `clamp_edge`. Всё это относится ко всей ткани целиком, не к патчу.
5. Пресет `twaron_ct717` (d = 0.39 мм, p = 1.18 мм, A = 0.5d, 102 × 102, профиль `Cos`, `overhang_y = 5 мм`, `clamp = Y`, `clamp_edge = 60 мм`). Сцена `cases/guo2019/experiment/guo2019_scene.hpp` берёт пресет, переопределяет `amp = 0.6·d` (`kFabricAmpOverD`), `seg`, `nx/ny`, `overhang`, `clamp`, материал и вызывает `build_fabric_stack` → `build_plain_weave`.
6. Выходной формат `.fib`: одна `MATERIAL 0`, по блоку `FIBER 0 n` на нить, затем `CLAMP_BOX`. Раскладка нитей пишется отдельным `.layout.txt` (`write_plain_weave_layout`).
7. Тест геометрии: `tests/test_plain_weave.cpp` (`add_test(NAME plain_weave_test ...)` в `CMakeLists.txt`, около строки 658) и `tests/plain_weave_cli_test.cmake` для CLI.

Вывод: геометрически «одеяло» из патчей с непрерывными нитями = одна ткань. Реальная работа: (а) удобный интерфейс «патчи», (б) метка принадлежности бусин патчу, (в) тесты, доказывающие, что это действительно тиражирование одного патча, (г) документация и связка с SCL.

## 3. Дизайн

Не менять существующий API `build_plain_weave`, структуру `PlainWeave` и формат `.fib`: сцена Guo 2019 и все тесты должны работать как раньше.

Новый заголовок `include/fiber/plain_weave_quilt.hpp` (header-only, как `plain_weave.hpp`, без зависимости от `dim`):

```cpp
namespace fiber {
struct QuiltParams {
    PlainWeaveParams base;   // d, pitch, amp, seg, overhang_*, profile, c*, clamp, материал
                             // поля base.nx / base.ny игнорируются и вычисляются
    int patch_nx = 34;       // нитей основы (вдоль x) в патче
    int patch_ny = 34;       // нитей утка  (вдоль y) в патче
    int tile_x   = 3;        // патчей вдоль x (это патчи по утку: ny = tile_x*patch_ny)
    int tile_y   = 3;        // патчей вдоль y (nx = tile_y*patch_nx)
};
struct PlainWeaveQuilt {
    PlainWeave W;                       // обычная ткань, nx = tile_y*patch_nx, ny = tile_x*patch_ny
    QuiltParams params;
    std::vector<std::vector<int>> bead_patch;  // [нить][бусина] -> id патча = ty*tile_x + tx
    std::vector<double> seam_x, seam_y; // координаты стыков вдоль x и y (tile_x-1 и tile_y-1 значений)
};
PlainWeaveQuilt build_plain_weave_quilt(const QuiltParams&);
void write_plain_weave_quilt_patches(std::ostream&, const PlainWeaveQuilt&); // <out>.patches.txt
}
```

Правила:
- `build_plain_weave_quilt` подставляет `nx = tile_y·patch_nx`, `ny = tile_x·patch_ny` и вызывает `build_plain_weave`, ничего не дублируя.
- Стык между патчами `t-1` и `t` лежит на середине полуволны между вершинами `t·P - 1` и `t·P` (`P = patch_ny` вдоль x, `patch_nx` вдоль y): координата `c + (t·P - 1/2 - (n-1)/2)·p`. `seam_x` и `seam_y` хранят эти значения.
- Принадлежность бусины: по её координате вдоль нити относительно стыков; бусина ровно на стыке (допуск `1e-9·p`) относится к патчу с меньшим индексом. Выступы за крайние нити относятся к крайним патчам.
- Поперёк нити (в какой патч попадает нить): нить основы `j` принадлежит ряду патчей `floor(j / patch_nx)`, нить утка `i` ряду `floor(i / patch_ny)`. `bead_patch` комбинирует обе координаты: id = (ряд по y) · `tile_x` + (ряд по x), где ряд по оси нити определяется координатой бусины, а ряд поперёк неё номером нити.
- Проверки параметров: все целые ≥ 1; `seg` может быть любым (метка по координате, а не по номеру бусины). Если `patch_nx` или `patch_ny` нечётны, `tile > 1` и фаза патчей отличается (патч (1,0) получится зеркальным, а не сдвинутым): бросать `std::invalid_argument`, если не задан флаг `allow_odd_patch`, с предупреждением в `warnings`.
- Все остальные проверки (`p < d`, `2A < d`, диапазон `clamp_edge`, число бусин) делает `build_plain_weave` уже для всей ткани.

## 5. Тесты (критерии приёмки)

1. **Эквивалентность целой ткани.** `build_plain_weave_quilt({twaron_ct717 + сцена Guo, patch 34x34, tile 3x3})` даёт те же `fibers[*].pts` (побитово) и тот же текст `.fib`, что `build_plain_weave` с `nx = ny = 102`. Это регрессия: сцена Guo 2019 не меняется.
2. **Тиражирование патча.** Для чётных `patch_*`: для каждого патча `(a, b)` и каждой бусины, лежащей внутри окна патча (не выступ), её координаты равны координатам соответствующей бусины патча `(0, 0)` плюс `(a·patch_ny·p, b·patch_nx·p, 0)` с допуском `1e-12·p`. Доказывает, что фаза волны на стыках сходится.
3. **Нет разрывов.** Для всех связей `l0_max/l0_min` ткани из патчей совпадает с одной тканью той же площади; ни одна связь не пересекает стык с длиной, отличной от обычной (на стыке есть бусина или хорда равной длины).
4. **Метки.** Сумма бусин по патчам равна общему числу бусин; для внутренних патчей число бусин одинаково; бусина на стыке относится к патчу с меньшим индексом.
5. **Нечётный патч.** Без `--allow-odd-patch` ошибка, с флагом предупреждение.
6. **Размер.** `plain_weave_window` для `3×3` по `34` даёт 119.2 × 119.2 мм.
7. **Пересечения (проверка переплетения).** В каждом пересечении `|z_основы - z_утка| = 2A` (в пределах допуска) и нет проникания при `2A ≥ d` для обоих профилей; это уже проверяет существующий `test_no_penetration`, прогнать на ткани из патчей.

Все существующие тесты (`plain_weave_test`, `plain_weave_cli_test`, тесты сцены Guo 2019) проходят без изменений.

## 6. Сверка с SCL-скриптом (после реализации, делает заказчик)

SCL-геометрия (`patch_60x60.scl`): основа вдоль x, уток вдоль -z, толщина по y, профиль полуэллипсов. Сопоставление с генератором (`--profile=arcs`): `x_gen = x_scl`, `y_gen = -z_scl`, `z_gen = y_scl`, плюс сдвиг начала координат и, возможно, зеркало по z (знак фазы, это выясняется по первому пересечению). Сравнивать только вершины (пики и нули), потому что `elgenerate beam bycurve` делит дугу на элементы, а генератор по хордам равной длины. Путь: экспорт `.k` из LS-PrePost, импорт по `docs/02-how-to/03-ls-prepost-to-calculation.md` (`*ELEMENT_BEAM`, режим `solid_fiber`, `tests/test_k_fiber.cpp`), сравнение узлов. Скрипт SCL пока не проверен в LS-PrePost: нужно подтвердить порядок фаз (основа и уток в противофазе в каждом пересечении) и накопление копий в `translate_model ... copy N`.

## 7. Вне объёма и открытые вопросы

- «Сшивание» без непрерывности нитей (разные нити на патчах, связанные дополнительными связями) не делаем: заказчик выбрал непрерывные нити.
- Разные материалы или параметры по патчам: `bead_patch` это позволит позже, сейчас материал один.
- Нужно ли сцене Guo 2019 знать про патчи (например, для разных `damage` по патчам)? По умолчанию нет.
- Размер патча 34 × 34 (≈ 40 мм) выбран, чтобы 3 × 3 дало ровно 102 нити; патч 60 мм при шаге 1.18 мм не делит 102.
- Профиль в расчётах косинусный, а в SCL эллиптический; на сходимость расчёта это не влияет, но геометрия отличается формой волны.

# Этап 2: прошивка слоёв («стёганое одеяло»)

Добавлено 2026-11-11 по решению заказчика: интересует шов поперёк слоёв (стёжка), который связывает слои пакета 2T/4T между собой. Патчи из этапа 1 задают сетку стёжки: линии шва идут по границам патчей.

## 8. Что говорит литература (кратко)

- Bilisik, Turhan, *Textile Research Journal* 79(14), 2009: многонаправленно прошитые пакеты Kevlar 29/129. Поглощённая энергия у прошитых и непрошитых пакетов значимо не отличается, но глубина вмятины на тыльной стороне меньше у прошитых: стёжка делает пакет жёстче и мешает слоям смещаться. Непрошитые слои свободно сдвигаются при ударе.
- Karahan, Kuş, Eren, *Int. J. Impact Eng.* 35(6), 2008: панели Twaron CT 710, три типа стёжки; число слоёв и тип стёжки значимо влияют на глубину и диаметр вмятины (подробности в закрытом тексте не читались).
- Li, Zhang, Min, Zhou, Sun, *Defence Technology* 24, 2023 (seamed woven fabrics, арамид, шар 8 мм, 230 и 400 м/с): прошитая ткань поглощает больше, до ~135 % (1 слой, шов через 4 нити) и ~156 % (многослойная) от непрошитой. Механизм по pull-out: шов ограничивает подвижность нитей и повышает трение между нитями; при слишком плотной прошивке поглощение снова падает (пережатие).
- Есть экспериментально-численные работы по прошитым тканям (Zhou et al., *Composite Structures* 261, 2021; Zhou et al., *J. Industrial Textiles*, 2022, UHMWPE; работа 2024 г. в *Thin-Walled Structures* по косому удару), но способ моделирования стежков в них не прочитан: полные тексты закрыты.

Вывод для модели: стёжка должна (1) не давать слоям расходиться и скользить друг по другу в точках шва, (2) ограничивать подвижность нитей рядом со швом, (3) иметь собственный порог разрыва, (4) иметь настраиваемую плотность, потому что эффект немонотонен.

## 9. Что есть в коде (ветка Guo2T)

- `FiberTopology` (`include/fiber/fiber_system.hpp`): `prev/next` описывают только цепочку нити, а `bonds` это список пар `FiberBond{i, j, l0, l_break}`, то есть связь между любыми двумя бусинами по структуре данных возможна.
- `FiberMaterial` у бусины, у связи своего материала нет: жёсткость связи берётся из материала бусин (уточнить в ядре Fiber-Bond).
- `.fib` (`src/fiber_input.cpp`) знает только `MATERIAL`, `FIBER`, `CLAMP_BOX`.
- Контакт нить-нить отбрасывает пары с одинаковым `object_id` (`include/interactions/fiber_contact.hpp`); бусины разных слоёв это разные нити, контакт между слоями работает.
- Слои в 2T/4T одинаковые и без сдвига в плоскости (`build_fabric_stack`, шаг `Delta_ply = 2A + d + eps_ply`), поэтому одинаковые бусины разных слоёв стоят точно друг над другом.

## 10. Модель стежка (рекомендуемый первый вариант)

**Стежок = вертикальная связь между соответствующими бусинами соседних слоёв** в точке прокола. Цепочка стежка через весь пакет: слой 1 — слой 2 — … — слой N.

- Только растяжение (как связи нити), длина `l0` равна начальному расстоянию между бусинами, разрыв по своему `eps_break_stitch`.
- Собственный материал стежка: `E`, `d` (диаметр швейной нити), `eps_break`. Нужен материал у связи, а не у бусины.
- Точки прокола: на линиях шва по границам патчей. Граница патча лежит на середине полуволны между нитями, и при чётном `seg` там есть бусина каждой поперечной нити (`z = cz`). Это и есть точки прокола: шаг стежка вдоль линии = шаг нитей `p` или кратный ему (параметр `stitch_every`).
- Связи стежков не меняют `prev/next`, поэтому сегменты контакта нить-нить не затрагиваются.
- Вариант 2 (позже): швейная нить как отдельная цепочка `FIBER`, которая проходит сквозь пакет и лежит на поверхности между проколами, привязанная к бусинам слоёв кинематически. Ближе к реальности (нить может проскальзывать), но требует связей «нить-бусина» и сложнее.

## 11. Шаги реализации

1. **Ядро:** у `FiberBond` добавить индекс материала связи (по умолчанию материал бусины `i`, побитово прежнее поведение для обычных связей). Ядро Fiber-Bond берёт `E`, `d` связи из этого материала. Проверить, что разрыв связи и `topology.version` работают для связи вне цепочки (у неё нет `prev/next`).
2. **Формат `.fib`:** директива `BOND <bead_i> <bead_j> <material_id>` (глобальные индексы бусин в порядке блоков `FIBER`, `l0` считается по начальным координатам). Обновить `load_fiber_file`, его описание в комментарии и справочник формата в `docs/`.
3. **Генератор:** в `plain_weave_quilt.hpp` функция построения стёжки для пакета слоёв: вход `stitch_lines = патчевые границы (x и/или y)`, `stitch_every`, материал стежка; выход список пар бусин. Запись `MATERIAL 1 ...` и строк `BOND` в `.fib` пакета (`write_fabric_stack_fib` в `cases/guo2019/experiment/guo2019_scene.hpp` или общий писатель).
4. **Сцена Guo 2019:** флаги `guo2019_shot --stitch=none|grid --stitch-every=N --stitch-E= --stitch-d= --stitch-eps-break=` для конфигураций 2T и 4T. По умолчанию `none`: прежние расчёты не меняются.
5. **Монитор:** число целых и порванных стежков во времени, сила в стежках, относительное смещение слоёв в плоскости (среднее по точкам прокола), прогиб тыльного слоя.

## 12. Тесты

1. Без `BOND` результаты прежних тестов и сцены побитово те же.
2. Два слоя по 2 нити, одна связь `BOND`: при раздвигании слоёв сила связи `E·A·(l-l0)/l0` по материалу стежка, при `l > (1+eps_break)·l0` связь рвётся, `topology.version` растёт.
3. Сжатие стежка не даёт силы (только растяжение).
4. Контакт нить-нить между слоями с прошивкой и без неё одинаков в начальном состоянии (стёжка не создаёт ложных контактов).
5. Генератор стёжки: число стежков = (число линий) × (число проколов на линии) × (N слоёв - 1); каждая пара бусин лежит на одной вертикали (|Δx|, |Δy| < 1e-12).
6. Дымовой прогон 2T `smoke` со стёжкой: слои не расходятся в точках прокола, энергия ограничена.

## 13. Проверка физики (открытые вопросы)

- В опытах Guo 2019 пакеты не прошиты, поэтому прямой валидации нет. Сравнивать с непрошитыми 2T/4T и с тенденциями из литературы: меньше прогиб тыльной стороны (Bilisik 2009), рост поглощения при умеренной плотности и спад при чрезмерной (Li 2023).
- Параметры швейной нити (материал, диаметр, прочность) и шаг стёжки должна задать заказчица.
- Повреждение нитей иглой при прошивке не моделируется.
