# План внедрения чтения геометрии из `.k` (LS-DYNA) в smarry-code/SPH

Только план, без кода. Основа:
- спецификация формата: [`k-format/ls-dyna-k-format-spec.md`](../k-format/ls-dyna-k-format-spec.md), [`k-format/cards.json`](../k-format/cards.json);
- отчёты о геометрии в проекте: [`sph-geometry/sph-geometry-analysis-fiber_new.md`](../sph-geometry/sph-geometry-analysis-fiber_new.md) и [`sph-geometry/sph-geometry-analysis.md`](../sph-geometry/sph-geometry-analysis.md) (master);
- сверка с кодом ветки `fiber_new`, коммит `e930bc3`. Ссылки `файл:строка` относятся к этой ветке.

**База — ветка `fiber_new`.** Геометрия нитей (`fiber::Model`, `FiberState`, `FiberTopology`, формат `.fib`) есть только там, а режим «Solid + Fiber» без неё реализовать не на что. Режим «только Solid» технически можно сделать и на master, но тогда его придётся переносить второй раз.

**Оговорка о достоверности спецификации.** Поля `*NODE` (ширины 8/16/16/16/8/8, TC/RC) и структура `*PART` в спецификации помечены **[K]**: они не сверены с официальным PDF-мануалом LS-DYNA (он был недоступен). Также не проверены включительность `NEND` в `*ELEMENT_SPH`, правила long-формата и вещественные без десятичной точки в fixed-формате. План учитывает это отдельным этапом K0 и устройством парсера (раздел 4.1).

## 1. Что именно делаем: два режима

| | Режим 1: `solid` | Режим 2: `solid_fiber` |
|---|---|---|
| Что читается из `.k` | Solid-частицы: `*NODE` + `*ELEMENT_SPH` (+ `*PART` для списка PID) | То же + нити: `*ELEMENT_BEAM` (цепочки 2-узловых элементов) |
| Куда пишется | `ParticleSystem` (`model.solid`) | `model.solid` + `model.fiber`, `model.topology`, `model.materials` |
| Размерность сборки | `SPH_DIM` = 1, 2 или 3 (со строгой проверкой координат, решение Р6) | только `SPH_DIM=3` (`fiber::check_fiber_requires_dim3`, `include/fiber/fiber_system.hpp:42`) |
| Что делать с `*ELEMENT_BEAM` в файле | пропустить с предупреждением (сколько элементов и каких PID) | превратить в нити; PID без описания в таблице деталей — ошибка |
| Нет ни одной нити | — | ошибка (как `load_fiber_file` при пустом файле, `src/fiber_input.cpp`) |

Независимо от режима нити можно взять из `.fib` (ключ `fiber_file`, этап K6): Solid из `.k` в режиме `solid` или из встроенного генератора + нити из `.fib`. Сочетания источников — в Р10.

«Solid» здесь — Solid-частицы проекта (`ParticleSystem`), а не сеточный `*ELEMENT_SOLID` LS-DYNA. Перевод гекса/тетра-сеток `*ELEMENT_SOLID` в частицы — отдельный необязательный этап K9 (раздел 6).

## 2. Исходное состояние (кратко)

- `parse_k_file` (`src/input.cpp:121-260`) читает только free-format через запятую, только `*NODE` и `*ELEMENT_SPH`; пишет `x[0..2]` безусловно (выход за границы при `dim<3`); элементы без узла молча теряются; в нём зашит поиск мониторной частицы (`x>0.0131`, `itype==3`, …) с записью в `log.txt`; `itype = body = PID`.
- В `input()` вызов закомментирован (`src/input.cpp:857`) вместе с жёсткой таблицей PID → itype/ρ/скорость. Источник геометрии выбирается compile-time флагами `config_input`, `shocktube`, `shearcavity` (`include/param.hpp:259,283-284`).
- `main` (`src/main.cpp`) работает только с `ParticleSystem` и перегрузкой `time_integration(cfg, sys, …)`. Перегрузка для `fiber::Model` уже есть (`include/time_integration.hpp:41`), их эквивалентность при пустых нитях проверена `tests/test_fiber_time_integration_equivalence.cpp`. Аргумент `delta_x` в реализации не используется (`src/time_integration.cpp:83`).
- Сборка модели нитей из ломаных (масса бусин, `l0`, `l_break`, `prev/next`, `object_id`, маска зажимов) живёт внутри `fiber::load_fiber_file` (`src/fiber_input.cpp:330-400`) и не вынесена в отдельную функцию.
- Тестовый `1.k` (LS-PrePost 2026, free-format, 250 000 частиц, 2 детали, `*PART` только с PID) — главный реальный образец.

## 3. Проектные решения

Все решения раздела утверждены Мэри 2026-10-03 (Р1, Р2 и имена ключей Р10 подтверждены явно).

**Р1. Чем в `.k` задаются нити.** Цепочками `*ELEMENT_BEAM` (N1, N2; N3 — узел ориентации, игнорируется). Нить = связная компонента графа «узел — балка», являющаяся простой незамкнутой цепочкой. Ветвление (узел степени > 2) и замкнутое кольцо — ошибка с указанием NID. Альтернатива `*ELEMENT_DISCRETE` (пружины) хуже: нет сечения и плотности. **Подтверждено Мэри 2026-10-03.**

**Р2. Откуда физика деталей: таблица деталей (sidecar-файл), а не `*MAT_*`/`*SECTION_*`.** `.k` даёт геометрию и PID; привязка PID к материалу проекта задаётся отдельным текстовым файлом в стиле `.fib` (пробелы, комментарии `#`), путь — ключ конфигурации `k_parts_file`. Директивы:
- `SOLID_PART <pid> <itype> <rho> [hsml=<h>] [v=<vx> <vy> <vz>]` — Solid-деталь;
- `MATERIAL <id> <E> <nu> <d> <rho> <eps_break> [mu_ff [mu_fs]]` — материал нити, синтаксис **тот же**, что в `.fib`, и разбирается тем же кодом;
- `FIBER_PART <pid> <material_id>` — деталь из балок становится нитями с этим материалом.

Почему не из `.k`: `itype` проекта (`include/materials.hpp`: 3 тантал … 11 Al2O3) с `*MAT_*` LS-DYNA напрямую не сопоставляется; у нити `eps_break`, `mu_ff`, `mu_fs` в `.k` не выражаются; единицы `.k` произвольны. Чтение `*SECTION_BEAM`/`*MAT_ELASTIC` как перекрёстной проверки диаметра и E — возможное расширение, не в первой версии. Таблица заменяет закомментированную жёсткую таблицу PID → itype/ρ в `input()`. **Подтверждено Мэри 2026-10-03.**

`itype` — номер материала частицы проекта (`ParticleSystem::itype`). По нему выбираются УРС в `urs()` (`src/int_force.cpp:16`: 1 газ, 2 вода, 3–4 Ми-Грюнайзен, 5–9 Тэт, 10–11 JH-2), модуль сдвига и предел текучести (`include/materials.hpp:59`), модель разрушения керамики (`src/ppochnost.cpp:59`). Неизвестный itype — исключение в `urs()`.

Формат таблицы деталей (текст, поля через пробелы, `#` — комментарий до конца строки, одна директива на строку):
```
# SOLID_PART <PID> <itype> <rho> [hsml=<h>] [v=<vx> <vy> <vz>]
SOLID_PART 1 7  320  v=1546 0 0   # ударник, полиуретан 320
SOLID_PART 2 10 2510              # керамика B4C
SOLID_PART 3 10 2510              # керамика B4C, второе тело
SOLID_PART 4 5  2638              # окно LiF
# нити (только в режиме solid_fiber); MATERIAL — синтаксис .fib
MATERIAL 0 2.0e9 0.35 1.0e-4 1140 0.02
FIBER_PART 5 0
```
Пример воспроизводит закомментированную таблицу из `input()`. Для каждой частицы детали: `itype` из таблицы; `rho = rho_0 =` плотность из таблицы; `vx` из `v=…` (иначе 0; компонент столько, сколько `dim`, лишние — ошибка, если не нулевые); `hsml` из таблицы или `2·(m/ρ)^(1/dim)`; `body = PID` (детали с одинаковым itype остаются разными телами для контакта); затем `urs()`.

Проверки таблицы:
- PID есть в `*ELEMENT_SPH`, но нет в `SOLID_PART` — ошибка;
- PID балки нет в `FIBER_PART` (режим `solid_fiber`) — ошибка;
- `itype` вне 1–11, `rho ≤ 0`, `hsml ≤ 0` — ошибка;
- PID повторяется (в том числе в `SOLID_PART` и `FIBER_PART` одновременно) — ошибка;
- `FIBER_PART` ссылается на необъявленный `MATERIAL` — ошибка;
- в таблице есть PID, которого нет в `.k`, — предупреждение;
- ошибки сообщают файл и номер строки.

**Р3. Поля Solid, которых нет в `.k`.**
- `rho`, `rho_0`, `itype` — из `SOLID_PART`.
- `hsml` — из `SOLID_PART`, иначе автоматически `2·(m/ρ)^(1/dim)` по каждой частице (конвенция проекта `hsml = 2·dx`, как в `shock_tube` и генераторах тестов).
- `vx` — из `SOLID_PART v=…`; `*INITIAL_VELOCITY*` не читаем в первой версии.
- `p, c, u, …` — нули (`inzializ_index`), затем `urs()` по каждой частице, как в `tests/guo2019_scene.hpp`.
- `body = PID` (уже так; `fiber/PLAN.md:49`).
- `MASS < 0` в `*ELEMENT_SPH` — объём: `mass = |MASS|·ρ(PID)`; суффикс `_VOLUME` — так же независимо от знака.

**Р4. Мониторная частица.** Зашитое условие из `parse_k_file` удаляется. Новый необязательный ключ `k_monitor_nid` (NID узла в `.k`) → `cfg.moni_particle` = индекс этой частицы; без ключа — 0, как в `apply_defaults`.

**Р5. Единицы.** Ключи `k_length_scale` и `k_mass_scale` (по умолчанию 1.0) умножают координаты и массы при чтении; значения в таблице деталей — сразу в СИ.

**Р6. Размерность для Solid.** `dim=3` — все три координаты. `dim=2` — плоскость xy, все `|z|` ≤ допуска, иначе ошибка. `dim=1` — ось x, `|y|,|z|` ≤ допуска, иначе ошибка. Допуск — относительный от габарита модели. Молча отбрасывать координату нельзя. Осесимметрия (`axis[]`) из `.k` не выводится и в объём не входит.

**Р7. Объём формата в первой версии.** Поддерживаем: free (запятые), fixed по ширинам карточки, long (`*KEYWORD LONG=Y`, суффиксы `+`/`-`), `$`-комментарии в колонке 1, `*KEYWORD`, `*TITLE`, `*END`, `*INCLUDE`, `*INCLUDE_PATH`, `*INCLUDE_PATH_RELATIVE`, `*PART` (только PID; остальные строки до `*` пропускаются), `NEND`-развёртку. Явная ошибка (а не тихий ноль): `&параметр` (`*PARAMETER`), `*INCLUDE_TRANSFORM`, `*ELEMENT_BEAM_*` с неизвестной опцией (опции добавляют карточки, и без их знания теряется синхронизация строк). Пропуск со сводкой: все прочие ключевые слова (`*MAT_*`, `*SECTION_*`, `*SET_*`, `*CONTROL_*`, …).

**Р8. Пересечения ролей.** Узел одновременно в `*ELEMENT_SPH` и в `*ELEMENT_BEAM` — ошибка. Дубликат NID в `*NODE`, дубликат EID, ссылка на отсутствующий узел, PID без `*PART` — ошибка с файлом и номером строки (сейчас элемент без узла молча теряется).

**Р9. Детерминизм порядка.** Solid-частицы — в порядке `*ELEMENT_SPH` в файле (с учётом include). Нити — в порядке первого появления их балки в файле; внутри нити обход от конца с меньшим NID. `object_id` = порядковый номер нити. Это нужно для воспроизводимости регрессий.

**Р10. Выбор источника геометрии в рантайме.** Новые ключи `Initial_Conditions.txt`: `k_file=<путь>` и `k_mode=solid|solid_fiber` (по умолчанию `solid`). Если `k_file` задан, он имеет приоритет над `shocktube`/`shearcavity`; `config_input` (particles.dat) и `k_file` одновременно — ошибка. Ключ `fiber_file` (сейчас разбирается, но никем не читается, `src/input.cpp:421-427`) начинает работать: после построения Solid `main` вызывает `fiber::load_fiber_file(cfg.fiber_file, model)`. Допустимые сочетания:

| Solid | Нити | Ключи |
|---|---|---|
| `.k` | нет | `k_file`, `k_mode=solid` |
| `.k` | `.fib` | `k_file`, `k_mode=solid`, `fiber_file` |
| `.k` | `.k` (балки) | `k_file`, `k_mode=solid_fiber` |
| генератор / `particles.dat` | `.fib` | `fiber_file` |
| любой | `.k` и `.fib` одновременно | ошибка: `k_mode=solid_fiber` вместе с `fiber_file` (два источника нитей) |

Нити из `.fib` требуют `SPH_DIM=3` (проверка уже есть в `parse_sph_config`). Если в режиме `solid` файл `.k` содержит балки и задан `fiber_file`, балки пропускаются с предупреждением, как и без `fiber_file`. **Имена ключей подтверждены Мэри 2026-10-03.**

## 4. Архитектура

### 4.1 Слои

```
.k-файл(ы) ──► [1] KReader ──► [2] KDeck ──► [3a] Solid-сборщик ──► model.solid
                 строки,          узлы, SPH,      PID-таблица,         (ParticleSystem)
                 ключевые слова,  балки, детали   dim, единицы
                 include,                     └► [3b] Fiber-сборщик ──► fiber::build_model_from_polylines ──► model.fiber/topology/materials
                 fixed/free/long                  цепочки балок            (общая с .fib)
```

1. **`KReader`** (чтение формата): построчно, без обрезки по 80 колонкам; распознаёт ключевое слово (регистр, опции, текст в скобках), комментарии, `*END`; раскрывает `*INCLUDE` (относительные пути от файла-родителя и `*INCLUDE_PATH`, защита от циклов); для каждой строки данных отдаёт поля по описанию карточки: free, если есть запятая, иначе fixed по ширинам, с пересчётом под long. **Ширины и смещения карточек — в одной таблице-описании** (по образцу `cards.json`), а не в коде разбора. Если после сверки (этап K0) ширины `*NODE` или структура `*PART` окажутся другими, правится одна строка таблицы. Каждое поле знает файл и номер строки для сообщений об ошибках.
2. **`KDeck`** (сырые данные, без физики): `nodes` (NID → x,y,z), `sph` (NID, PID, MASS, с развёрнутым `NEND`), `beams` (EID, PID, N1, N2), `parts` (PID, заголовок), счётчики пропущенных ключевых слов. Ссылки разрешаются после чтения всех файлов (порядок блоков произволен).
3. **Сборщики.**
   - 3a. Solid: `KDeck` + таблица деталей + `dim` + единицы → `ParticleSystem` (Р3, Р6).
   - 3b. Fiber: балки → граф → упорядоченные ломаные (Р1, Р9) → общая функция сборки модели нитей.

### 4.2 Общая сборка нитей для `.fib` и `.k`

Вычисления из `load_fiber_file` (`src/fiber_input.cpp:330-400`: бусины, массы `ρ·A·(l_prev+l_next)/2`, `l0`, `l_break`, `prev/next`, `object_id`, маска `CLAMP_BOX`) выносятся в отдельную функцию, например `fiber::build_model_from_polylines(ломаные, материалы, боксы, Model&)`. Её вызывают и `load_fiber_file`, и импорт `.k`. Тогда физика нити из `.k` гарантированно совпадает с `.fib`, а совпадение проверяется тестом (раздел 5). Разбор директивы `MATERIAL` также выносится, чтобы таблица деталей использовала его без копии.

### 4.3 Размещение в репозитории (по существующим соглашениям: заголовки в `include/`, исходники в `src/`)

| Что | Где |
|---|---|
| Чтение формата и `KDeck` | `include/k_input/k_reader.hpp`, `src/k_reader.cpp` |
| Таблица карточек | `include/k_input/k_cards.hpp` (constexpr-таблица) |
| Таблица деталей (sidecar) | `include/k_input/k_parts.hpp`, `src/k_parts.cpp` |
| Сборщики Solid/Fiber и точка входа `load_k_geometry(cfg, mode, Model&)` | `include/k_input/k_geometry.hpp`, `src/k_geometry.cpp` |
| Общая сборка нитей | `include/fiber/fiber_build.hpp`, `src/fiber_input.cpp` (рядом с `load_fiber_file`) |
| Подключение | `SPH_PIPELINE_SOURCES` в `CMakeLists.txt` |

Старый `parse_k_file` заменяется тонкой обёрткой над новым кодом (режим `solid`, без таблицы деталей: `itype = body = PID`, как сейчас), чтобы `test_body_from_k_file` (`tests/test_fiber_model.cpp:408`) остался зелёным, а затем удаляется вместе с объявлением в `include/input.hpp:21`.

### 4.4 Изменения в `main`/`input()`

- `main` создаёт `fiber::Model` и вызывает перегрузку `time_integration(cfg, model, …)` всегда; при пустых нитях она эквивалентна нынешней (есть тест). Расширение до `cfg.maxn` (`src/main.cpp`) применяется к `model.solid`.
- `input()` получает `Model&` и выбирает источник: `k_file` (новое), `particles.dat`, генераторы. Закомментированный блок `src/input.cpp:857-…` удаляется (его смысл переходит в таблицу деталей).
- `dx`: так как `delta_x` в интеграторе не используется, для `.k` передаётся медиана `(m/ρ)^(1/dim)` (только для печати/совместимости).
- Загрузка `.fib`: если задан `cfg.fiber_file`, после построения Solid (из любого источника) вызывается `fiber::load_fiber_file(cfg.fiber_file, model)`. Функция не трогает `model.solid` и заполняет `model.clamps.fiber_mask` из `CLAMP_BOX`, поэтому порядок «сначала Solid, потом нити» безопасен. Затем печатается сводка: число бусин, связей и нитей.

| Загрузка `.fib` через `main`/`input()` | `fiber_file` + Solid из `.k` и из генератора → `model.fiber` совпадает с прямым вызовом `load_fiber_file`; `fiber_file` вместе с `k_mode=solid_fiber` → ошибка; Solid не изменился | 3 |
| Регрессии | BC2, BC6, Guo 2019, `test_fiber_time_integration_equivalence` не меняются (генераторы не трогаются) | как есть |
| Производительность | `1.k` (250 000 частиц, ~500 000 строк) читается за разумное время; замер времени в выводе теста, без жёсткого порога | 3 |

## 6. Этапы

Каждый этап — отдельный PR в `fiber_new` (или в ветку от неё), зелёный CI, без изменения результатов существующих сцен.

Если мануал недоступен — выгрузить из LS-PrePost по одной модели в fixed, long и free и взять ширины оттуда; положить файлы в `tests/data/k/` как эталоны | таблица карточек подтверждена или исправлена; спецификация обновлена |

## 7. Риски

| Риск | Чем закрыт |
|---|---|
| Ширины `*NODE`/структура `*PART` не совпадут с мануалом (пункты [K]) | K0; ширины в одной таблице; эталонные файлы LS-PrePost в тестах. До K0 надёжно работает только free-format (им записан `1.k`) |
| Опции `*ELEMENT_BEAM_*`/`*PART_*` добавляют карточки, сбивая разбор | неизвестная опция `*ELEMENT_BEAM_*` → ошибка; у `*PART` берутся только первые две карточки, остальное до следующего `*` пропускается |
| Тихая потеря частиц (как сейчас при висячем NID) | Р8: любая висячая ссылка — ошибка с номером строки; итоговая сводка «прочитано N узлов, M частиц, K нитей» |
| Шаг бусин в `.k` не согласован с диаметром/SPH-шагом | в первой версии не проверяется; печатать min/max длину сегмента и `l/d` в сводке |
| Разные единицы в `.k` | Р5, явные масштабы; сводка с габаритом модели в метрах |
| Расхождение физики нитей `.fib` и `.k` | общая функция сборки (4.2) и тест побитовой эквивалентности |
| Большие файлы | один проход, `reserve`, без регулярных выражений; замер на `1.k` |

## 8. Вне объёма

`*PARAMETER`, `*INCLUDE_TRANSFORM`, `*DEFINE_TRANSFORMATION`, `*INITIAL_VELOCITY*`, `*SECTION_SPH` (h берётся из таблицы деталей), `*DEFINE_BOX_SPH`, оболочки `*ELEMENT_SHELL`/`*ELEMENT_TSHELL`, `*ELEMENT_DISCRETE_SPHERE`, осесимметричные `.k`-модели, экспорт обратно в `.k`.
