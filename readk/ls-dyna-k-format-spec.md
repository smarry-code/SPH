# Спецификация LS-DYNA keyword (`.k`) файлов — геометрия

Назначение: основа для конвертера `.k` → внутренний формат. Охват: все геометрические разделы `.k` — `*NODE`, `*ELEMENT_*` (SPH, SOLID, SHELL, TSHELL, BEAM, DISCRETE), `*PART`, `*SECTION_*`, `*SET_*`, `*INCLUDE` и общие правила формата (fixed / free / long, комментарии, продолжение строк). Спецификация составлена только по внешней документации.

Машиночитаемая версия карт: [`cards.json`](cards.json) (смещения/ширины/типы/умолчания).

## 1. Общие правила формата

### 1.1 Структура файла

- Файл — последовательность **блоков**. Блок начинается со строки-ключевого слова (`*` в колонке 1), далее идут строки данных (карточки) до следующего ключевого слова. **[V]**
- Порядок блоков произвольный; единственное исключение — необязательное `*END`, после которого чтение прекращается. Поэтому ссылки (элемент→узел, деталь→секция) разрешаются после чтения всего файла. **[V]**
- Ключевое слово начинается с колонки 1; после него возможны пробелы (хвостовые пробелы допустимы) и опции. **[V]**
- Регистр не важен (`*node` = `*NODE`). **[V]**
- Допускаются суффиксы-опции в имени (`*SET_NODE_LIST_TITLE`, `*ELEMENT_SHELL_THICKNESS`), поэтому сопоставлять нужно по самому длинному известному префиксу. Пробелы и текст в скобках в имени — подсказки для LS-PrePost, например `*ELEMENT_SOLID (ten nodes format)`; для решателя они не нужны, берётся первое слово. **[P]**
- Неизвестные блоки конвертер должен пропускать, не теряя синхронизации (до следующей строки с `*` в колонке 1).

### 1.2 Комментарии

- Строка с `$` в **колонке 1** — комментарий целиком, игнорируется. **[V]**
- Комментарий `$` в середине строки данных мануалом не гарантируется; для строковых полей (заголовки, имена файлов) `$` может быть частью значения, поэтому надёжно считать комментарием только `$` в колонке 1 **[K]**.
- Строки `$#   nid   x ...` — типичные «заголовки колонок» от LS-PrePost, это обычные комментарии.

### 1.3 Три формата ввода данных

**(а) Фиксированный (fixed/standard)** — по умолчанию. Колонки строки делятся на поля фиксированной ширины (чаще 10 символов × 8 полей = 80 колонок; для `*NODE`/`*ELEMENT_*` — 8/16 символов, см. ниже). Пустое поле = значение по умолчанию. Целые читаются как `I`, вещественные — как `F/E` (допустимы `1.0`, `1.0E+3`, `1.0D-3`, без десятичной точки — проверить **[K]**).

**(б) Свободный (free, comma-separated)** — значения разделены запятыми. Признак: в строке данных есть запятая. **[V]** (в мануале: «Input operates in free format using comma-separated values».)
   - Пустое поле между запятыми (`1,,3`) = значение по умолчанию.
   - Недостающие в конце поля = по умолчанию.
   - Ширина поля роли не играет (но в v960 было ограничение целого до 8 цифр, I8 **[V]**; в современных версиях ограничения по `*NODE` NID — см. long).
   - Пробелы вокруг значений допустимы.
   - Строковые поля (заголовки, имена файлов) в free-формате с запятыми ненадёжны — читайте их по строке целиком **[K]**.

**(в) Длинный (long)** — все поля расширяются минимум до 20 символов: ширина поля = `max(width_стандартная, 20)`, смещения пересчитываются как накопленная сумма. **[P]** Включается:
   - глобально строкой `*KEYWORD LONG=Y` (`LONG=S` — standard/по умолчанию, `LONG=K` — «keyword-standard», т.е. стандартная ширина). **[P]**
   - для отдельного блока — суффиксом `+` у ключевого слова (`*NODE+`; long) или `-` (`*NODE-`; принудительно standard). **[P]**
   - Пример `*NODE` в long-формате: NID, X, Y, Z, TC, RC — по 20 символов (итого 120 колонок), `*ELEMENT_SPH`: NID 20, PID 20, MASS 20, NEND 20 (стандартные ширины 8/8/16/10 → max(w,20)).

> Замечание: описание long-формата из **[P]** — реализация pydyna, соответствует документации LS-DYNA (`*KEYWORD LONG=Y`), но подтвердить побайтово по мануалу — **[K]**.

### 1.4 Продолжение строк, параметры

- Длинные строки значений (имя файла в `*INCLUDE*`, `*INCLUDE_PATH`): если длина больше 80, строка завершается пробелом и `+`, продолжение — на следующей строке. **[M]** (help к `INCLUDE_PATH`)
- Карточки не «продолжаются» произвольно: число строк в блоке определяется картой ключевого слова (см. разделы 3–5). Для списков (`*SET_*_LIST`) строки повторяются до следующего ключевого слова.
- `*TITLE`: следующая строка — заголовок модели (A80). `*KEYWORD` — необязательна; после неё могут идти «memory»-параметры, игнорируются. **[K][optislang]**
- Максимальная длина строки не ограничена 80 символами при чтении (Optislang читает до перевода строки). Нельзя обрезать строки жёстко по 80 колонкам. Для long-формата длина > 80 штатна.

- `*PARAMETER` / ссылки `&имя` в числовых полях **[K]**: конвертер без поддержки параметров должен выдавать ошибку, а не считать значение нулём.

### 1.5 Единицы

LS-DYNA единицы не хранит — система единиц (мм/т/с, м/кг/с и т. д.) задаётся пользователем и в файле не указана. Конвертер должен принимать систему единиц параметром (или масштаб длины/массы), а `*INCLUDE_TRANSFORM` (FCTLEN/FCTMAS/FCTTIM) учитывать явно. **[K]**

## 3. Узлы, SPH-элементы, детали, секции

Во всех таблицах: **Смещ.** — 0-based смещение в строке (standard-формат), **Шир.** — ширина, `I` — integer, `R` — real, `A` — string.

### 3.1 `*NODE`

Одна карточка на узел, повторяется до следующего ключевого слова. Опций в названии нет (`*NODE` + `*NODE_*` другие ключевые слова).

| Поле | Смещ. | Шир. | Тип | По умолч. | Описание |
|---|---|---|---|---|---|
| NID | 0 | 8 | I | — (обяз.) | Идентификатор узла, уникален |
| X | 8 | 16 | R | 0.0 | Координата x |
| Y | 24 | 16 | R | 0.0 | Координата y |
| Z | 40 | 16 | R | 0.0 | Координата z |
| TC | 56 | 8 | I | 0 | Translational constraint (0–7) — для SPH не нужен |
| RC | 64 | 8 | I | 0 | Rotational constraint (0–7) — для SPH не нужен |


Источник: NID/X/Y/Z **[A]**; TC/RC и ширины 8/16/16/16/8/8 **[K]** (подтверждается схожим `*NODE_RIGID_SURFACE`: NID 8, X/Y/Z по 16 **[M]**). Free-формат: `NID,X,Y,Z[,TC,RC]`. Для SPH узел и частица имеют общий ID; координаты частиц берутся из `*NODE`.

### 3.2 `*ELEMENT_SPH`

Одна карточка на частицу. **[M]**

| Поле | Смещ. | Шир. | Тип | По умолч. | Описание |
|---|---|---|---|---|---|
| NID | 0 | 8 | I | — | ID узла; «Node ID and Element ID are the same for the SPH option» (ID элемента = ID узла) |
| PID | 8 | 8 | I | — | ID детали (`*PART`) |
| MASS | 16 | 16 | R | 0.0 | `> 0` — масса частицы; `< 0` — объём (берётся `abs`), масса = `abs(MASS) × ρ`, где ρ из материала детали `PID` |
| NEND | 32 | 10 | I | 0 | Необязательно. `> 0`: сгенерировать частицы с узлами от NID до NEND с теми же PID и MASS (диапазон) |

Замечания для конвертера:
- Free-формат: `NID,PID,MASS[,NEND]`. Если `MASS < 0`, нужна плотность из материала детали (`*PART` → MID → `*MAT_*`), иначе масса не определена.
- `NEND`: разворачивать как `for n in NID..NEND` (включительно) **[K: включительность проверить]**; узлы с такими ID должны существовать в `*NODE`.
- Altair упоминает опцию `*ELEMENT_SPH_VOLUME` (значение трактуется как объём) **[A]**; в `kwd.json` отдельной карты нет. Поддержать суффикс `_VOLUME`: поле = объём, независимо от знака.

### 3.3 `*PART`

Формат **[K]** (в `kwd.json` нет; проверить по мануалу):

| Карточка | Поле | Смещ. | Шир. | Тип | По умолч. | Описание |
|---|---|---|---|---|---|---|
| 1 | HEADING | 0 | 70 (до 80) | A | — | Название детали (одна строка, может быть пустой) |
| 2 | PID | 0 | 10 | I | — | ID детали |
| 2 | SECID | 10 | 10 | I | 0 | ID секции (`*SECTION_*`; для SPH — `*SECTION_SPH`) |
| 2 | MID | 20 | 10 | I | 0 | ID материала (`*MAT_*`) |
| 2 | EOSID | 30 | 10 | I | 0 | ID уравнения состояния (`*EOS_*`) |
| 2 | HGID | 40 | 10 | I | 0 | ID hourglass-контроля (для SPH не нужен) |
| 2 | GRAV | 50 | 10 | I | 0 | Гравитационная инициализация (0/1) |
| 2 | ADPOPT | 60 | 10 | I | 0 | Адаптивность |
| 2 | TMID | 70 | 10 | I | 0 | ID терморегулятора |

Особенности:
- Карточка 1 — **всегда** строка заголовка (текст, а не числа): её нельзя разбирать как данные. Если во второй карточке указан только PID, остальные поля принимают значения по умолчанию (0).
- Опции (`*PART_CONTACT`, `*PART_INERTIA`, `*PART_PRINT`, `*PART_ATTACHMENT_NODES`, `*PART_AVERAGED`, …) добавляют карточки между карточками 2 и следующим блоком, но первые две карточки те же. Для SPH достаточно взять PID/SECID/MID и пропустить остальные строки до `*`.
- Различать `*PART` и `*PART_xxx`: сопоставление по точному имени/опции, а не префиксу, чтобы не спутать с `*PARTICLE_BLAST` и т.п.

### 3.4 `*SECTION_SPH`

Одна карточка. **[M]** (все поля `I`/`R` шириной 10)

| Поле | Смещ. | Шир. | Тип | По умолч. | Описание |
|---|---|---|---|---|---|
| SECID | 0 | 10 | I | — | ID секции, на неё ссылается `*PART.SECID`, уникален |
| CSLH | 10 | 10 | R | 1.2 | Постоянная для сглаживающей длины (h = CSLH · ∂(шаг частиц)); обычно 1.05–1.3; <1 не рекомендуется |
| HMIN | 20 | 10 | R | 0.2 | Множитель минимальной сглаживающей длины |
| HMAX | 30 | 10 | R | 2.0 | Множитель максимальной сглаживающей длины |
| SPHINI | 40 | 10 | R | 0.0 | Необязательная начальная сглаживающая длина (переопределяет расчёт; тогда CSLH не используется) |
| DEATH | 50 | 10 | R | 1.0E+20 | Время отключения SPH-аппроксимации |
| START | 60 | 10 | R | 0.0 | Время включения SPH-аппроксимации |
| SPHKERN | 70 | 10 | I | 0 | Ядро: 0 — кубический сплайн (по умолч.), 1 — quintic spline (бо́льший носитель), др. значения см. мануал |

Расширения: `*SECTION_SPH_ELLIPSE` — вторая карточка `HXCSLH, HYCSLH, HZCSLH, HXINI, HYINI, HZINI` (по 10); `*SECTION_SPH_INTERACTION`, `*SECTION_SPH_USER` — см. `cards.json`/kwd.json. **[M]**


## 4. Наборы

Наборы нужны, если геометрия/граничные условия ссылаются на группы узлов или деталей.

### 4.1 `*SET_NODE_LIST` (и `_TITLE`, `_COLLECT`, `_GENERATE`) **[M]**

| Карточка | Поля (все по 10) |
|---|---|
| 1 | SID(I), DA1–DA4 (R, 0.0), SOLVER (A, `MECH`), ITS (I, 1), unused |
| 2, 3, … (повторяются) | NID1…NID8 (I) — до 8 ID в строке, пустые/0 игнорируются |

### 4.2 `*SET_PART_LIST` **[M]**

Карточка 1: `SID, DA1–DA4, SOLVER`; далее строки `PID1…PID8` (по 10). `_GENERATE` — диапазоны, как выше.

## 5. `*INCLUDE`

| Ключевое слово | Содержимое | Источник |
|---|---|---|
| `*INCLUDE` | строка с именем файла (A80; дольше 80 — продолжение через « +» на следующей строке) | **[A][M][K]** |
| `*INCLUDE_PATH` | `PATH` — каталог(и) поиска include-файлов (до 512 символов, также с «+»-продолжением) | **[M]** |
| `*INCLUDE_PATH_RELATIVE` | то же, но путь относительно каталога главного файла | **[M]** (имя ключевого слова) |
| `*INCLUDE_TRANSFORM` | FILENAME (A80); карточка 2: `IDNOFF, IDEOFF, IDPOFF, IDMOFF, IDSOFF, IDFOFF, IDDOFF` (10×7, смещения ID); карточка 3: `IDROFF, —, PREFIX(A10), SUFFIX(A10)`; карточка 4: `FCTMAS, FCTTIM, FCTLEN (R, 1.0), FCTTEM, INCOUT1, FCTCHG`; карточка 5: `TRANID` | **[M][A]** |

Правила для конвертера:
- Относительные пути — относительно каталога файла с `*INCLUDE` (или каталогов из `*INCLUDE_PATH`) **[K]**; защититься от циклов.
- В `*INCLUDE_TRANSFORM` ID узлов/деталей получают смещения (`IDNOFF` → NID, `IDPOFF` → PID), а координаты масштабируются `FCTLEN` (и при `TRANID ≠ 0` — преобразованием из `*DEFINE_TRANSFORMATION`). Масса масштабируется `FCTMAS`.
- Если include-файл не найден — ошибка (не молчаливый пропуск), иначе потеряются частицы.
- Содержимое include вставляется «как есть» в точку включения; порядок по-прежнему не важен.

## 7. Прочее, что может встретиться рядом с геометрией

- `*DEFINE_BOX_SPH` (`BOXID, XMN, XMX, YMN, YMX, ZMN, ZMX, VID` + `LCID, VD, NID, IREACT, IBUFF, ISHOW, PID`; все по 10) — область активации SPH-частиц. **[M]**
- `*CONTROL_SPH`, `*BOUNDARY_SPH_*`, `*MAT_*`, `*EOS_*`, `*DEFINE_CURVE`, `*INITIAL_VELOCITY*` — физика/ГУ, вне геометрии; должны пропускаться или конвертироваться отдельно.
- `*PARAMETER` — см. 1.4.

## 8. Рекомендации по реализации конвертера

1. **Токенизация.** Читать файл построчно, без жёсткой обрезки по 80 колонкам. Строка с `*` в колонке 1 — начало блока; `$` в колонке 1 — комментарий.
2. **Определение формата строки.** Free, если есть запятая; иначе fixed по ширинам карточки; если активен `*KEYWORD LONG=Y` или блок с суффиксом `+` — ширины `max(w, 20)`.
3. **Двухпроходная сборка.** Сначала собрать узлы, элементы, детали, секции, наборы; затем разрешить ссылки (порядок блоков в файле произволен).
4. **Развёртка** `NEND` в `*ELEMENT_SPH`, обработка `MASS<0` (объём → нужна плотность), `*INCLUDE` (с циклами и относительными путями).
5. **Валидация.** Дубликаты ID, ссылки на несуществующие узлы/детали/секции, `&параметр` без `*PARAMETER`, отсутствующий include — диагностическое сообщение с номером строки (не молчаливое «0»).
6. **Единицы** — параметр конвертера.
