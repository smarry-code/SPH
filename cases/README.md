# Опытные кейсы

Реестр физических опытов, с которыми сверяется код, и всё, что нужно для их постановки: исходные данные
опыта, код сцены, числа опыта, параметры решателя, эталоны. Расчёты нынешнего кода — в
[`experiments/`](../experiments/README.md), рабочие ТЗ и постановки — в [`notes/`](../notes/README.md).

## Устройство

```
cases/
├── README.md                ← этот файл: правила и реестр
├── common/                  ← общая библиотека постановок (не зависит от кейса)
│   ├── e2e_harness.hpp      ← обвязка: изоляция каталога, глушение вывода, check/note, ru_num
│   ├── energy.hpp           ← импульс и энергии Solid и Fiber
│   ├── lattice.hpp          ← правило числа ячеек решётки (cell_count)
│   └── e2e_curve.hpp, e2e_shape.hpp, e2e_staircase.hpp, e2e_frames.hpp, e2e_plot.hpp
│                            ← кривая монитора, сверка формы и лесенки, чтение кадров, SVG
└── <кейс>/
    ├── README.md            ← карточка (шаблон ниже)
    ├── source/              ← архив опыта: исходные данные как получены, не правятся
    ├── regression/          ← замороженная постановка для ctest: код сцены, числа опыта,
    │                          initial_conditions.txt, reference.txt, snapshots/ (эталоны регрессии)
    └── experiment/          ← живая постановка для расчётов: копия regression/ + драйверы
```

Каталоги `source/`, `regression/`, `experiment/` есть не у всех кейсов: только там, где они нужны.

## Роли постановок

Решение и его причины — [ADR-011](../docs/04-explanation/decisions/adr-011-case-setups.md).

1. **ctest берёт постановку только из `regression/`, расчёты и их утилиты — только из `experiment/`.**
   Копии называются одинаково (те же файлы и пространства имён); нужную копию цели выбирает CMake:
   `sph_case(<цель> <кейс> regression|experiment)`. В одной цели двух копий кейса не бывает.
2. **`regression/` заморожена.** Меняется только (а) при подстройке под изменённый API ядра без изменения
   поведения — регрессия (`ctest -L regression`) обязана пройти побитово; (б) по решению владельца с
   перегенерацией эталонов (`cmake --build build --target regression_golden`) и причиной в коммите.
3. **`experiment/` меняется свободно** под расчёты. Расхождение с регрессией:
   `diff -r cases/<кейс>/regression cases/<кейс>/experiment`. Перенос изменений эксперимента в регрессию —
   отдельный коммит по п. 2.
4. **Проверки самих экспериментальных утилит** (`checkpoint_cli_test`, `stitch_kt_cli_test`,
   `mosaic_kt_cli_test`, `fabric_checks_smoke_*`) собираются из `experiment/`: они проверяют утилиту, а не
   физику постановки.
5. **`common/`** — только код, не зависящий от кейса; его правка касается обеих сторон и проверяется полным
   `ctest`.
6. **Копия `experiment/` заводится, когда нужен расчёт.** Сейчас она есть только у `guo2019`; у `bc2`, `bc6`
   — только `regression/`.

## Правила хранения

- Один кейс — один каталог `cases/<кейс>/`; имя кейса латиницей в нижнем регистре и совпадает со
  словом `<кейс>` в именах каталогов `experiments/ГГГГ-ММ-ДД-<кейс>-<слаг>/` (`bc2`, `bc6`, `guo2019`).
- Файлы `source/` не правятся: это архив опыта. Рабочие копии в формате постановки (например,
  `regression/reference.txt`) делаются скриптом из `tools/`, если перенос нетривиален.
- Результаты старого кода не хранятся: они остаются в истории git.
- Тестовые сцены без физического опыта (закрепление, чекпоинт, JC) живут в `tests/`, не здесь.
- Текст — UTF-8.

### Шаблон карточки

1. **Опыт** — что происходит, материалы.
2. **Источник** — откуда данные, единицы; «не установлен», если неизвестно.
3. **Статус** — `в коде и тестах` / `только исходные данные` / `нет данных`.
4. **Файлы** — что лежит в `source/`.
5. **Код и тесты** — что лежит в `regression/` и `experiment/`, какие цели `ctest` и утилиты их берут.
6. **Эксперименты** — каталоги `experiments/`.
7. **Постановка** — заметки `notes/`.
