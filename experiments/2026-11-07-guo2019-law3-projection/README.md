### 1.3. Правки по ревью (`6edcdc5`)

Ревью кода против ТЗ (2026-11-09) нашло недочёты диагностики; алгоритм проекции не менялся (проверено
побайтно, §2.4):

1. **`proj_resid_rel`** делил на W̃_c (с множителями c_k), а ТЗ A4 требует долю h·N_c/m_red, то есть
   ṗ⁺/(W_c·P_c) с W_c = Σw²/m без c_k. Исправлено: метрика стала строже (до max c_k раз). Добавлена
   **`proj_resid_load`** = Σ_c(ṗ_c⁺/W̃_c) / Σ_c P_c — недостающий импульс в долях полной нагрузки, учитывает
   и слоты с P = 0 (столбец в конце `monitor.csv`, ключ `proj_resid_load_max` в `shot.txt`).
2. Предупреждение о γ ≠ 1 печаталось дважды за выстрел; теперь один раз, с обоими видами контакта.
3. Ключи режима в `shot.txt` брались из CLI, а не из итоговой конфигурации; теперь из `sc.cfg`.
4. Предупреждение при `warm = 0`.
5. Т4 на случайной сцене стал проверкой (было только печать), Т6 сравнивает ряды δ(t), v(t), а не только
   конечные значения.
6. Шапка `include/energy_log.hpp`: работа стадии проекции входит в `D_contact_fiber`.

Серия C считалась до правок, поэтому в её `monitor.csv` столбец `proj_resid_rel` — по старому
определению, а `proj_resid_load` нет.

разделением массы снимают его не полностью, когда у бусины несколько контактов (c_k > 1). То же видно в
модульном тесте: случайная сцена **с закреплёнными** бусинами даёт W_stage = +3·10⁻³ Дж за шаг (Т7, печать;
проверка Т4 стоит только на сцене без закреплений). Величина в серии ничтожна (в 10⁴ раз меньше допуска
на скачок residual), D_cf ни разу не убыл; по ТЗ §1.9 это описано, а не исправлено. Гипотезу
`LIT_TUNNELING_LAW3.md` §2.3 (перекомпенсация при нескольких контактах на бусину) проверить по документу
нельзя: его нет в репозитории; механизм выше с ней согласуется.

## 8. Отклонения от ТЗ и открытые вопросы

1. **Ветка** `contact3_fix`, а не `fiber_contact_projection`; база — `b2cc5a5` из `fiber_divergence_diag`
   (`6f1b63f` — предок). Ветка отправлена на GitHub по просьбе владельца (2026-11-08).
2. **`LIT_TUNNELING_LAW3.md`** в репозитории нет; ссылки на него (§5 п. 4) не проверены.
3. **`contact_stats`** в режиме проекции не поддержан: явная ошибка при включении.
4. **Сквозные проходы** в прошлых отчётах = max `n_tunnel`; по кадрам надёжного счётчика нет (§4).
5. **predictor = 1 при законах 0/4** — ошибка разбора, а не предупреждение.
6. **Чекпоинт v3.** Сервер 8t перезагрузился посреди первой серии; рестарт с чекпоинта терял накопленные
   максимумы монитора. Добавлено сохранение состояния монитора (`8b5cb9a`), серия посчитана заново с нуля.
7. **Метрика остатка** в серии — старого определения (§1.3); новая `proj_resid_load` в серии не снята.
8. **Тёплый старт на расходящихся парах** даёт малую положительную работу (§5). Возможное исправление —
   отбрасывать P⁽⁰⁾ у пар с ṗ < 0 до итераций или ограничивать его — меняет алгоритм и требует согласования.
9. **Контакт только при δ > 0.** Стадия гасит скорость сближения, но набранное проникание не снимает
   (выталкивания нет по запрету): поэтому δ_ff/d держится на 0,10–0,17, а не падает к нулю, и у C4 медленно
   растёт. Предсказанный зазор (§5.4 метода) не входил в задачу.
10. **Т2** сравнивает с законом 3 с допуском 10⁻⁹ v0, а не «до округления» (фактическое отличие 7·10⁻¹⁵ м/с).
