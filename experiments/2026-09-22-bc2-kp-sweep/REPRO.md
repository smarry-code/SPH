# Воспроизведение: развёртка BC2 по Kp

Карточка прогона. Всё, что нужно, чтобы получить те же двенадцать кривых и ту же
фигуру, — включая временную заплату, которая в репозиторий намеренно не попала.

---

## 3. Отличия рабочего дерева от этого коммита на момент прогона

**Всё лежит в [`repro-diff.zip`](repro-diff.zip)** (2,7 КБ) — патчи в формате
`git apply`, а не пересказ. Внутри:

| Файл в архиве | Что делает | Судьба |
|---|---|---|
| `MANIFEST.md` | состав, порядок наложения, команды снятия | — |
| `HEAD.txt` | коммит, автор, дата, заголовок | — |
| `01-bc2-config-kp-uncomment.patch` | раскомментирует `contact_penalty_scale` в `tests/data/bc2_initial_conditions.txt` | постоянное изменение, по указанию владельца (ключ был отключён коммитом `cfbef76`) |
| `02-kp-env-override.patch` | временная заплата в `tests/test_e2e_bc2.cpp`: `Kp` читается из переменной окружения `SPH_BC2_KP` | **в репозиторий не попадала**, откачена сразу после развёртки |

```bash
unzip repro-diff.zip -d repro          # или: python -m zipfile -e repro-diff.zip repro/
git apply --check repro/02-kp-env-override.patch   # проверить, ничего не меняя
git apply repro/01-bc2-config-kp-uncomment.patch
git apply repro/02-kp-env-override.patch
```

Два замечания, без которых числа не сойдутся. Первое: значение 2,5 из
конфигурации на прогонах развёртки **не действует** — его перекрывает
переменная окружения из заплаты 02; патч 01 нужен лишь для того, чтобы ключ
вообще разбирался парсером. Второе: без заплаты 02 двенадцать точек развёртки
потребовали бы двенадцати пересборок.

Оба патча проверены на текущем дереве: `git apply --check` проходит для 02,
`git apply --check --reverse` — для 01 (он уже наложен). Сборка с наложенной
заплатой 02 компилируется и линкуется; `std::getenv` даёт одно предупреждение
`_CRT_INSECURE_DEPRECATE` из заголовков MSVC, на работу не влияющее.

## 4. Команды

```bash
# 1. сборка с включёнными долгими e2e-тестами
cmake -S . -B build -DSPH_E2E_SLOW_TESTS=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build -j10

# 2. двенадцать прогонов, по три параллельно
cd experiments/2026-09-22-bc2-kp-sweep
printf '%s\n' "1 0.5" "1 1" "1 2" "1 4" "1 7" "1 10" \
              "2 0.5" "2 1" "2 2" "2 4" "2 7" "2 10" > todo.txt
xargs -P 3 -a todo.txt -n 2 bash scripts/one.sh

# 3. проверка кривых: монотонность по времени и доход до t_total
python scripts/chk.py

# 4. сборка фигуры из data/ — пишет bc2_kp_sweep.svg рядом
python scripts/figkp.py
```

`scripts/one.sh` запускает один прогон:
`SPH_BC2_KP=<Kp> build/test_e2e_bc2.exe --full --contact-type=<тип>
--time-limit=21600 --emit-curve=data/curve_t<тип>_kp<Kp>.txt`.
Путь к бинарю переопределяется переменной `SPH_E2E_EXE`.

**Осторожно с параллелизмом.** Ограничивать число одновременных прогонов через
`while [ "$(jobs -rp | wc -l)" -ge 3 ]` **нельзя**: `jobs` внутри подстановки
команд выполняется в подоболочке и всегда видит пустой список, отчего запускаются
все двенадцать сразу и по два писателя на один файл кривой. В первом заходе это
уже произошло; отсюда `xargs -P 3`, который считает процессы честно.
