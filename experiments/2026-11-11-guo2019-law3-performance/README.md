# Производительность контакта закона 3 с проекцией: один поток, 8 потоков, профиль (2026-11-11)

- **Кейс:** guo2019, 1T base, V0 = 79 м/с, μ = 0,27, dt-scale 0,5, ткань как в серии C1, `--t-max=4e-5` (4372 шага).
- **Ветка:** `contact3_fix`. NEW — коммит `1658756` (правки по ревью Codex). BASE — `6edcdc5` (до правок).
- **Машина:** `claude-compute-8t`, 2 × 4 ядра Xeon Cascadelake, без SMT, 1 узел NUMA, L3 2 × 32 МиБ, g++ 15.2, `-O2`.
- **Прогонов:** 16 — 10 однопоточных (в том числе 2 профиля), 6 на 2/4/8 потоках, 2 профиля на 8 потоках; см. `results/driver.log`.
- **Статус:** выполнено. Код расчёта не менялся: только замеры и предложения.

### 4. Один поток: на что уходит шаг

Верхняя функция проекта по `results/{H,P}.prof1.threads.txt`, удар (60–98 % записи), доли шага:

| Категория | H | P |
|---|---|---|
| поиск соседей нить–нить (`for_each_neighbor_cell` + `dist2`, `cell_range`, `linear_index`) | ~44 % | ~36 % |
| поиск нить–Solid (`collect_cross_one`) | 21,4 % | 17,2 % |
| поиск SPH шара | 4,1 % | 3,3 % |
| геометрия контакта нитей (`fiber_segment_closest_params`, `compute_fiber_contact_geometry`, ядро) | 12,8 % | 8,6 % |
| стадия проекции и проходы по слотам (`run_normal_projection`, остаток после трения, перенос в трение, тёплый старт, счётчики, `rebuild`) | — | **~21 %** |
| SPH шара (силы, свёртка) | 6,6 % | 5,3 % |

**Поиск соседей — 60–70 % однопоточного шага при любом законе.** Причины в коде:

1. **125 ячеек вместо 27.** Индекс строится с ячейкой, *равной* радиусу поиска: `fiber_contact.hpp:283`, `fiber_solid_contact.hpp:366`. Тогда `neighbor_reach = floor(r/h) + 1 = 2` (`spatial_index.hpp:279`), и для каждой бусины обходится 5³ = 125 ячеек. Шар радиуса r задевает в среднем около трети из них.
2. **Перебор ячеек с делением и остатком.** `for_each_neighbor_cell` (`spatial_index.hpp:289`) для каждой из 125 комбинаций считает смещение через `%` и `/`. Делается это заново *для каждой частицы* ячейки, хотя набор соседних ячеек у всех частиц ячейки общий.
3. **Поиск нить–Solid по всем 43 248 бусинам.** Сетка строится по 3 544 частицам шара. Бусины вне её габарита прижимаются к крайним ячейкам (`cell_of_point`, `std::clamp`) и всё равно перебирают по 125 ячеек. Между тем шар (D = 12 мм) накрывает ~1–2 % ткани (120 × 120 мм).

**Проекция идёт по всем примитивам, а не по активным слотам.** Нормальные слоты заводятся по одному на примитив (`fiber_contact.hpp:776`): это все пары бусин разных нитей в радиусе поиска. Активны из них только слоты с δ > 0, не больше 1218. На каждом шаге по всему массиву (слот 152 байта) проходят:
- сброс в ядре;
- `NormalWarmStart::apply`;
- `compute_normal_counts`;
- подсчёт активных;
- в ударе — 9–10 проходов `emit_pass` и 4 свёртки по слотам;
- `rebuild` (последовательно);
- `fill_friction_slots_from_normal_ff` (пишет весь массив слотов трения);
- остаток после трения;
- `emit_counts` стадии трения.

Кроме того, каждый `emit_pass` обновляет `dvel_fiber` по всем 43 248 бусинам и заново обнуляет `scratch` свёртки.

**Подробнее к пунктам 1–3.**

- **Пункт 1.** Перечень соседних ячеек строить один раз на ячейку, а не на частицу, причём без деления и остатка, и сразу выкидывать пустые ячейки. Затем для каждой частицы пропускать ячейку, если расстояние от точки до её габарита больше r·(1 + 10⁻¹²).
  - Выпадают только ячейки, где пар заведомо нет, поэтому порядок пар (частица → ячейка → позиция) сохраняется.
  - Из 125 ячеек остаётся около трети.
- **Пункт 2.** Бусину, удалённую от габарита сетки шара больше чем на r, пропускать до перебора ячеек. До контакта это почти все бусины, в ударе — ~98 %. Внутри — то же отсечение ячеек, что в пункте 1.
- **Пункт 3.** Сжать индексы активных слотов (δ > 0) в список по возрастанию k: один параллельный подсчёт и префиксная сумма. Дальше все проходы идут по списку:
  - тёплый старт, счётчики, итерации, свёртки;
  - `rebuild` (станет дешёвым и параллельным);
  - перенос в трение, остаток после трения, `emit_counts` трения.

  Сброс слотов в ядре — только у тех, что были активны на прошлом шаге.

  Побитовость: порядок вкладов по бусине сохраняется, k возрастает. Суммы по слотам (A0, W, сводки) нужно сворачивать по прежним 64 отрезкам *исходного* индекса k: x + 0,0 = x, поэтому пропуск неактивных слагаемых сумму не меняет.

- `alignas(64)` у буферов вкладов: ложного разделения в профиле не видно, дисбаланс ≈ 0.
- Смена числа отрезков `kDetSegments`: ожидание на барьерах — 0,1 %.

## Что осталось неясным

- **Число примитивов не измерено.** Монитор пишет только активные слоты. Оценки пунктов 3 и 8 опираются на долю времени в профиле, а не на счётчик.
- **Цена правок до контакта.** Из +8–10 % (Pb один прогон) профиль объясняет ~3 %. Нужен повтор Pb и профиль Pb.
- **Однопоточный профиль покрывает только начало удара** (до 25 мкс, ~1000 шагов удара). Поздний удар с бо́льшим числом слотов не профилировался; доля проекции там, вероятно, выше.
- **Оценки пунктов 1–2 сверху.** Сколько ячеек отсекается на самом деле, зависит от плотности бусин по ячейкам. Оценка «треть от 125» — геометрическая.
- **Потери внутри параллельных регионов.** Если бы потери на 8 потоках шли только от последовательного кода (26 % стенного времени), ускорение P было бы ≈ 6,2 = 0,26 + 0,74·8. Измерено 4,8: параллельные регионы на 8 потоках идут в ~1,3 раза медленнее на поток, чем в одном. Дисбаланса нет, значит, это полоса памяти или частота ядер под нагрузкой. Счётчики аппаратных событий (`perf stat`: промахи LLC, циклы) не снимались. Оценка f_s по Амдалу из времени (0,077–0,094) включает обе части потерь.
