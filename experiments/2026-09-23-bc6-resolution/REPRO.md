## 4. Команды

```bash
# 1. сборка
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target test_e2e_bc6

# 2. лестница по Δx: сначала 0,40 мм как проверка конвейера, затем
#    остальные по два одновременно, крупные первыми
cd experiments/2026-09-23-bc6-resolution
OMP_NUM_THREADS=6 bash scripts/one.sh 4.0e-4 dx040
OMP_NUM_THREADS=6 xargs -P 2 -a data/todo.txt -n 2 bash scripts/one.sh

# 3. повтор 0,20 мм (проверка детерминизма)
OMP_NUM_THREADS=6 bash scripts/one.sh 2.0e-4 dx020_rep

# 4. повтор 0,20 мм с сохранением кадров — для разбора повреждения
OMP_NUM_THREADS=6 build/test_e2e_bc6.exe --full --contact-type=0 --delta-x=2.0e-4 \
    --time-limit=21600 --keep-workdir --emit-curve=data/curve_dx020_keep.txt \
    > data/run_dx020_keep.log 2>&1
python scripts/damage.py "<каталог из строки «каталог прогона сохранён» в логе>" \
    > data/damage_dx020.txt

# 5. четвёртая реплика — кривая цели bc6_plot (потоки по умолчанию)
cmake --build build --target bc6_plot
cp build/bc6_curves/bc6_curve_0.txt data/curve_dx020_bc6plot.txt

# 6. число частиц по телам для всех Δx — функцией теста bc6::plan_geometry,
#    без прогона (оборванный прогон 0,10 мм отчёт о геометрии не печатает)
clang++ -std=c++20 -O1 -DSPH_DIM=2 -Iinclude -Itests experiments/2026-09-23-bc6-resolution/scripts/particles.cpp -o particles.exe
./particles.exe > experiments/2026-09-23-bc6-resolution/data/particles.txt

# 7. метрики, data/summary.txt и фигура bc6_resolution.svg
python scripts/fig.py
```

`scripts/one.sh <Δx, м> <тег>` запускает
`build/test_e2e_bc6.exe --full --contact-type=0 --delta-x=<Δx> --time-limit=21600
--emit-curve=data/curve_<тег>.txt`, пишет лог в `data/run_<тег>.log` и дописывает
в его конец стенное время и код возврата. Путь к бинарю переопределяется
переменной `SPH_E2E_EXE`.

При `--delta-x` тест пропускает контрольные числа §2.4 и физические проверки §6
(они привязаны к штатному Δx) и возвращает 0, если конвейер дошёл до конца.
Метрики по кривым считает `scripts/fig.py`, а не тест.

## 6. Проверка повтора

Повтор считается успешным, если `python scripts/fig.py` печатает для лестницы
(столбцы: Δx, шагов, признак обрыва, пик, плато 1, длительность плато 1,
фронт 10–90, спуск 10–90; число частиц и слоёв — из `data/particles.txt`):

```

  0.40    11303    6/27    807    0   209.6   186.6 0.512     240.5          —
  0.28    22772    8/38   1154    0   204.0   179.8 0.622     199.3          —
  0.20    44638   11/53   1615    0   198.2   183.4 0.668     185.5      200.9
  0.14    90577   15/76   2310    0   192.0   185.7 0.683     163.3      192.6
  0.10   177645  21/106   3232    1   193.5   187.3 0.799     141.7      147.0
```

Число частиц детерминировано и обязано совпасть точно; `data/particles.txt`
проверяется повтором шага 6 без всякого расчёта.

Эти величины берутся из части кривой до ≈ 1,7 мкс, где четыре реплики при
0,20 мм совпадают с точностью печати, поэтому они должны повторяться до десятых.
Прогон 0,10 мм может и не оборваться, а шагов может оказаться на единицы больше
или меньше.

**Всё, что позже ≈ 1,7 мкс, повторяться не обязано**: плато 2, отношение
ступеней, провал 2, RMS от эталона. Расчёт недетерминирован, и реплики одной
сетки расходятся там до 34 м/с (см. README, «Воспроизводимость»). Расхождение в
этих столбцах при повторе — ожидаемое поведение, а не признак ошибки.

Шаг 7 проверяется и **без** пересчёта: `data/` содержит все восемь кривых, и
таблица с фигурой пересобираются из них за секунду.

## 7. Подготовленный прогон Δx = 0,05 мм (не считался)

Шестая ступень лестницы, 706 406 частиц (`data/particles.txt`). На машине этой
серии не запускалась: памяти впритык (см. README, сноска ² к таблице числа
частиц). Прогон, начатый 2026-09-23 в 16:56, остановлен через ≈ 30 с по
решению владельца; его лог и временный каталог удалены, в `data/` от него
ничего нет.

**Требования (оценка):** ≥ 8 ГБ свободной памяти, порядка 10 ч на 6 потоках,
около 6500 шагов. Бюджет сторожа — сутки.

```bash
# на машине для запуска: тот же коммит, сборка Release
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target test_e2e_bc6
bash experiments/2026-09-23-bc6-resolution/scripts/run_dx005.sh
#   OMP_NUM_THREADS — по умолчанию все ядра; SPH_TIME_LIMIT — по умолчанию 86400 с
python experiments/2026-09-23-bc6-resolution/scripts/fig.py
```

`run_dx005.sh` вызывает `one.sh 0.5e-4 dx005`; результат ложится в
`data/curve_dx005.txt` и `data/run_dx005.log`, в конец лога дописываются
стенное время и код возврата. `fig.py` подхватывает кривую сам: ступень уже
внесена в список, а пока кривой нет, она отмечается в `data/summary.txt`
строкой «не посчитаны». На Linux `one.sh` берёт `build/test_e2e_bc6` без `.exe`.

**Что проверить после прогона.** Строка «всего частиц 706406» в логе, если
прогон дошёл до конца (при обрыве отчёт о геометрии не печатается), и
совпадение с `data/particles.txt`. По правилам каталога дата каталога — день
получения результата: если прогон закончится позже 2026-09-23, это надо
отразить в README (шапка и строка указателя).
