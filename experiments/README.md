# Журнал экспериментов

Каталог хранит **результаты расчётных прогонов**: что запускали, с какими
параметрами, что получилось и как это повторить. Он не заменяет `contact/*.md` —
там лежат постановки задач, методика и разборы. Здесь лежат сами измерения,
каждое со своей датой и своим набором чисел.

> Это инструкция самому себе (Claude Code) на будущие сессии. Правила ниже —
> обязательные, а не рекомендательные.

---

## 1. Устройство каталога

```
experiments/
├── README.md                          ← этот файл: правила и указатель
└── ГГГГ-ММ-ДД-<кейс>-<слаг>/          ← один эксперимент = один каталог
    ├── README.md                      ← обязательно: описание эксперимента
    ├── REPRO.md                       ← обязательно с 2026-09-22: как повторить
    ├── *.svg                          ← все графики этого эксперимента
    ├── data/                          ← (опционально) кривые, сводные таблицы
    └── scripts/                       ← (опционально) скрипты сборки графиков
```

**Имя каталога:** `ГГГГ-ММ-ДД-<кейс>-<слаг>`, где дата — день **получения
результата** (не день, когда пишется описание), кейс — `bc2`, `bc6` и т. п.,
слаг — два-три слова латиницей через дефис: `kp-sweep`, `resolution-scheme`,
`abort-contact-type2`.

**Один каталог — один вопрос.** Если прогон отвечает на два разных вопроса,
это два каталога. Если один вопрос потребовал двенадцати прогонов — это один
каталог.

## 2. Что обязано лежать в каталоге эксперимента

### 2.1. `README.md` — описание

Разделы строго в этом порядке; пустые не выбрасывать, а писать «нет»:

| Раздел | Содержание |
|---|---|
| Шапка | дата, кейс, ветка, коммит `HEAD`, число прогонов, статус |
| **Вопрос** | одна-две фразы: на что отвечал эксперимент |
| **Постановка** | что меняли, в каких пределах, что держали постоянным |
| **Результат** | таблица чисел — обязательно с единицами и долей от эталона |
| **График** | вставка SVG из этого же каталога, с разбором: что на нём видно |
| **Вывод** | прямой ответ на вопрос из «Вопроса», без смягчений |
| **Что осталось неясным** | честный список; «ничего» — допустимый ответ |

### 2.2. `REPRO.md` — воспроизведение

Обязателен для экспериментов **с 2026-09-22 и далее**. Более ранние оставлены
без него намеренно: точное состояние дерева на момент тех прогонов уже не
восстановить, и выдумывать его нельзя.

Содержание (по образцу карточки прогона в comet-ml):

1. **Окружение** — ОС, компилятор с версией, CMake, Python, число потоков OpenMP.
2. **Коммит** — полный хэш `HEAD` на момент прогона и его заголовок.
3. **Diff — отдельным zip-архивом `repro-diff.zip` рядом с `REPRO.md`,
   а не текстом в самом файле.** В `REPRO.md` остаётся только таблица состава
   архива и команды наложения. Требование владельца от 2026-09-22; на прежние
   эксперименты не распространяется.
4. **Команды** — сборка и запуск дословно, в порядке выполнения.
5. **Стоимость** — сколько это считалось и сколько заняло места.
6. **Проверка** — как убедиться, что повтор дал то же самое (конкретные числа).

**Устройство архива.** Внутри — патчи в формате `git apply`, по одному на
логическое изменение, с числовым префиксом в порядке наложения; `MANIFEST.md`
с составом, порядком и командами снятия; `HEAD.txt` с полным хэшем, автором,
датой и заголовком коммита. Патчи получать из настоящего `git diff`, а не
набирать руками: рукописный патч не накладывается из-за контекста и номеров
строк.

**Временная инструментация хранится только здесь.** Правило «диагностическую
инструментацию не коммитить» остаётся в силе: она живёт в архиве как патч, а
рабочее дерево откатывается.

**Как собрать архив на этой машине.** Бинаря `zip` в Git Bash нет; пользоваться
`python -m zipfile -c repro-diff.zip <файлы>` либо модулем `zipfile` из скрипта.
Распаковка у читателя — `unzip` или `python -m zipfile -e`.

**Архив обязан быть проверен до записи в каталог.** Минимум: распаковать во
временный каталог и прогнать `git apply --check` по каждому патчу (для уже
принятых изменений — `git apply --check --reverse`). Непроверенный архив хуже
его отсутствия: он выглядит воспроизводимым, не будучи таковым.

## 3. Правила обращения

**Графики, которые собираются целью сборки, остаются на своём месте.**
`contact/e2e/bc2_monitor_velocity.svg` и `bc6_monitor_velocity.svg` записываются
целями `bc2_plot` / `bc6_plot` по путям из `CMakeLists.txt` и вставлены в
`contact/06-e2e-case.md` и `contact/06-e2e-bc6.md`. В каталог эксперимента кладётся
**снимок** — копия на момент прогона. Перемещать такой файл нельзя: сломается и
сборка, и отчёт. Разовые графики, которые никуда не вставлены, наоборот,
переносятся в каталог эксперимента и живут только там.

**Записанный эксперимент не переписывается.** Новый прогон с другими параметрами
— новый каталог с новой датой. Правки в старом допустимы только двух видов:
исправление фактической ошибки в числах (с пометкой, что и когда исправлено) и
добавление ссылки на более поздний эксперимент, который его уточнил или
опроверг.

**Отрицательный результат заносится наравне с положительным.** «Параметр не
влияет», «гипотеза опровергнута», «стало хуже» — это результат, и он ценнее
молчания: он закрывает направление. Формулировать прямо, без «возможно, стоит
дополнительно исследовать».

**Числа — только измеренные.** Каждое число в `README.md` должно быть выводимо
из файлов этого же каталога либо из названного прогона. Оценки и прикидки
помечать словом «оценка». Заявленный результат, не переживший проверку, снимать
явной строкой, а не тихой правкой.

**Кадры расчёта (`sph_output_*.txt`) не хранить.** Это гигабайты. Хранить кривые
монитора (`--emit-curve`), логи прогонов и сводные таблицы. Ориентир по объёму
каталога эксперимента — до ~1 МБ; если больше, оставлять только сводки.
Исключение владельца от 2026-10-01: для `2026-10-01-clamp-fiber-viz` и
`2026-10-01-clamp-solid-viz` (анимации e2e-тестов закрепления) ориентир — до 10 МБ;
на другие каталоги не распространяется.

**Скретчпад — не архив.** `C:\Users\Maria\AppData\Local\Temp\claude\...` чистится.
Всё, что должно пережить сессию, копируется сюда в тот же день, когда получено.

**Действующие ограничения владельца** (не отменены и распространяются на любой
эксперимент): не подгонять пороги сверки под результат; не трогать
`src/input.cpp`; диагностическую инструментацию не коммитить — её текст
попадает в `REPRO.md`, а рабочее дерево откатывается; не менять постановку
задачи и геометрию.

**После заведения каталога** — дописать строку в указатель ниже. Указатель
обязан оставаться полным: каталог без строки в указателе считается незаконченной
работой.
