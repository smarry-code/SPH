## 4. Команды

```bash
# 1. заплата и сборка
python -m zipfile -e experiments/2026-09-23-bc6-xsph/repro-diff.zip repro/
git apply repro/01-bc6-epsilon-env-override.patch
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target test_e2e_bc6

# 2. серия B1 + B2 без ступени 0,05 мм: четыре прогона из data/todo.txt,
#    по два одновременно, 0,10 мм первым
bash experiments/2026-09-23-bc6-xsph/scripts/run_all.sh

# 3. ТОЛЬКО на мощной машине (≥ 8 ГБ свободной памяти) — ступень 0,05 мм.
#    Без SPH_RUN_HEAVY=1 скрипт откажется работать.
SPH_RUN_HEAVY=1 bash experiments/2026-09-23-bc6-xsph/scripts/run_e005_dx005.sh

# 4. снять заплату и вернуть штатный бинарь
git apply -R repro/01-bc6-epsilon-env-override.patch
cmake --build build --target test_e2e_bc6

# 5. метрики, data/summary.txt и фигура bc6_xsph.svg
python experiments/2026-09-23-bc6-xsph/scripts/fig.py
```

`scripts/one.sh <ε> <Δx, м> <тег>` запускает
`SPH_BC6_EPSILON=<ε> build/test_e2e_bc6[.exe] --full --contact-type=0
--delta-x=<Δx> --time-limit=$SPH_TIME_LIMIT --emit-curve=data/curve_<тег>.txt`,
пишет лог в `data/run_<тег>.log`, дописывает в его конец стенное время, код
возврата, ε и Δx, и проверяет, что в логе есть строка
`SPH_BC6_EPSILON = <ε>`. Если строки нет (заплата не наложена), кривая
переименовывается в `INVALID_curve_<тег>.txt`, скрипт возвращает 3.

Кривые при ε = 0,25 (`data/curve_e025_dx0{20,14,10}.txt`) — копии
`data/curve_dx0{20,14,10}.txt` из
[2026-09-23-bc6-resolution](../2026-09-23-bc6-resolution/); пересчитывать их не нужно.

Два прогона одновременно, по 6 потоков; `run_all.sh` занял 28 мин по стенным
часам — все прогоны оборвались раньше `t_total`, поэтому быстрее оценки
(≈ 80 мин). Объём каталога — около 0,5 МБ; кадры не сохранялись.

**Код возврата серии — 123**, это ожидаемо: xargs возвращает 123, если хоть
один прогон завершился с ненулевым кодом, а здесь все четыре вернули 1 (обрыв
по ρ < 0).

**Ошибка первой версии `one.sh`.** Проверка заплаты сравнивала ε со строкой
лога как текст (`0.10` против напечатанного `0.1`), и прогон `e010_dx020`
получил метку `INVALID_`, хотя ε в нём применился (`SPH_BC6_EPSILON = 0.1` в
логе). Кривая переименована обратно вручную после сверки лога. В каталоге
лежит исправленная версия — сравнение как чисел. До старта следующих прогонов
она проверена на копиях логов `e010_dx020` и `e005_dx010` (оба уже содержали
строку ε): верные пары проходят, чужая (0,05 против лога с 0,1) бракуется с
кодом 3. Прогоны `e005_dx020` и `e005_dx014` стартовали с ней и прошли её
штатно; `e005_dx010` шёл со старой версией и прошёл её текстом (`0.05`).
