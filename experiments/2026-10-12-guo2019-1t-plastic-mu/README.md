# Guo 2019, 1T, base: пластичная нить Twaron CT 717 и трение μ

Ветка `plastic`. Серия выстрелов по одному слою ткани (конфигурация 1T, уровень `base`, 102 x 102 нити) с упруго-пластичной нитью
и варьированием μ (μ_ff = μ_fs). Цель: V_BL модели около 76 м/с (статья 76 +3/-3): при 73 м/с шар не пробивает ткань
(желательно 3 порванные вертикальные и 0 горизонтальных нитей, прогиб при первом разрыве 25-27 мм), при 79 м/с пробивает.

## Постановка

- Код: `tools/guo2019/guo2019_shot.cpp` + `tests/guo2019_*.hpp` из ветки `plastic` (база `fiber_new`) без изменений постановки 1T base
  (правки Guo2T относятся к 2T/4T; сцена 1T у них та же). Новое в `plastic`: ключи `--fiber-inelastic=<файл>`, `--eps-break=<x>`;
  в `shot.txt` добавлены `eps_p_max`, `W_p` (Дж, все связи, включая порванные), `n_bonds_plastic` и параметры нити.
- Остальные параметры как в серии подбора μ в Guo2T (`mu_driver.py`): `--n-mon=10 --n-diag=100 --save-t=20e-6 --frames=off --repeat=1`,
  `t_max = 1.5 мс`, при «undetermined» один повтор с `t_max = 3.0 мс`, 8 потоков, `body_isolation` включён.
- Нить: E = 85 ГПа, d = 0.39 мм, rho = 1440 (как в сцене). `twaron_plastic.fib` (только директивы):
  `PLASTIC 0 SY=2.04e9 H=100e9`, `FAILURE 0 SIGMA_U=2.55e9`; `--eps-break=0.05` (страховочный, `l_break = 1.05 l0`). RATE, VISCO не заданы.
- Обоснование: eps_y = SY/E = 2.4 %, E_t = E H/(E+H) = 46 ГПа. Разрыв при полном напряжении sigma = E(eps - eps_p) + q = 2.55e9 (без Максвелла q = 0), то есть упругая часть 3 %
  (как eps_break упругой модели). На ветви упрочнения sigma = SY + H eps_p = 2.55e9, откуда eps_p = 0.51 %, eps = 3.51 %.
  Работа до разрыва на единицу объёма: упругая 0.5 sigma^2/E = 38.3 МДж/м^3 + пластическая SY eps_p + 0.5 H eps_p^2 = 11.7 МДж/м^3, всего 50.0 МДж/м^3
  (упругая нить с eps_break = 3 %: 38.3 МДж/м^3, на 30 % меньше). Проверка на smoke: max eps_p = 0.00510.

## Сравнение с Guo2T

Сравнение с `eval_mu*.md` Guo2T идёт между разными ревизиями кода: сцена 1T в обеих ветках та же, но правки Guo2T касаются 2T/4T,
а серия plastic собрана из ветки `plastic`. Поэтому расхождения в 1T между eval_mu*.md Guo2T и этой серией не следует целиком
относить к трению или пластике: часть может быть от ревизии кода. Для чистого сравнения нужна та же ревизия.

## Сетка прошлой серии (plastic_driver.py, не подбор окна)

**Прошлая серия.** Первая сетка по μ с фиксированными V0 = 73 и 79 м/с (`plastic_driver.py`, μ ∈ {0.3, 0.5, 0.7, 0.9, 1.0}, все V0 = 73 по возрастанию μ, затем 79,
последовательно, один выстрел на 8 потоков). Её результаты в `~/plastic1T/` и разделы «Статус и результаты» и «Запуск» ниже относятся к ней.
Подбор окна скоростей ведётся отдельной серией `window_driver.py` (раздел «Серия подбора окна»), сетка по μ там другая: 0.1, 0.3, 0.5, 0.7, 0.9.

## Запуск прошлой серии (сервер claude-compute)

```
# исходники и сборка (один раз): ~/SPH_plastic (tar без build*/.git), cmake -G Ninja -DCMAKE_BUILD_TYPE=Release -DSPH_DIM=3 -DCMAKE_CXX_FLAGS="-include cmath"
cd ~/plastic1T && OMP_NUM_THREADS=8 setsid nohup python3 plastic_driver.py > queue.log 2>&1 < /dev/null &
```

Драйвер `scripts/plastic_driver.py` (копия лежит в `~/plastic1T/`) перезапускаем той же командой: готовые выстрелы пропускаются.

## Статус и результаты прошлой серии (на сервере, `~/plastic1T/`)

- `pgrep -af "plastic_driver|guo2019_shot"`, `tail ~/plastic1T/queue.log`;
  ход текущего выстрела: `tail -1 ~/plastic1T/mu<μ>_v<V0>/*/monitor.csv` (шаг, t, dt, z_c, v_z ...).
- `~/plastic1T/mu<μ>_v<V0>/` (`*_long/` для повтора): `1T_base_v<V0>_r0/shot.txt`, `monitor.csv`, кадры, рядом `.log`.
- `~/plastic1T/shots.csv`: μ, V0, run (base/long), исход, V_R, e, порвано верт./гориз., время и прогиб при первом разрыве, max eps_p, W_p,
  E_tot_max/E_tot_0, E_tot_end/E_tot_0, n_tunnel, t_end, t_max, wall.
- `~/plastic1T/eval.md`: блок оценки после каждого выстрела (формат как `eval_mu*.md` в Guo2T) с выводом относительно цели; `eval.jsonl` то же машинно.
  В `eval.jsonl` дополнительно поле `n_bonds_plastic` (в `shots.csv` его нет, чтобы не менять заголовок уже существующего файла).

### Как читать блок оценки

- `E_tot_end/E_tot_0` у пластичной нити меньше 1 ожидаемо: E_tot (кинетическая + упругая энергия) не включает необратимую работу
  `W_p` и работу трения, поэтому к концу расчёта доля энергии уходит в эти статьи. Это не потеря энергии схемой.
  Контроль сохранения энергии по схеме -- `E_tot_max/E_tot_0` (превышение 1.005 отмечается как возможная генерация энергии).
- `n_bonds_plastic` -- только целые (непорванные) связи с `eps_p > 0` на конец расчёта. Порванные связи сюда не входят
  (их пластическая работа учтена в `W_p`, которая включает и порванные связи).

### Перезапуск и восстановление

- При старте драйвер проверяет все готовые выстрелы (есть `<sdir>/shots.csv`) и дописывает недостающие части оценки: блок в `eval.md`,
  строку в `shots.csv`, строку в `eval.jsonl`. Ключ записи -- (μ, V0, run = base|long), каждая часть проверяется отдельно, уже записанное не дублируется.
  Так восстанавливается ситуация, когда процесс упал между записью результата выстрела и оценкой.
- Ошибка в одном выстреле (битый файл, нет результата и т.п.) печатает traceback в stdout (при запуске по инструкции это `queue.log`)
  и серия продолжается со следующего выстрела. Отсутствие бинаря `guo2019_shot` -- сообщение и выход с кодом 1.

## Вязкость и скоростная зависимость: параметры и диапазоны

Файл `twaron_plastic_visco_rate.fib` (рядом с `twaron_plastic.fib`; `eps_break = 0.05` по-прежнему ключом `--eps-break=0.05`):

```
PLASTIC 0 SY=2.04e9 H=100e9
RATE 0 JC C=0.015 EDOT0=1e-3
VISCO 0 E1=8.5e9 TAU=20e-6 XI=0.05
FAILURE 0 SIGMA_U=2.55e9
```

**Критерий разрыва.** `FAILURE SIGMA_U` сравнивается с полным напряжением `sigma_full = E(eps - eps_p) + q` (q -- напряжение ветви Максвелла,
ненулевое только при `VISCO E1>0`). Член Кельвина `eta*d(eps)/dt` не входит: это численное демпфирование. Без Максвелла `q = 0`, критерий и результат прежние.
Запас `sigma_u/sigma_y = 2.55/2.04 = 1.25`: скоростной множитель R поднимает предел текучести до `R*sigma_y`, и он не должен догонять `sigma_u`,
иначе пластика исчезает (нить рвётся раньше, чем потечёт).

| Параметр | Значение | Диапазон | Обоснование и оговорки |
|---|---|---|---|
| RATE JC, `C` | 0.015 | 0...0.02 | Литература по арамидам: рост прочности на 10-30 % от квазистатики до ~10^3 1/с (оценка не проверена). Верхняя граница из условия `C ln(eps_p_dot/EDOT0) < 0.25` при `eps_p_dot ~ 100 1/с`: `ln ~ 11.5`, то есть `C < 0.022`. Скоростная прочность `sigma_u` не реализована: большие `C` делают нить хрупче, не прочнее. `E = 85 ГПа` уже динамический модуль, поэтому частичный двойной учёт; `C` взят у нижней границы. |
| RATE JC, `EDOT0` | 1e-3 1/с | 1e-4...1e-2 | Квазистатическая скорость. Вторичный параметр. |
| VISCO, `E1` (Максвелл) | 8.5 ГПа | 0...12 ГПа | `E + E1` в динамическом диапазоне 78...97 ГПа. Альтернатива: `E ~ 75 ГПа` (квазистатика) + `E1 = 15...20 ГПа`. Больше `E1` -- жёстче на фронте и (критерий по полному напряжению) раньше разрыв; шаг ~ `sqrt(E/(E+E1))` (для `E1 = 8.5` ГПа множитель 0.953, `E_inst = 93.5 ГПа`). |
| VISCO, `TAU` | 20 мкс | 5...100 мкс | Волна по нити 60 мм ~ 8 мкс при `c ~ 7.7 км/с`, удар 500...1000 мкс. При `TAU << 5 мкс` ветвь не действует, при `TAU >> 1 мс` это просто добавка жёсткости; максимум рассеяния при `TAU` порядка времени нагружения. |
| VISCO, `XI` (Кельвин) | 0.05 | 0...0.1 | Численное гашение звона бусин. При `XI >= 0.3` заметно поглощается энергия и уменьшается шаг. Для подгонки не варьировать. |

**Порядок варьирования при неудаче** (нет окна ни при одном μ): μ -> `sigma_u` (2.55 -> 2.8...3.0 ГПа) и `sigma_y/sigma_u` (0.7...0.9) -> `C`, `E1`, `TAU` -> `XI` не трогать.

## Серия подбора окна

Цель: найти μ, для которого есть пара соседних скоростей (не более 6 м/с) «не пробит» / «пробит» в диапазоне 66...87 м/с (V_BL статьи 76 +3/-3).
Драйвер `scripts/window_driver.py` (использует функции `plastic_driver.py`, обе копии кладутся рядом).

**Критерий (строгий).** «Не пробит» = исход `not_perforated` (с правилом остановки шара к `t_max`) И `V_R = 0` И порвано вертикальных <= 5 И горизонтальных = 0.
Всё остальное -- «пробит» (причина пишется в `eval.md`). Если исход так и остался «не определён» (после повтора с `t_max = 3 мс`), для этого μ вывод невозможен.

**Алгоритм.** μ по порядку 0.1, 0.3, 0.5, 0.7, 0.9 (`--mus`). Для текущего μ одновременно выстрелы 73 и 79 м/с (два процесса, по 4 потока, `OMP_NUM_THREADS=4`):

| 73 м/с | 79 м/с | дальше |
|---|---|---|
| не пробит | пробит | окно [73; 79] |
| пробит | пробит | выстрел 67 (один, 8 потоков): не пробит -> окно [67; 73]; пробит -> окна нет |
| не пробит | не пробит | выстрел 85: пробит -> окно [79; 85]; не пробит -> окна нет |
| пробит | не пробит | «немонотонно», окна нет, дальнейших выстрелов нет (помечается в `window.md`) |

Окно допустимо при `V_p - V_np <= 6` и `66 <= V_np`, `V_p <= 87`. Окно найдено -> драйвер останавливается, остальные μ не считаются; иначе -- следующий μ.
Параметры каждого выстрела: `--config=1T --level=base --save-t=20e-6 --n-mon=10 --n-diag=100 --t-max=1.5e-3 --frames=off --fiber-inelastic=<fib> --eps-break=0.05 --energy-log=100`.

**Падение выстрела.** Падение = код возврата `guo2019_shot` не 0 или нет `shots.csv`. Это не то же самое, что «не определён» (исход есть, но неясен),
и не даёт права считать μ «окна нет»:
- упавший выстрел перезапускается один раз автоматически; лог первой попытки сохраняется как `<каталог>.fail1.log`;
- при паре 73/79 падение одного выстрела не отбрасывает второй: готовый результат записывается, перезапускается только упавший;
- если повтор тоже упал, серия **останавливается** (exit 1): в `queue.log` и в `window.md` (вердикт «УПАЛ», раздел «Итог серии») пишется причина и путь к логу;
  следующие μ не считаются. Окна для этого μ нет не потому, что его нет, а потому, что выстрел не дал результата.

**Проверки на старте.** Если нет файла `--bin` или `--fib`, драйвер выводит сообщение и выходит с кодом 1 до запуска выстрелов.

**Запуск (сервер).** Бинарь с логом энергии (`-DSPH_ENERGY_LOG=ON`), предпроверка в драйвере:

```
cd ~/window1T && setsid nohup python3 window_driver.py --bin ~/SPH_plastic/build-elog/guo2019_shot --fib ~/window1T/twaron_plastic_visco_rate.fib > queue.log 2>&1 < /dev/null &
```

Файлы драйвера: `scripts/window_driver.py` и `scripts/plastic_driver.py` (лежат рядом; `plastic_driver.py` сохраняет код возврата выстрела для проверки падения).

**Как смотреть статус.**
- `~/window1T/window.md` -- сводка по μ: выстрелы, вердикты с причиной, найденное окно или причина неудачи, итог серии (переписывается после каждого шага);
- `~/window1T/eval.md`, `shots.csv`, `eval.jsonl` -- блоки оценки по выстрелам (формат `plastic_driver`, плюс строгий вердикт);
- `tail ~/window1T/queue.log`, `pgrep -af "window_driver|guo2019_shot"`; ход выстрела: `tail -1 ~/window1T/mu<μ>_v<V0>/*/monitor.csv`;
  лог энергии: `~/window1T/mu<μ>_v<V0>/*/energy_log.csv` (`W_p_fiber`, `W_v_fiber`).
- Перезапуск той же командой безопасен: готовые выстрелы не пересчитываются, логика окна восстанавливается по готовым результатам;
  выстрел, оборванный на середине (нет `shots.csv`), считается заново.
