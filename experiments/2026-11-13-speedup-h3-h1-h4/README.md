# Ветка speedup: alignas(64), H3, H1+H4 — проверка и замеры (2026-11-13)

Коммиты в `speedup` поверх `0b9d3b0` (правки A–D контакта нитей, отчёт 2026-11-12):

| Коммит | Что |
|---|---|
| `5995594` | `ContributionBuffer` с `alignas(64)`: нет ложного разделения кэш-линий между отрезками |
| `10fbcb1` | **H3** — последовательный код шага: кэш опорных dt нитей (`FiberDtRefCache`), `L_max` один раз за шаг, параллельный `SpatialIndex::build` (одна свёртка bbox, `parallel_scan` префиксов), без лишних `assign` |
| `7147083` | **H1+H4** — отсечка далёких пар нить–нить (`fiber_contact_surely_apart`) прямо при сборке primitive и обход пар без промежуточного массива (`for_each_pair_segmented`); ядро, предел шага и демпфер `energy_log` работают по виду `FiberContactPrimView` (плотные массивы по j, ключ вкладов и отрезок — по полному k) |
| `c8973f7` | Правки по ревью Codex: границы отрезков без переполнения (`seg_begin`), строки `segcnt_` без ложного разделения |

Результат побитово равен `f1298aa` при любом числе потоков.

## Итог

1. **Шаг на 8 потоках (8t) быстрее на 16 %:** H 0,0235 → 0,0198 с/шаг (1,19×), P 0,0251 → 0,0210 с/шаг (1,20×) против `0b9d3b0`.
   - Против `f1298aa`: 1,71× (H) и 1,60× (P); против исходной `1658756`: 3,6× и 4,4×.
   - На 1, 2 и 4 потоках выигрыш тот же порядка: 13–18 %.
2. **Почти весь выигрыш дал H1+H4.** На claude-compute (2 потока) это −13 % в парных замерах; alignas и H3 на 2 потоках ниже шума ВМ (±5–10 %).
3. **Побитовость сохранена везде:** законы 0/3/4, проекция, сборки `SPH_ENERGY_LOG` и `SPH_CONTACT_STATS`, 1/2/8 потоков, рестарт с чекпоинта; ctest 101/101.
4. **Масштабирование сохранилось:** E(8) = 0,60 (H, было 0,60) и 0,59 (P, было 0,57); последовательная доля главного потока по-прежнему около 14 %, но в абсолютном времени она сократилась на 20–32 %.
5. **Главная цель дальше — сборка поиска нить–нить:** 26–29 % сэмплов окна «удар» на 8 потоках. Теперь в ней сидит и отсечка `surely_apart`, которая раньше была в ядре.

## 1. Проверка (claude-compute)

Скрипт [`scripts/verify_compute.sh`](scripts/verify_compute.sh) (на сервере `~/c3sp_tests/run.sh`) после каждого этапа:

1. сборки `build`, `build-elog` (`SPH_ENERGY_LOG`), `build-cstats` (`SPH_CONTACT_STATS`) для нового дерева и эталона `f1298aa`;
2. изменённые юнит-тесты (обе сборки), ctest -j1 (обе сборки), `test_checkpoint`;
3. короткие сцены против `f1298aa`: законы 0/3/4 (`monitor.csv`, `energy_log.csv`, `shot.txt` без времени), проекция (против эталона и 1 против 2 потоков), сборка `cstats` на законах 3/4 (`monitor.csv` и оба файла `contact_stats`, 1 и 2 потока), рестарт с чекпоинта;
4. при полном совпадении — замер: полная сцена Guo 1T на 2 потоках, H и P, по 2 повтора, прошлый и новый бинарь попеременно; каждый `monitor.csv` против `f1298aa`.

Журналы: [`results/verify_h3_log.txt`](results/verify_h3_log.txt), [`results/verify_h1h4_log.txt`](results/verify_h1h4_log.txt), [`results/verify_codex_fix_log.txt`](results/verify_codex_fix_log.txt). Всё «СОВПАДАЕТ».

Что всплыло по ходу:
- **H1+H4, первая сборка.** Агент оставил рядом с новым ядром по виду старое ядро по `vector` — двойное определение. Старый блок удалён (196 строк, побайтно из версии H3).
- **H1+H4, предпосылки тестов.** Сцена «пары есть, выживших нет» не давала m = 0: сдвиг одного семейства по z оставлял параллельные нити внутри семейства на 0,009 < R = 0,011. Сцена заменена «лестницей» по z (нить `object_id = o` сдвинута на 0,018·o). Проверки не ослаблены, все 98 предпосылок выполняются.
- **Скрипт.** Секция cstats затирала переменную, по которой сверялся рестарт (ложное «ОТЛИЧАЕТСЯ»); cstats на проекции не поддерживается программой, поэтому cstats идёт на законах 3/4 без предиктора.

## 5. Дальнейшие шаги

1. **Сборка поиска нить–нить (26–29 % на 8 потоках).** Кандидаты: дешёвый предфильтр по ячейкам/AABB сегментов до `surely_apart`; уменьшение радиуса поиска (сейчас d + 2·L_max на все пары); кэш выживших между шагами с проверкой по смещению (Verlet-список).
2. **H1-bis:** монитор `contact_ff` на отсечённом поиске (сейчас диагностика требует полного списка).
3. **H4 для Solid–SPH и нить–Solid:** `compute_solid_sph_contributions` + `build_solid_sph_search` — 19–21 % на 8 потоках, там всё ещё вектор пар и склейка.
4. **`reduce_segments_into` (12 %):** свёртка по частицам, следующая по весу.
5. **Ожидание в libgomp (idle_wait 18–20 %):** слияние коротких параллельных регионов шага.
