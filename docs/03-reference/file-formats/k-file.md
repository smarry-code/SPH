# Формат файлов геометрии `*.k`

LS-DYNA keyword-файл, содержащий сетку узлов и SPH-элементов. Разбирается
функцией [`parse_k_file()`](../../../src/input.cpp:110) (внутренняя связь,
`static`). Используется при загрузке геометрии удара/соударения из
препроцессора LS-PrePost.

## Общая структура

Файл состоит из **блоков**, начинающихся с ключевого слова в первой позиции
строки. Поддерживаемые блоки:

| Ключевое слово | Содержание блока |
|---|---|
| `*NODE` | Координаты узлов |
| `*ELEMENT_SPH` | Описание SPH-элементов |
| `*PART`, `*KEYWORD` и прочие | Игнорируются (переводят парсер в нейтральное состояние) |

## Правила синтаксиса

- Ключевые слова распознаются по ведущему символу `*` (без учёта регистра);
  комментарии после `$` в строке ключевого слова отсекаются.
- Комментарии внутри данных: всё после символа `$` в строке отбрасывается
  (функция `trim_comment`).
- Строки, состоящие только из пробелов, пропускаются.
- Формат данных — **free format**: поля разделяются запятыми (функция
  `split_by_commas_preserve_empty`). Недостающие поля заполняются нулями.
- Узлы с отрицательным `NID` игнорируются.

## Блок `*NODE`

Каждая строка: `NID, x, y, z`.

| Поле | Тип | Описание |
|---|---|---|
| `NID` | long long | Идентификатор узла (ключ карты) |
| `x`, `y`, `z` | double | Координаты (м) |

## Блок `*ELEMENT_SPH`

Каждая строка: `NID, PID, MASS`.

| Поле | Тип | Описание |
|---|---|---|
| `NID` | long long | Ссылка на узел (его координаты берутся из `*NODE`) |
| `PID` | size_t | Идентификатор детали/материала → записывается в `sys.itype` |
| `MASS` | double | Масса частицы (кг) |

## Разрешение данных

После чтения обоих блоков выполняется слияние: для каждого SPH-элемента ищется
узел с совпадающим `NID`. Элементы без найденного узла **пропускаются**.
Размер `ParticleSystem` устанавливается по числу валидных элементов.

```text
parse_k_file:
  nodes[NID] = {x, y, z}     ← блок *NODE
  sph_elements = [{NID,PID,MASS}, ...]   ← блок *ELEMENT_SPH
  ── слияние ──
  sys.x[*][idx] = nodes[NID]
  sys.mass[idx] = MASS
  sys.itype[idx] = PID
```

## Пример файла

```text
$# LS-DYNA Keyword file
*KEYWORD
*PART
SphNode
1
*NODE
1, 0.0000, 0.0000, 0.0000
2, 0.0003, 0.0000, 0.0000
3, 0.0006, 0.0000, 0.0000
*ELEMENT_SPH
1,1,0.0628
2,1,0.0628
3,1,0.0628
*END
```

!!! note "Мониториируемая частица"
    При разборе `parse_k_file` автоматически определяется `cfg.moni_particle` —
    частица с координатой $x > 0{,}0131$ и `itype == 3` вблизи оси; её индекс
    записывается в `log.txt`.

## Рекомендации по подготовке

- Экспортируйте геометрию из LS-PrePost в формате `*.k`, убедитесь, что блоки
  `*NODE` и `*ELEMENT_SPH` присутствуют.
- Проверьте, что всем SPH-элементам сопоставлены существующие узлы.
- Значения `PID` должны соответствовать `itype` материалов (см. [`materials.hpp`](../../../include/materials.hpp:20)).
