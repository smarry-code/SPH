# Формат файлов геометрии `*.k`

LS-DYNA keyword-файл с узлами и элементами. Читается функцией [`load_k_geometry()`](../../../include/k_input/k_geometry.hpp) и превращается в начальную геометрию расчёта: Solid-частицы из `*ELEMENT_SPH` (режимы `solid` и `solid_fiber`) и нити из `*ELEMENT_BEAM` (режим `solid_fiber`). Физика деталей (материал, плотность, скорость, параметры нити) в `.k` не читается: она задаётся отдельной [таблицей деталей](k-parts.md). Ключи конфигурации - в [Initial_Conditions.txt](../config/initial-conditions.md).

!!! warning "Не всё сверено с официальным мануалом LS-DYNA"
    Ширины полей fixed- и long-формата для `*NODE`, `*PART` и `*BOUNDARY_SPC_*` (в коде помечены `[K]`), включительность `NEND` в `*ELEMENT_SPH`, правила long-формата и вещественные числа без десятичной точки в fixed-формате **не сверены с официальным мануалом LS-DYNA** (мануал был недоступен). **Надёжно проверен только free-format** (поля через запятую): им записан `1.k` из корня репозитория (выгрузка LS-PrePost 2026). Для остальных карточек (`*ELEMENT_SPH`, `*ELEMENT_BEAM`, `*ELEMENT_SOLID`, `*SET_NODE_LIST`) в коде нет пометки `[K]`, но и ссылки на проверку по мануалу в этой документации нет. Если используете fixed или long, сверьте результат со сводкой импорта.

## Поддерживаемые ключевые слова

Ключевое слово - строка, начинающаяся с `*` в первой колонке. Регистр не важен; имя заканчивается пробелом или `(`. Строки данных, начинающиеся с пробелов и `*`, ключевыми словами не считаются.

| Ключевое слово | Что делается |
|---|---|
| `*KEYWORD` | Опция `LONG=Y` включает long-формат для всего файла (`LONG=N` выключает) |
| `*TITLE` | Первая строка данных сохраняется как заголовок (информационно) |
| `*NODE` | Узлы: NID, X, Y, Z (TC, RC читаются, не используются) |
| `*ELEMENT_SPH`, `*ELEMENT_SPH_VOLUME` | SPH-частицы |
| `*ELEMENT_BEAM` | Балки: используются EID, PID, N1, N2; в режиме `solid_fiber` - нити, в режиме `solid` - пропускаются с предупреждением |
| `*ELEMENT_SOLID` | Читается всегда; в частицы превращается только при `k_solid_elements = particles`, иначе пропускается с предупреждением |
| `*PART` | Заголовок и PID детали |
| `*BOUNDARY_SPC_NODE`, `*BOUNDARY_SPC_SET` | Закрепления (маски зажимов) |
| `*SET_NODE_LIST`, `*SET_NODE_LIST_TITLE`, `*SET_NODE_LIST_GENERATE` (и их сочетание) | Наборы узлов для `*BOUNDARY_SPC_SET` |
| `*INCLUDE`, `*INCLUDE_PATH`, `*INCLUDE_PATH_RELATIVE` | Включение файлов |
| `*END` | Конец чтения текущего файла |
| Все остальные (`*MAT_*`, `*SECTION_*`, `*CONTROL_*`, `*SET_NODE_LIST` с иными опциями и т. д.) | Пропускаются без ошибки, считаются в сводке |

Отсутствие `*NODE` или `*ELEMENT_SPH` само по себе не ошибка, но любая ссылка элемента на отсутствующий узел или PID без `*PART` - ошибка (см. «Ошибки»).

## Форматы полей

Формат выбирается **для каждой строки данных**: если в строке есть запятая - это free-format, иначе fixed-format.

### Free-format

Поля разделяются запятыми, ширина не ограничена, пробелы вокруг полей отбрасываются. Недостающие хвостовые поля и пустые поля берут значение по умолчанию (0); пустое обязательное поле - ошибка `обязательное поле <имя> пусто`.

```text
*NODE
1, 0.000, 0.000, 0.000
2, 0.001, 0.000, 0.000
```

Целое поле должно быть целым (`1.0` в поле NID - ошибка `поле NID: ожидалось целое, получено '1.0'`). Вещественное допускает цифры, `.`, `+`, `-`, `e`, `E`, `d`, `D` (экспонента Фортрана). Поле, начинающееся с `&`, - ссылка на `*PARAMETER`, это ошибка (см. «Ошибки»).

### Fixed-format

Строка режется по ширинам полей карточки; пустая подстрока - значение по умолчанию. Ширины standard-формата (как в `include/k_input/k_cards.hpp`):

| Карточка | Поля (ширина в символах) | Пометка |
|---|---|---|
| `*NODE` | NID 8, X 16, Y 16, Z 16, TC 8, RC 8 | `[K]` |
| `*ELEMENT_SPH` | NID 8, PID 8, MASS 16, NEND 10 | |
| `*ELEMENT_BEAM` | EID, PID, N1, N2, N3, RT1, RR1, RT2, RR2, LOCAL - по 8 | |
| `*ELEMENT_SOLID` | EID, PID, N1..N8 - по 8 | |
| `*ELEMENT_SOLID (ten nodes format)` | карточка 1: EID, PID по 8; карточка 2: N1..N10 по 8 | |
| `*PART`, карточка 2 | PID, SECID, MID, EOSID, HGID, GRAV, ADPOPT, TMID - по 10 | `[K]` |
| `*BOUNDARY_SPC_NODE` | NID, CID, DOFX, DOFY, DOFZ, DOFRX, DOFRY, DOFRZ - по 10 | `[K]` |
| `*BOUNDARY_SPC_SET` | NSID, CID, DOFX, DOFY, DOFZ, DOFRX, DOFRY, DOFRZ - по 10 | `[K]` |
| `*SET_NODE_LIST`, карточка 1 | SID, DA1..DA4, SOLVER - по 10 | |
| `*SET_NODE_LIST`, далее | NID1..NID8 - по 10 (нули игнорируются) | |
| `*SET_NODE_LIST_GENERATE`, далее | B1BEG, B1END, ..., B4BEG, B4END - по 10, границы включительно | |

Смещение поля - сумма ширин предыдущих полей. `[K]` - ширина не сверена с мануалом (см. предупреждение выше).

### Long-format

Включается глобально строкой `*KEYWORD LONG=Y` либо для отдельного блока суффиксом `+` у ключевого слова (`*NODE+`); суффикс `-` принудительно включает standard. В long-формате каждое поле имеет ширину не меньше 20 (`max(ширина, 20)`). Этот пункт также не сверен с мануалом. Продолжение строк через `+`/`-` реализовано только для имён файлов в `*INCLUDE` (строка, оканчивающаяся на ` +`, продолжается на следующей); для данных узлов и элементов объединения строк нет.

## Комментарии и пустые строки

- Комментарий - строка, у которой **первый символ** `$`. Комментарии в конце строки данных не поддерживаются: `1, 0.0, 0.0, 0.0  $ узел` даст ошибку разбора поля Z.
- Строка, начинающаяся с `*`, - всегда ключевое слово. Писать `* комментарий` в конце или между данными нельзя: она будет прочитана как неизвестное ключевое слово и закончит текущий блок.
- Пустые строки пропускаются. Исключение - заголовок `*PART` (первая строка после ключевого слова): он читается целиком, как есть.

## Включение файлов

```text
*INCLUDE
geometry/nodes.k
```

Имя файла - вся строка данных после ключевого слова, **без кавычек** (кавычки не снимаются и станут частью имени). Относительный путь ищется сначала относительно каталога текущего файла, затем в каталогах, заданных `*INCLUDE_PATH`/`*INCLUDE_PATH_RELATIVE`. Абсолютный путь используется как есть. Если имя оканчивается на ` +`, оно продолжается на следующей строке.

```text
*INCLUDE_PATH
/opt/data/k-files;/opt/data/more
*INCLUDE_PATH_RELATIVE
sub
```

Строка `*INCLUDE_PATH` содержит один или несколько каталогов через `;`. Для `*INCLUDE_PATH_RELATIVE` относительные каталоги отсчитываются от каталога **главного** `.k` файла. Заданные каталоги действуют для всех последующих `*INCLUDE`, включая вложенные.

`*END` обрывает чтение файла, в котором встретился; родительский файл после `*INCLUDE` продолжает читаться.

## Ошибки

Все ошибки - исключения с сообщением `<файл>:<строка>: …` (строка 1-based; для вложенных файлов - имя вложенного файла). Тексты ниже даны с точностью до подставляемых значений.

| Условие | Сообщение |
|---|---|
| Поле начинается с `&` (`*PARAMETER`) | `*PARAMETER не поддерживается (поле <имя>: '<значение>')` |
| `*INCLUDE_TRANSFORM` | `*INCLUDE_TRANSFORM не поддерживается (смещения ID и масштабы не применяются)` |
| `*ELEMENT_SPH_<опция>`, кроме `_VOLUME` | `*ELEMENT_SPH_…: опции *ELEMENT_SPH (кроме _VOLUME) не поддерживаются` |
| `*ELEMENT_BEAM_<опция>` | `*ELEMENT_BEAM_…: опции *ELEMENT_BEAM добавляют карточки и не поддерживаются` |
| `*ELEMENT_SOLID_<опция>` | `*ELEMENT_SOLID_…: опции *ELEMENT_SOLID не поддерживаются` |
| Целое/вещественное поле не разобралось | `поле <имя>: ожидалось целое (число), получено '…'` |
| Пустое обязательное поле | `обязательное поле <имя> пусто` |
| `NEND` ненулевой и меньше `NID` | `*ELEMENT_SPH: NEND (<a>) < NID (<b>)` |
| Не удалось открыть главный файл или include | `не удалось открыть файл <путь>` |
| `*INCLUDE`: пустое имя / файл не найден / цикл | `*INCLUDE: пустое имя файла`, `*INCLUDE: файл '…' не найден (искали: …)`, `*INCLUDE: цикл включений, файл '…' уже читается` |
| `*INCLUDE`: имя оборвано продолжением | `*INCLUDE: имя файла оборвано продолжением ' +'` |
| `*PART` без карточки с PID | `*PART: после заголовка нет карточки с PID` |
| `*ELEMENT_SOLID (ten nodes format)` без второй карточки | `*ELEMENT_SOLID (ten nodes format): нет второй карточки с узлами` |
| `*SET_NODE_LIST_TITLE` без заголовка | `*…: нет заголовка набора` |
| Диапазон набора с концом меньше начала | `диапазон набора: конец (<e>) < начала (<b>)` |
| Дубликат NID в `*NODE` | `*NODE: дубликат NID <n> (первый раз: <файл>:<строка>)` |
| Дубликат PID в `*PART` | `*PART: дубликат PID <n> (первый раз: …)` |
| Дубликат NID в `*ELEMENT_SPH` | `*ELEMENT_SPH: дубликат NID <n> (первый раз: …)` |
| Дубликат EID в `*ELEMENT_BEAM` / `*ELEMENT_SOLID` | `*ELEMENT_BEAM: дубликат EID <n> (первый раз: …)`, аналогично для `*ELEMENT_SOLID` |
| Ссылка на отсутствующий узел | `*ELEMENT_SPH: узел <n> не найден в *NODE`; аналогично для `*ELEMENT_BEAM`, `*ELEMENT_SOLID`; для узла ориентации N3 - `узел ориентации <n> не найден в *NODE`; `*BOUNDARY_SPC_NODE: узел <n> не найден в *NODE` |
| Элемент ссылается на PID без `*PART` | `*ELEMENT_SPH: PID <n> не описан в *PART`; аналогично для `*ELEMENT_BEAM`, `*ELEMENT_SOLID` |
| `*BOUNDARY_SPC_SET` ссылается на отсутствующий набор | `*BOUNDARY_SPC_SET: набор узлов <n> не найден (*SET_NODE_LIST)` |
| Узел одновременно в `*ELEMENT_BEAM` (N1 или N2) и `*ELEMENT_SPH` | `узел <n> одновременно в *ELEMENT_BEAM и в *ELEMENT_SPH (<файл>:<строка>)` |

Ошибки сборки геометрии (после чтения):

| Условие | Сообщение |
|---|---|
| `MASS = 0` у SPH-элемента | `MASS = 0 у узла <n>` |
| `k_mode=solid_fiber` без `k_parts_file` | `k_mode=solid_fiber требует таблицу деталей (k_parts_file)` |
| PID SPH-элемента (или `*ELEMENT_SOLID`) без `SOLID_PART` | `PID <n> из <файл>:<строка> не описан в SOLID_PART` |
| Масса-объём без таблицы деталей | `MASS-объём (<0 или _VOLUME) требует таблицы деталей (нужна плотность)` |
| Ненулевая координата вне `dim` | `узел NID <n>: \|z\|=… > допуска … при dim=…` |
| `k_monitor_nid` не среди SPH-частиц | `k_monitor_nid=<n> не среди SPH-частиц` |
| `*BOUNDARY_SPC_*` с `CID` не равным 0 | `<ключевое слово>: CID=<n> (локальная система координат) не поддерживается` |
| `k_solid_elements=particles` без таблицы / при `SPH_DIM` не равном 3 | `k_solid_elements=particles требует таблицу деталей (k_parts_file)`, `*ELEMENT_SOLID → частицы требует SPH_DIM=3` |
| Узел `*ELEMENT_SOLID` совпадает с узлом SPH или балки | `узел <n> одновременно в *ELEMENT_SOLID и в *ELEMENT_SPH` (или `… *ELEMENT_BEAM`) |
| Нулевой объём `*ELEMENT_SOLID` | `*ELEMENT_SOLID EID <n>: нулевой или неконечный объём V=…` |

Ошибки нитей перечислены в разделе «Нити».

### Предупреждения

Предупреждения не прерывают загрузку и печатаются в сводке строками ` Предупреждение: …`:

| Условие | Текст |
|---|---|
| В режиме `solid` есть балки | `*ELEMENT_BEAM пропущены (режим solid): <N> элементов, PID: …` |
| `*ELEMENT_SOLID` при `k_solid_elements = skip` | `*ELEMENT_SOLID пропущены (пока не поддерживаются): <N> элементов, PID: …` |
| Вывернутый `*ELEMENT_SOLID` | `…: *ELEMENT_SOLID EID <n>: тетраэдры разбиения разной ориентации (вывернутый элемент?)` |
| Закреплена компонента, которой нет при данном `dim` | `<ключевое слово>: DOF<X/Y/Z> закреплён, но dim=<d> - компонента отсутствует в модели, пропущено` |
| Узлы закрепления не SPH-частицы и не бусины | `*BOUNDARY_SPC_*: <N> узлов не являются ни SPH-частицей, ни бусиной нити - закрепление пропущено` |
| PID таблицы деталей отсутствует в `.k` | см. [Таблица деталей](k-parts.md) |

## Поле `MASS` в `*ELEMENT_SPH`

Для SPH-элемента (поля `NID` - **номер узла**, `PID`, `MASS`, `NEND`):

- `MASS > 0` в `*ELEMENT_SPH`: масса частицы, умножается на `k_mass_scale`;
- `MASS < 0` в `*ELEMENT_SPH` или любое ненулевое `MASS` в `*ELEMENT_SPH_VOLUME`: объём; масса = `|MASS| * k_length_scale^dim * rho(PID)`, где `rho` из таблицы деталей, `dim` - `SPH_DIM` сборки, `k_mass_scale` не применяется. При `dim < 3` это «объём» в смысле конвенции проекта (площадь или длина), а не геометрический объём;
- `MASS = 0` или пусто: ошибка.

```text
*ELEMENT_SPH
1, 1, 0.0628
*ELEMENT_SPH
2, 2, -1.0e-6
*ELEMENT_SPH_VOLUME
3, 2, 1.0e-6
```

Узлы 2 и 3 получат массу `1.0e-6 * k_length_scale^dim * rho[PID 2]`. Частицы идут в порядке записей в файле (с учётом `*INCLUDE`).

## `NEND` - развёртка диапазона узлов

Если `NEND` задан и не меньше `NID`, запись разворачивается в частицы для узлов `NID`, `NID+1`, ..., `NEND` (по коду - **включительно**; включительность не сверена с мануалом), все с одинаковыми `PID` и `MASS`:

```text
*ELEMENT_SPH
1, 1, 0.0628, 10
```

Это 10 частиц для узлов 1..10 с массой 0.0628. Все эти узлы должны быть описаны в `*NODE`. `NEND = 0`, пусто или равный `NID` - одна частица.

## Нити из `*ELEMENT_BEAM` (режим `solid_fiber`)

Нить - связная компонента графа «узел - балка» (рёбра по N1, N2; узел ориентации N3 игнорируется), являющаяся простой незамкнутой цепочкой. Нити идут в порядке первой балки в файле; обход каждой нити начинается с конца с меньшим NID. Требуется `SPH_DIM=3`, таблица деталей с `FIBER_PART` для PID балок и `MATERIAL` для них. Координаты бусин умножаются на `k_length_scale`; масса бусин считается по материалу нити (`k_mass_scale` не действует).

Ошибки (с префиксом `<файл>:<строка>: `, где применимо):

| Условие | Сообщение |
|---|---|
| Нет балок в режиме `solid_fiber` | `в режиме solid_fiber нет ни одной нити (нет *ELEMENT_BEAM)` |
| `N1 == N2` | `*ELEMENT_BEAM EID <n>: N1 == N2 (NID <n>)` |
| Повтор ребра (пара узлов) | `дубликат ребра (узлы <a>, <b>): уже в балке EID <n> (…)` |
| Узел в трёх и более балках | `ветвление нити: узел NID <n> принадлежит <k> балкам (допустимо не более 2)` |
| Замкнутое кольцо | `замкнутое кольцо из балок (узел NID <n>), нить должна быть незамкнутой цепочкой` |
| Балки одной нити с разными PID | `нить из балок с разными PID: <a> и <b> (первая балка: …)` |
| PID нити без `FIBER_PART` | `PID <n> из … не описан в FIBER_PART` |

```text
*ELEMENT_BEAM
1, 5, 10, 11
2, 5, 11, 12
3, 5, 12, 13
```

Это одна нить из бусин в узлах 10-11-12-13 (3 сегмента, 4 бусины), PID 5. Материал нити берётся из таблицы деталей по `FIBER_PART 5 <id>`.

## Закрепления

`*BOUNDARY_SPC_NODE` и `*BOUNDARY_SPC_SET` превращаются в маски зажимов (`model.clamps.solid_mask` для SPH-частиц, `model.clamps.fiber_mask` для бусин нитей) функцией [`apply_spc_clamps()`](../../../include/k_input/k_geometry.hpp). Для узла из закрепления в маску записываются биты компонент, у которых `DOFX/DOFY/DOFZ` не равен нулю и номер компоненты меньше `dim`; вращательные `DOFRX/DOFRY/DOFRZ` читаются, но не используются. `CID` должен быть 0. Повторные закрепления одного узла объединяются по OR. Если ни одного бита не установлено, маска остаётся пустой.

```text
*BOUNDARY_SPC_NODE
100, 0, 1, 1, 0, 0, 0, 0
*SET_NODE_LIST
1
100, 101, 102
*BOUNDARY_SPC_SET
1, 0, 0, 0, 1, 0, 0, 0
```

Первый блок закрепляет по X и Y узел 100. Второй задаёт набор 1 из узлов 100, 101, 102, третий закрепляет по Z все узлы набора.

## `*ELEMENT_SOLID` как частицы

При `k_solid_elements = particles` (нужны `SPH_DIM=3` и таблица деталей) каждый элемент (4 узла; 8 узлов, если любое из N5..N8 не нуль; 10 узлов в формате `(ten nodes format)`) даёт одну частицу в центре масс с `mass = rho * V`, `hsml = 2 * V^(1/3)` (если нет `hsml=` в таблице), `body = PID`. Гексаэдр режется на 6 тетраэдров. Такие частицы идут **после** всех SPH-частиц, в порядке файла. Иначе элементы пропускаются с предупреждением, но проверки ссылок (узлы, PID в `*PART`) выполняются всегда.

## Единицы

`k_length_scale` умножает координаты всех узлов (SPH, балки, `*ELEMENT_SOLID`), `k_mass_scale` - поле `MASS` у SPH-элементов с `MASS > 0` (см. выше). Значения в таблице деталей (`rho`, `hsml`, `v=`, параметры `MATERIAL`) задаются сразу в СИ и масштабированию не подвергаются.

## Проверка размерности

Если `SPH_DIM < 3`, для SPH-узлов проверяются «лишние» координаты: при `dim = 2` - `z`, при `dim = 1` - `y` и `z`. Допуск `1e-9 * ext`, где `ext` - наибольший размах габарита по трём осям (в метрах после масштабирования). Если `|координата|` превышает допуск, ошибка с NID и значением. Молча отбросить координату нельзя.

## Сводка при загрузке

После успешной загрузки `input()` печатает сводку (шаблон; числа условные):

```text
 ******************************
 Импорт LS-DYNA .k: file.k (режим solid)
 Узлов в колоде <N>
 Частиц: SPH <N>, из солидов <N>
 Габарит SPH, м: x [<min>, <max>], y [<min>, <max>], z [<min>, <max>]
 dx_median, м: <значение>
 Предупреждение: <текст>
 Пропущено MAT_ELASTIC: <число блоков>
 ******************************
```

`dx_median` - медиана $(m/\rho)^{1/\dim}$; без таблицы деталей равна 0. Если есть нити, добавляются строки `Нитей <N>, бусин <N>, связей <N>` и `Сегмент l0, м: [<min>, <max>], l/d: [<min>, <max>]`. Если есть закрепления, добавляется `Зажато частиц <N>, бусин <N>`. Имя пропущенного ключевого слова печатается заглавными без `*`, число - количество блоков. Если задан `fiber_file`, после этого печатается строка `Нити из <файл>: бусин …, связей …, нитей …`.

Реальный образец - файл `1.k` в корне репозитория: free-format, в каждой строке `*ELEMENT_SPH` три поля через запятую, два `*PART`, заголовок `$#` вверху.

## Подготовка файла

1. Выгрузите модель из LS-PrePost в `.k`; надёжно проверен free-format.
2. В файле должны быть `*NODE`, `*PART` для каждого PID и `*ELEMENT_SPH` (или `*ELEMENT_BEAM` для нитей).
3. NID в `*NODE`, NID в `*ELEMENT_SPH` и EID в `*ELEMENT_BEAM` должны быть уникальны.
4. Подготовьте [таблицу деталей](k-parts.md) с `SOLID_PART` для каждого PID из `*ELEMENT_SPH` (и `FIBER_PART` для балок в режиме `solid_fiber`).
5. Выберите режим: `k_mode = solid` или `k_mode = solid_fiber`.
6. Если `.k` в миллиметрах, задайте `k_length_scale = 1e-3`.
