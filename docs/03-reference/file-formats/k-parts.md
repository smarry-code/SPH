# Таблица деталей для импорта `.k`

Текстовый sidecar-файл, который привязывает PID деталей из LS-DYNA `.k` файла к физике проекта. Путь задаётся ключом `k_parts_file` в `Initial_Conditions.txt` (см. [Конфигурация](../config/initial-conditions.md)). Формат самого `.k` - в [Формат `*.k`](k-file.md).

## Назначение

Файл `.k` даёт геометрию и PID. Физика детали (материал проекта, плотность, начальная скорость, параметры нити) в него не берётся из `*MAT_*`/`*SECTION_*`: эти блоки пропускаются. Причины, по плану импорта:

- `itype` проекта (номер материала частицы) с `*MAT_*` LS-DYNA напрямую не сопоставляется;
- у нити есть параметры (`eps_break`, `mu_ff`, `mu_fs`), которых в `.k` нет;
- единицы в `.k` произвольны, для них есть `k_length_scale` и `k_mass_scale`.

## Синтаксис

- Одна директива на строку, поля разделяются пробельными символами.
- `#` начинает комментарий до конца строки (в любом месте строки).
- Пустые строки пропускаются.
- Имена директив и именованных параметров регистрозависимы.
- Любая ошибка - исключение с текстом `<файл>:<строка>: <сообщение>` (строка 1-based).

Директивы: `SOLID_PART`, `MATERIAL`, `FIBER_PART`. Любое другое первое слово - ошибка `неизвестная директива '<слово>'`.

## Директивы

### `SOLID_PART`

Описывает Solid-деталь (SPH-элементы с этим PID).

```text
SOLID_PART <pid> <itype> <rho> [hsml=<h>] [v=<vx> [<vy> [<vz>]]]
```

| Параметр | Обязателен | Описание |
|---|---|---|
| `pid` | да | PID детали (целое) |
| `itype` | да | Номер материала проекта, целое от 1 до 15 |
| `rho` | да | Плотность, кг/м³, конечное число > 0 |
| `hsml=<h>` | нет | Длина сглаживания, м, > 0. Без него `hsml = 2*dx` на каждой частице (см. ниже) |
| `v=<vx> [<vy> [<vz>]]` | нет | Начальная скорость, м/с: от одной до трёх компонент, следующие за `v=` числа читаются, пока не встретится токен с `=` |

Именованные параметры идут после `rho` в любом порядке, каждый не более одного раза.

**Значения `itype`** (по `include/materials.hpp` и `urs()` в [`int_force.cpp`](../../../src/int_force.cpp)):

| itype | Материал | УРС в `urs()` |
|---|---|---|
| 1 | идеальный газ | `p_gas` |
| 2 | вода | `p_art_water` |
| 3 | тантал | Ми-Грюнайзен |
| 4 | алюминий | Ми-Грюнайзен |
| 5 | LiF | Тэт |
| 6 | полиуретан 160 | Тэт |
| 7 | полиуретан 320 | Тэт |
| 8 | полиуретан 626 | Тэт |
| 9 | PMMA | Тэт |
| 10 | B4C | JH-2 |
| 11 | Al2O3 | JH-2 |
| 12 | STEEL 4340 (Джонсон-Кук) | Linear |
| 13 | STEEL 1006 (Джонсон-Кук) | Shock (Ми-Грюнайзен) |
| 14 | AL 7039 (Джонсон-Кук) | Shock (Ми-Грюнайзен) |
| 15 | AL5083H116 (Джонсон-Кук) | Linear |

Материалы 12–15 описаны в [реестре](../materials/registry.md) и в
[how-to](../../02-how-to/06-johnson-cook-material.md).

**Примеры** (из плана импорта `readk/k-import-plan.md`):

```text
SOLID_PART 1 7  320  v=1546 0 0   # ударник, полиуретан 320
SOLID_PART 2 10 2510              # керамика B4C
SOLID_PART 4 5  2638              # окно LiF
SOLID_PART 3 10 2510 hsml=0.0002  # то же с заданной длиной сглаживания
```

### `MATERIAL`

Материал нити (нужен в режиме `solid_fiber`).

```text
MATERIAL <id> <E> <nu> <d> <rho> <eps_break> [mu_ff [mu_fs]]
```

Синтаксис и разбор те же, что у директивы `MATERIAL` в файле `.fib`: используется общая функция `parse_material_directive` из [`fiber_input.cpp`](../../../src/fiber_input.cpp). Поля: `id` (целое >= 0), `E` (модуль Юнга), `nu` (коэффициент Пуассона), `d` (диаметр волокна), `rho` (плотность), `eps_break` (деформация разрыва), необязательные `mu_ff` (трение нить-нить) и `mu_fs` (трение нить-Solid), по умолчанию 0, каждое >= 0.

!!! note "Что парсер не проверяет"
    Разбор `MATERIAL` проверяет только формат строки, `id >= 0` и `mu_ff, mu_fs >= 0`. Диапазоны `nu`, `d`, `rho`, `eps_break` и верхняя граница `id` при разборе таблицы не проверяются.

Пример (строка из плана импорта):

```text
MATERIAL 0 2.0e9 0.35 1.0e-4 1140 0.02
```

### `FIBER_PART`

Деталь из балок `*ELEMENT_BEAM` становится нитями с указанным материалом.

```text
FIBER_PART <pid> <material_id>
```

| Параметр | Описание |
|---|---|
| `pid` | PID из `*ELEMENT_BEAM` (целое) |
| `material_id` | `id` директивы `MATERIAL`, целое от 0 до 1000000 |

Директива `MATERIAL` может стоять как до, так и после `FIBER_PART`: ссылки проверяются после чтения всего файла.

```text
FIBER_PART 5 0
```

## Вычисляемые поля частицы

Для SPH-частицы детали:

- `itype`, `rho`, `rho_0` - из `SOLID_PART` (`rho_0 = rho`);
- `body = PID`: детали с одинаковым `itype` остаются разными телами;
- начальная скорость - из `v=` (не заданные компоненты 0). Компонента с номером не меньше `dim` и не равная нулю - ошибка `v= задаёт ненулевую компоненту <n> при dim=<dim>`; нулевые лишние компоненты допускаются;
- `hsml` - значение `hsml=`, если задано, иначе
  $$h_i = 2\left(\frac{m_i}{\rho_i}\right)^{1/\dim},$$
  где $m_i$ - масса частицы после масштабирования (см. «Поле `MASS`» в [Формат `*.k`](k-file.md)), $\rho_i$ - плотность из `SOLID_PART`, `dim` - `SPH_DIM` сборки. Это конвенция проекта `hsml = 2*dx`;
- затем для каждой частицы вызывается `urs()`, заполняющая давление и скорость звука.

## Ошибки разбора таблицы

Тексты ниже даны с точностью до подставляемых значений; к каждому добавляется префикс `<файл>:<строка>: `.

| Условие | Сообщение |
|---|---|
| Неизвестная директива | `неизвестная директива '<слово>'` |
| `SOLID_PART` без трёх обязательных полей | `SOLID_PART: ожидается <pid> <itype> <rho>` |
| `pid`, `itype` не целые; `rho` не конечное число | `SOLID_PART: PID не целое: '…'`, `SOLID_PART: itype не целое: '…'`, `SOLID_PART: rho не конечное число: '…'` |
| `itype` вне 1..15 | `SOLID_PART: itype=<значение> вне диапазона 1..15` |
| `rho` не больше нуля | `SOLID_PART: rho должно быть > 0` |
| `hsml=` не число / не больше нуля / повторён | `SOLID_PART: hsml= не конечное число: '…'`, `SOLID_PART: hsml должно быть > 0`, `SOLID_PART: hsml= повторяется` |
| `v=` повторён / без значений / нечисловое значение | `SOLID_PART: v= повторяется`, `SOLID_PART: v= без значений`, `SOLID_PART: v= нечисловое значение: '…'` |
| Лишний или неизвестный токен (в том числе четвёртая компонента `v=`) | `SOLID_PART: лишний или неизвестный токен '…'` |
| `FIBER_PART` без двух полей | `FIBER_PART: ожидается <pid> <material_id>` |
| `FIBER_PART`: `pid` не целое; `material_id` не целое или вне 0..1000000; лишний токен | `FIBER_PART: PID не целое: '…'`, `FIBER_PART: неверный material_id: '…'`, `FIBER_PART: лишний токен '…'` |
| PID уже есть в `SOLID_PART` или `FIBER_PART` | `повтор PID <pid>` |
| Неверный формат `MATERIAL` | `k_parts: неверный формат MATERIAL в строке <n>` (после префикса файла и строки) |
| `FIBER_PART` ссылается на необъявленный `MATERIAL` | `FIBER_PART ссылается на необъявленный MATERIAL <id>` (строка самого `FIBER_PART`) |

## Сверка с `.k` файлом

После чтения обоих файлов:

| Условие | Результат |
|---|---|
| PID из `*ELEMENT_SPH` нет в `SOLID_PART` | Ошибка: `<таблица>: PID <pid> из *ELEMENT_SPH (<файл>:<строка>) не описан в SOLID_PART` |
| PID из `*ELEMENT_BEAM` нет в `FIBER_PART`, режим `solid_fiber` | Ошибка: аналогично, `… не описан в FIBER_PART`. В режиме `solid` балки не сверяются |
| PID из `*ELEMENT_SOLID` нет в `SOLID_PART`, при `k_solid_elements = particles` | Ошибка: `… из *ELEMENT_SOLID (…) не описан в SOLID_PART` |
| PID из таблицы не встречается ни в `*ELEMENT_SPH`, `*ELEMENT_BEAM`, `*ELEMENT_SOLID`, ни в `*PART` | Предупреждение `<таблица>:<строка>: SOLID_PART PID <pid> отсутствует в .k` (или `FIBER_PART …`); загрузка продолжается |

Предупреждения выводятся в сводке импорта строками `Предупреждение: …`.

## Пример файла

```text
# Таблица деталей (значения из плана импорта)
SOLID_PART 1 7  320  v=1546 0 0
SOLID_PART 2 10 2510
SOLID_PART 3 10 2510
SOLID_PART 4 5  2638

# нити (только в режиме solid_fiber)
MATERIAL 0 2.0e9 0.35 1.0e-4 1140 0.02
FIBER_PART 5 0
```

## Когда нужна таблица

### Режим `solid`

Таблица необязательна. Если `k_parts_file` пуст, для каждой частицы заполняются только координаты, масса, `itype = PID` и `body = PID`; `rho`, `hsml` и прочие поля остаются нулями, `urs()` не вызывается. Масса `MASS < 0` или из `*ELEMENT_SPH_VOLUME` без таблицы - ошибка (нужна плотность). Начальный шаг по CFL без `hsml` и скорости звука не определён, `dt` остаётся прежним. Для осмысленного расчёта таблицу следует задавать.

### Режим `solid_fiber`

Таблица обязательна: без `k_parts_file` загрузка прерывается ошибкой `k_mode=solid_fiber требует таблицу деталей (k_parts_file)`. Каждый PID из `*ELEMENT_SPH` должен иметь `SOLID_PART`, каждый PID из `*ELEMENT_BEAM` - `FIBER_PART` с объявленным `MATERIAL`.

## Связь с конфигурацией

```text
k_file = geometry/impact.k
k_mode = solid_fiber
k_parts_file = geometry/impact_parts.txt
k_length_scale = 1.0
k_mass_scale = 1.0
```

Допустимые сочетания источников:

| Solid | Нити | Ключи |
|---|---|---|
| `.k` | нет | `k_file`, `k_mode=solid`, `k_parts_file` |
| `.k` | `.fib` | `k_file`, `k_mode=solid`, `k_parts_file`, `fiber_file` |
| `.k` | из балок | `k_file`, `k_mode=solid_fiber`, `k_parts_file` |

Формат сводки, печатаемой после загрузки, описан в разделе «Сводка при загрузке» страницы [Формат `*.k`](k-file.md).
