# Формат `Initial_Conditions.txt`

Текстовый файл конфигурации расчёта. Разбирается функцией
[`parse_sph_config()`](../../../src/input.cpp:110) (объявление — в
[`input.hpp`](../../../include/input.hpp:13)) и заполняет поля
[`SimulationConfig`](../../../include/simulation_config.hpp:31).

## Общие правила синтаксиса

- Одна директива на строку в формате `ключ = значение`.
- Пробелы вокруг `=` и по краям строки игнорируются.
- Пустые строки пропускаются.
- Строки, начинающиеся с символа `*`, трактуются как **комментарии** и игнорируются.
- Строки без знака `=` и строки с пустым ключом или пустым значением пропускаются.
- Если файла нет, `parse_sph_config` не выдаёт ошибки: расчёт идёт на значениях по умолчанию.
- Ключи, отсутствующие в файле, сохраняют значения по умолчанию из
  [`SimulationConfig::apply_defaults()`](../../../include/simulation_config.hpp:189).
- Неизвестные ключи игнорируются.

## Импорт геометрии из LS-DYNA `.k` файла

Если задан `k_file`, начальная геометрия читается из файла вместо встроенных генераторов. Ключи `k_*` управляют импортом (см. [Формат `*.k`](../file-formats/k-file.md) и [Таблица деталей](../file-formats/k-parts.md)).

!!! warning "Комментарии в `Initial_Conditions.txt`"
    Разбор строки - только `ключ = значение`: значением считается всё после первого `=` до конца строки. Комментария после значения не существует (`k_length_scale = 1e-3  # мм` даёт ошибку, а `k_file = a.k  * вот` - путь `a.k  * вот`). Комментарий - только отдельная строка, начинающаяся с `*`.

### Режимы импорта

| Режим | Ключи | Что загружается | Таблица деталей |
|---|---|---|---|
| Solid | `k_file`, `k_mode = solid` | SPH-частицы из `*ELEMENT_SPH` (балки пропускаются с предупреждением) | Необязательна |
| Solid + Fiber | `k_file`, `k_mode = solid_fiber` | SPH из `*ELEMENT_SPH` + нити из `*ELEMENT_BEAM`; только `SPH_DIM=3` | Обязательна |
| Solid + внешние нити | `k_file`, `k_mode = solid`, `fiber_file` | SPH из `.k` + нити из `.fib`; только `SPH_DIM=3` | Необязательна |

### Примеры конфигурации

Только SPH из `.k` (режим `solid`, файл в миллиметрах):

```text
k_file = geometry/impact.k
k_mode = solid
k_parts_file = geometry/impact_parts.txt
k_length_scale = 1e-3
```

SPH и нити из балок (режим `solid_fiber`, сборка с `SPH_DIM=3`):

```text
k_file = geometry/fabric.k
k_mode = solid_fiber
k_parts_file = geometry/fabric_parts.txt
```

SPH из `.k` и нити из отдельного файла:

```text
k_file = geometry/structure.k
k_mode = solid
k_parts_file = geometry/structure_parts.txt
fiber_file = geometry/weave.fib
```

### Начальный шаг по времени

При непустом `k_file` `main()` после загрузки пересчитывает начальный шаг по критерию Куранта ([`compute_cfl_timestep()`](../../../src/time_integration.cpp)):

$$\Delta t = \mathrm{CFL} \cdot \min_i \frac{h_i}{c_i + |\mathbf v_i|}$$

Здесь $h_i$ - `hsml` частицы (из `hsml=` в `SOLID_PART` или $2\,(m_i/\rho_i)^{1/\dim}$), $c_i$ - скорость звука, вычисленная `urs()` по `itype` и `rho`, $\mathbf v_i$ - начальная скорость (`v=` в таблице деталей). Новое значение принимается, только если оно конечно и больше нуля. Без таблицы деталей `hsml` и `c` нулевые, шаг не определён, и `dt` остаётся прежним (дальше цикл пересчитывает его сам на каждом шаге).

### Несовместимые сочетания

- `k_mode=solid_fiber` вместе с `fiber_file` - ошибка `k_mode=solid_fiber вместе с fiber_file: два источника нитей` (проверяется независимо от `k_file`);
- `k_file` при `config_input = true` в [`param.hpp`](../../../include/param.hpp) (compile-time константа, не ключ файла) - ошибка `k_file несовместим с config_input (загрузка particles.dat)`;
- `k_file` вместе с `shocktube`/`shearcavity` (тоже compile-time флаги `param.hpp`) - не ошибка: при непустом `k_file` встроенные генераторы не вызываются.

### Побочный эффект `sle = 1`

`update_smoothing_length` вызывается из `time_integration` сразу после `single_step()` ([`time_integration.cpp:457`](../../../src/time_integration.cpp:457)), поэтому длина
сглаживания, выставленная при построении геометрии, живёт ровно один шаг и затем
заменяется значением $1.3\,(m/\varrho)^{1/\dim}$.

Практическое следствие: если построитель ставит `hsml = 2*delta_x`, рабочее
значение всё равно равно $1.3\Delta x$, а носитель кубического сплайна —
$2.6\Delta x$, а не $4\Delta x$. Любое рассуждение о радиусе носителя (ширина
фронта, момент начала взаимодействия тел, размер зазора между телами) надо вести
от фактического $h$, а не от того, что записала геометрия. На этой ошибке было
построено обоснование зазора удара 1.000 мм в кейсе BC6, впоследствии снятое.

### Что из этого измерено

Полные прогоны BC6 (`contact_force_type = 0`, $\Delta x = 0.2$ мм, 44 638 частиц).
«Фронт» — подъём осевой скорости монитора 10–90 %; RMS — отклонение от приборного
эталона после совмещения по переднему фронту.

| Что меняли | Результат |
|---|---|
| `epsilon` 0.25 → 0.05 | Фронт короче на 1 %. Расчёт разваливается: $\varrho < 0$ в частице B4C на 3.27 мкс |
| `epsilon` 0.25 → 0 | То же, развал на 2.74 мкс |
| `alpha` 1.0 → 0.5 | Фронт 328 → 303 нс; RMS 22.5 → 26.9 м/с (**хуже**) |
| `alpha` 1.0 → 0.3, `beta` → 0.6 | Фронт 328 → 290 нс; RMS 22.5 → 29.8 м/с (**хуже**) |

Вывод по XSPH: в зоне откола `epsilon` — несущий элемент схемы, а не тюнинговая
ручка. Вывод по псевдовязкости: снижение `alpha` даёт по фронту около 12 % и
одновременно ухудшает согласие на остальной кривой.

### Тихие отказы

Значения ниже проходят разбор без ошибки и дают внешне нормальный расчёт с
неожиданной физикой.

| Условие | Что произойдёт |
|---|---|
| `nnps` любое | Ключ не используется конвейером (см. таблицу выше); `nnps = 3` больше не «заглушка» с пустым списком пар, расчёт идёт как при 1 или 2 |
| `pa_sph` вне {1, 2} | Ветка `else` в [`solid_sph.hpp:895`](../../../include/interactions/solid_sph.hpp:895) помечена как `pa_sph == 2`: любое другое значение считается как 2 |

### Откуда взяты текущие значения

Девять параметров метода в кейсах BC2 и BC6 перенесены **как есть** из архивных
`Initial_Conditions.txt` исходных опытов и под задачу не калибровались. Проверка
постфактум (см. «Что из этого измерено») показала, что `epsilon` понижать нельзя,
`alpha` менять бессмысленно, а остальные семь соответствуют назначению.
