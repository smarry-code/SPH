# ADR-006: Graph coloring для устранения `#pragma omp atomic`

**Статус:** Принято
**Дата:** Этап параллелизма (фаза B)

## Контекст

В парных циклах SPH накопление вкладов в поля частиц (`dvxdt`, `dvydt`, ...)
выполняется операцией `+=`. Разные пары, обрабатываемые разными потоками
одновременно, могут ссылаться на одну частицу (пара `(3,7)` и пара `(3,9)` пишут
в `dvxdt[3]`). Операция `+=` неатомарна и защищалась
`#pragma omp atomic update`, что создавало узкое место параллелизма: конкуренцию
за cache-line и блокировку SIMD-векторизации.

## Решение

Введён инфраструктурный модуль [`PairGraph`](../../../include/pair_graph.hpp:53),
реализующий:

1. CSR-представление пар по частицам (`pair_offset`, `pair_csr`);
2. жадную окраску графа конфликтов;
3. унифицированный обход пар по цветам.

Пары одного цвета **не имеют общих частиц** ⇒ каждый индекс модифицируется
ровно одной парой данного цвета ⇒ конкурентной записи нет ⇒ `atomic` не нужен.

Реализован условный путь через порог
[`coloring_niac_threshold`](../../../include/simulation_config.hpp:33):

- `niac >= threshold` → `graph.build()` + обход по цветам (`AccPlain`);
- иначе → `atomic`-ветвь потребителей (`AccAtomic`).

Тело парного цикла пишется один раз (шаблонная лямбда) и инстанцируется для
обоих аккумуляторов — нет дублирования логики и нет накладных расходов в
runtime.

## Последствия

**Положительные:**

- Устранены `#pragma omp atomic` в парных циклах при активном coloring;
- Разблокирована SIMD-векторизация и улучшена локальность;
- Унифицированный интерфейс обхода пар для всех потребителей.

**Отрицательные:**

- Дополнительная память под CSR и окраску;
- Накладные расходы на `build()` (один раз за шаг);
- При малых `niac` выигрыш от coloring незначителен (поэтому используется
  порог).
