# Из LS-PrePost в расчёт

Как взять геометрию из LS-DYNA keyword-файла (`.k`, например экспорт
LS-PrePost) и запустить по ней расчёт `SPH`. Справочники:
[формат `.k`](../03-reference/file-formats/k-file.md),
[таблица деталей](../03-reference/file-formats/k-parts.md),
[ключи `Initial_Conditions.txt`](../03-reference/config/initial-conditions.md).

## 1. Что должно быть в `.k`

- `*NODE` — координаты узлов;
- `*ELEMENT_SPH` — SPH-частицы (узел = частица), каждая с PID детали;
- `*PART` на каждый используемый PID;
- для нитей (режим `solid_fiber`) — `*ELEMENT_BEAM`: каждая нить — простая
  незамкнутая цепочка 2-узловых балок одного PID;
- по желанию — `*BOUNDARY_SPC_NODE` / `*BOUNDARY_SPC_SET` (зажимы) и
  `*ELEMENT_SOLID` (переводится в частицы при `k_solid_elements = particles`).

Материалы, сечения и прочие `*MAT_*`, `*SECTION_*`, `*CONTROL_*` читатель
пропускает (со сводкой). Физику деталей задаёт таблица деталей (шаг 2).

!!! warning "Формат строк"
    Надёжно проверен только free-format (значения через запятую), которым
    пишет LS-PrePost (так записан корневой `1.k`). Ширины полей fixed/long
    взяты из спецификации и не сверены с официальным мануалом LS-DYNA.

Единицы в `.k` не хранятся. Если модель в мм/г и т. п., задайте масштабы
`k_length_scale` и `k_mass_scale` (шаг 3); значения в таблице деталей — сразу в СИ.

## 2. Таблица деталей

Текстовый файл рядом с `.k` (`#` — комментарий). Каждому PID из
`*ELEMENT_SPH` нужна строка `SOLID_PART`, каждому PID балок в режиме
`solid_fiber` — `FIBER_PART`:

```text
# SOLID_PART <PID> <itype> <rho> [hsml=<h>] [v=<vx> <vy> <vz>]
SOLID_PART 1 7  320  v=1546 0 0   # ударник, полиуретан 320
SOLID_PART 2 10 2510              # керамика B4C
SOLID_PART 3 10 2510              # керамика B4C, второе тело
SOLID_PART 4 5  2638              # окно LiF
# нити: MATERIAL — тот же синтаксис, что в .fib
MATERIAL 0 2.0e9 0.35 1.0e-4 1140 0.02
FIBER_PART 5 0
```

`itype` — номер материала проекта (`include/materials.hpp`), `body` частицы
= PID. Подробности и все проверки — в [справочнике](../03-reference/file-formats/k-parts.md).

## 3. `Initial_Conditions.txt`

К обычным параметрам решателя (возьмите за основу, например,
`tests/data/guo2019_initial_conditions.txt`) добавьте ключи импорта.
Строки, начинающиеся с `*`, — комментарии; комментарий в конце строки со
значением **не допускается** (он станет частью значения).

```text
* Геометрия из LS-DYNA .k
k_file = model.k
k_mode = solid
k_parts_file = model.parts
* модель в миллиметрах
k_length_scale = 1.0e-3
* необязательно: NID узла мониторной частицы
k_monitor_nid = 100
* расчёт
t_total = 3.0e-6
save_t = 2.5e-8
```

- Значения по умолчанию ([`SimulationConfig`](../../include/simulation_config.hpp:127)): `k_mode = solid`,
  `k_solid_elements = skip`, `k_length_scale = k_mass_scale = 1`, `k_monitor_nid = -1` (не задан).
  Масштабы должны быть положительными, неверное значение режима — ошибка разбора.
- `k_mode = solid_fiber` — нити из `*ELEMENT_BEAM`; нужен `SPH_DIM=3`.
- Нити можно взять и из `.fib`: `k_mode = solid` + `fiber_file = cloth.fib`.
  `solid_fiber` вместе с `fiber_file` — ошибка (два источника нитей).
- `k_file` имеет приоритет над встроенными генераторами (`shocktube`,
  `shearcavity`); начальный шаг по времени для `.k` берётся по CFL.

## 4. Сборка с нужной размерностью

Размерность исполняемого `SPH` задаёт CMake-параметр `SPH_DIM` (по умолчанию
1). Для 3D-модели и для нитей нужен 3:

```bash
cmake --preset clang-windows -DSPH_DIM=3
cmake --build build --target SPH
```

При `SPH_DIM=2` все узлы SPH-частиц должны лежать в плоскости `z = 0`, при
`SPH_DIM=1` — на оси x (с относительным допуском `1e-9` от габарита), иначе
импорт завершится ошибкой с NID узла.

## 5. Запуск и сводка

Запускайте `SPH` из каталога, где лежат `Initial_Conditions.txt`, `.k` и
таблица деталей (пути в ключах — относительно этого каталога). Перед
расчётом печатается сводка импорта, например:

```text
 Импорт LS-DYNA .k: deck.k (режим solid_fiber)
 Узлов в колоде 40
 Частиц: SPH 32, из солидов 0
 Габарит SPH, м: x [0, 0.003], y [0, 0.003], z [0, 0.001]
 dx_median, м: 0.001
 Нитей 2, бусин 8, связей 6
 Сегмент l0, м: [0.001, 0.001], l/d: [10, 10]
```

Проверьте габарит в метрах (масштаб единиц), число частиц и нитей, строки
`Предупреждение:` (пропущенные балки/солиды, зажимы на узлах без роли) и
`Пропущено …` (ключевые слова, которые не читаются).

Результаты пишутся в текущий каталог: `sph_output_NNNNN.txt` (Solid),
`fiber_output_NNNNN.txt` (нити, если есть), `sph_gp.csv`, `log.txt`.

## 6. Частые ошибки

Любая ошибка импорта печатается как `Ошибка: <файл>:<строка>: …` и
завершает программу с кодом 1.

| Симптом | Что сделать |
|---|---|
| PID не описан в `SOLID_PART` / `FIBER_PART` | добавить строку в таблицу деталей |
| `*PARAMETER не поддерживается` (`&имя` в поле) | подставить числа при экспорте |
| опции `*ELEMENT_BEAM_*` / `*ELEMENT_SOLID_*` не поддерживаются | экспортировать без опций |
| ветвление нити / замкнутое кольцо | разбить на простые незамкнутые цепочки |
| лишняя координата при `dim<3` | собрать с правильным `SPH_DIM` или выровнять модель |
| «Нити (fiber_file) заданы в конфигурации, но сборка выполнена с SPH_DIM=…» | пересобрать с `-DSPH_DIM=3` |
