# Генератор полотняного переплетения

Генератор `plain_weave_gen` создаёт ткань полотняного переплетения в формате файла нитей (`.fib`), который загружается в симулятор как отдельная геометрия.

## Сборка

```bash
cmake --build <build> --target plain_weave_gen
```

Например:

```bash
cmake --build build --target plain_weave_gen
```

## Основные концепции

Генератор строит ткань в плоскости x–y с толщиной по оси z. **Основа** (warp) идёт вдоль оси x, **уток** (weft) вдоль оси y. В каждом пересечении нити контактируют волнистостью — основа и уток чередуют верхнее и нижнее положение.

Сгенерированный файл содержит:
- **`.fib`** — координаты нитей (бусин и связи между ними)
- **`.layout.txt`** — раскладка: метаданные о каждой нити

## Дискретизация

Бусины ставятся точно в каждое пересечение, между пересечениями — равные хорды:

- **На полуволне:** ровно **k** сегментов (связей) одинаковой длины, бусины стоят в вершинах (пересечениях).
- **Выступ:** делится на `max(1, round(e/(p/k)))` сегментов, отдельно по направлениям.
- Длины связей l₀ в пределах полуволны (и выступа) совпадают до ~10⁻¹⁵ относительно. Это равные хорды, а не равные дуги: в модели связь — хорда.

## Зажим (CLAMP_BOX)

Параметр `--clamp` задаёт, какие нити закреплены с обоих концов:

- `--clamp=x` — нити вдоль x (горизонтальные)
- `--clamp=y` — нити вдоль y (вертикальные)
- `--clamp=xy` — обе группы
- `--clamp=none` — нет зажима (по умолчанию)

При `--clamp ≠ none` **обязателен** параметр `--clamp-edge=<м>` (граница зажима c_e). Генератор пишет две директивы `CLAMP_BOX` в `.fib`, по одной на каждый конец, с полным охватом по осям (допуск d).

Допустимый диапазон c_e:
- Нижняя граница: `c_e ≥ (n_поперечных - 1) / 2 · p + d/2` (не попасть в пересечения)
- Верхняя граница: `c_e ≤ (n_поперечных - 1) / 2 · p + e` (хотя бы одна зажатая бусина на конце)

Если бусина попадает в зажим близко к границе c_e (в пределах 10⁻⁹·p), печатается предупреждение.

## Формат раскладки

Файл `<out>.layout.txt` содержит одну строку на нить:

```
object_id direction index offset clamped first_bead last_bead n_clamp_lo n_clamp_hi
```

- `object_id` — номер нити (0..nx-1 основа, nx..nx+ny-1 уток)
- `direction` — `x` (основа) или `y` (уток)
- `index` — индекс в направлении (0..nx-1 или 0..ny-1)
- `offset` — координата, перпендикулярная направлению (м)
- `clamped` — 1 если нить зажата, иначе 0
- `first_bead`, `last_bead` — глобальные индексы первой и последней бусин в файле `.fib`
- `n_clamp_lo`, `n_clamp_hi` — число зажатых бусин у начала и конца нити

## Известные ограничения

1. **Толщина полотна:** круглое сечение даёт толщину ≈2A + d, не реальную. Для пресета `twaron_ct717` это ≈0,78 мм против 0,4 мм в статье.

2. **Контакт в узлах при касании:** при 2A = d оси нитей в модели — хорды соседних бусин, а не гладкие кривые, и у узла хорды сближаются меньше чем на d. На исходной геометрии уже есть контакты: на геометрии Twaron 4 контакта (пары сегментов) на пересечение, проникание ≈9,6% d при k=2 и ≈3,8% d при k=4. При A = 0,6·d контактов на исходной геометрии нет (проверки 7/7б в `tests/test_plain_weave.cpp`).

3. **Плотность twaron_ct717:** 0,327 кг/м² против номинала 0,292 (статья: 0,28). Превышение складывается из удлинения нити волнистостью (хорды полуволны на ≈6% длиннее p) и выступов утка по 5 мм (+0,015 кг/м², ≈5%).

## Одеяло из патчей

Ткань-«одеяло» — прямоугольная сетка из `tile_x × tile_y` одинаковых патчей, каждый патч состоит из `patch_nx × patch_ny` нитей. Нити непрерывны через стыки патчей: соседние патчи не сшиваются отдельными связями, а образуют одну ткань. Геометрически результат совпадает с обычной тканью с `nx = tile_y·patch_nx` нитями основы и `ny = tile_x·patch_ny` нитями утка; шаг, профиль, выступы и зажим задаются так же, как для полной ткани.

Патчи одинаковы по построению. Сдвиг на один патч сохраняет фазу волны, если `patch_nx` и `patch_ny` чётны (см. правило нечётного патча ниже).

### Ключи

| Ключ | Смысл |
|---|---|
| `--patch=NXxNY` | Патч: `NX` нитей основы × `NY` нитей утка, например `34x34`. Размер патча вдоль x равен `NY·p`, вдоль y равен `NX·p` |
| `--tile=TXxTY` | Число патчей: `TX` вдоль x, `TY` вдоль y, например `3x3`. Ключи `--patch` и `--tile` задаются вместе |
| `--allow-odd-patch` | Разрешить нечётный размер патча при `tile > 1`. Без флага такой запуск завершается ошибкой, с флагом выводится предупреждение |

Ключи `--patch` и `--tile` несовместимы с `--nx` и `--ny`: при их наличии генератор выдаёт ошибку, потому что число нитей задаётся произведением `--tile` на `--patch`. `--allow-odd-patch` без `--patch` и `--tile` тоже ошибка. Остальные ключи (`--preset`, `--d`, `--pitch`, `--amp`, `--seg`, `--overhang-*`, `--clamp`, `--clamp-edge`, материал) действуют как обычно.

### Пример

```bash
./build/plain_weave_gen --preset=twaron_ct717 --patch=34x34 --tile=3x3 --out=quilt.fib
```

Три патча по 34 нити дают 3 · 34 = 102 нити в каждом направлении, то есть ту же ткань, что `--preset=twaron_ct717` без патчей. Шаг 1,18 мм, окно 101 · 1,18 = 119,18 мм. Размер одного патча 34 · 1,18 = 40,12 мм.

Генератор пишет три файла:

- `quilt.fib` — ткань целиком в формате `.fib` (одна `MATERIAL 0`, по блоку `FIBER` на нить);
- `quilt.fib.layout.txt` — раскладка нитей, тот же формат, что у обычной ткани (см. «Формат раскладки»);
- `quilt.fib.patches.txt` — принадлежность бусин патчам.

### Формат `.patches.txt`

Первые две строки — комментарии (`#`):

```text
# патчей 3x3 по 34x34 нитей (patch_nx x patch_ny); id патча = ty*tile_x + tx
# object_id direction index first_bead last_bead n_ranges {patch:first:last}...
```

Далее одна строка на нить, в порядке блоков `FIBER` в `.fib`:

```text
object_id direction index first_bead last_bead n_ranges patch:first:last [patch:first:last ...]
```

- `object_id`, `direction` (`x` — основа, `y` — уток), `index` — как в `.layout.txt`;
- `first_bead`, `last_bead` — глобальные индексы первой и последней бусины нити (с нуля, сквозной счёт по всему файлу);
- `n_ranges` — число отрезков нити, идущих подряд внутри одного патча;
- каждая тройка `patch:first:last` — id патча и глобальные индексы первой и последней бусины отрезка. Отрезки идут вдоль нити без пропусков и вместе покрывают все её бусины.

Идентификатор патча: `id = ty*tile_x + tx`, где `tx` — номер патча вдоль x (0 … TX−1), `ty` — вдоль y (0 … TY−1). Нить основы пересекает `TX` патчей (`n_ranges = TX`), нить утка — `TY` патчей.

Структура строки для нити основы в ряду `ty = 0` при `TX = 3`:

```text
0 x 0 <first> <last> 3 0:<a>:<b> 1:<b+1>:<c> 2:<c+1>:<last>
```

### Принадлежность бусин патчам (стыки)

Стык между патчами `t−1` и `t` вдоль x лежит посередине полуволны между вершинами `t·P − 1` и `t·P`, где `P = patch_ny`. Вдоль y — то же с `P = patch_nx`. Координата стыка:

```text
seam = c + (t·P − 1/2 − (n − 1)/2)·p,   n = ny (вдоль x) или nx (вдоль y)
```

Правила отнесения бусины к патчу:

- **Ряд вдоль нити** определяется координатой бусины относительно стыков. Бусина ровно на стыке (допуск `10⁻⁹·p`) относится к патчу с меньшим индексом. На стыке бусина есть только при чётном `seg`: это точка полуволны с `z = cz`.
- **Выступы** за крайние нити относятся к крайним патчам.
- **Ряд поперёк нити** определяется номером нити: нить основы `j` лежит в ряду `floor(j / patch_nx)` вдоль y, нить утка `i` — в ряду `floor(i / patch_ny)` вдоль x.

### Нечётный патч

Если `patch_ny` нечётно при `tile_x > 1` (или `patch_nx` нечётно при `tile_y > 1`), сдвиг на один патч меняет фазу волны на противоположную: соседний патч получается зеркальным, а не сдвинутым. Ткань остаётся корректной, так как нити непрерывны, но патчи не тождественны. Поэтому без `--allow-odd-patch` генератор выдаёт ошибку, с флагом печатает предупреждение `WARN plain_weave_quilt: ...`.

### Сверка с SCL-скриптом LS-PrePost

Скрипт `patch_60x60.scl` строит патч в LS-PrePost и тиражирует его с склейкой узлов. Его геометрия:

- основа вдоль x, уток вдоль −z, толщина по y;
- профиль — полуэллипсы, что в генераторе соответствует `--profile=arcs`;
- расчёты Guo 2019 используют профиль `cos`, поэтому сравнивать можно только вершины (пики и нули волны). SCL делит дугу элементами `elgenerate beam bycurve`, генератор — хордами равной длины.

Соответствие осей (из плана `fiber/plan-quilt-fabric.md`, раздел 6):

```text
x_gen = x_scl,   y_gen = −z_scl,   z_gen = y_scl
```

Возможны сдвиг начала координат и зеркало по z; знак фазы выясняется по первому пересечению.

Размер патча нужно проверить до сравнения. В имени скрипта указано 60×60, а `--patch=34x34` даёт 40,12 мм. Если в SCL другой размер патча, сравниваются только совпадающие по геометрии элементы.

Скрипт SCL ещё не проверен в LS-PrePost. Нужно подтвердить порядок фаз (основа и уток в противофазе в каждом пересечении) и накопление копий при `translate_model ... copy N`. Путь сверки: экспорт `.k` из LS-PrePost и импорт по [инструкции](03-ls-prepost-to-calculation.md), затем сравнение узлов.

### Сетка стёжки слоёв

Стёжка бывает двух видов. Режим `grid` связывает соседние слои пакета поперёк слоёв (2T, 4T и пакет `<k>T` при k ≥ 2). Режим `seam` (шов-строчка) идёт вдоль линии шва внутри каждого слоя и работает при любом числе слоёв, в том числе для одного слоя (1T). Линии шва совпадают с границами патчей (внутренние стыки `seam_x` и `seam_y`).

Функция `build_quilt_stitches` (`include/fiber/plain_weave_quilt.hpp`) строит список пар бусин:

- **Проколы.** Стежок ставится на бусину, которая лежит на линии шва. Линию `x = s` прокалывают нити основы, линию `y = s` — нити утка. Для этого нужна бусина на линии, то есть чётный `seg`; при нечётном `seg` функция выдаёт ошибку.
- **Шаг вдоль линии.** `every = N` оставляет прокол на каждой N-й поперечной нити (номер нити кратен N). По умолчанию `N = 1`, то есть прокол на каждой нити.
- **Пары.** Для каждого прокола и каждой пары соседних слоёв `(k, k+1)` строится связь между бусинами одной вертикали. Слои должны совпадать по составу нитей и бусин и лежать строго друг над другом. Пакет из N слоёв даёт N − 1 связей на прокол.
- **Глобальные индексы.** Бусины нумеруются сквозным счётом по слоям, затем по нитям и бусинам, в том же порядке, в каком `.fib` пишется слой за слоем.

#### Шов-строчка (`seam`)

Функция `build_quilt_seam_stitches` (тот же заголовок, те же `QuiltStitchParams` и проверки) прошивает каждый слой независимо:

- **Проколы.** Как в `grid`: на линии `x = seam_x[t]` у каждой нити основы ровно одна бусина-прокол (на линии `y = seam_y[t]` — у каждой нити утка); фильтр `every` тот же (номер нити кратен N). Нет бусины на линии (нечётный `seg`) — ошибка `std::invalid_argument`.
- **Пары.** Проколы сортируются вдоль линии (по y у основы, по x у утка), и соседние проколы соединяются стежком. При `every = 1` на линии с n поперечными нитями получается n − 1 стежок на слой; начальная длина `l0 ≈ every·pitch` (считается по координатам при загрузке, как у любой `BOND`).
- **Число.** Сумма по линиям (проколов − 1), умноженная на число слоёв. Для 1T на уровне smoke (12×12 нитей, `--stitch-tile=3`: 2 линии x и 2 линии y по 12 нитей) это 4·11 = 44 стежка, для base (102 нити) — 4·101 = 404.
- **Индексы.** Глобальные, в том же порядке, что у `build_quilt_stitches`; материал и запись в `.fib` те же (`MATERIAL 1`, `BOND i j 1`).

Стежки — связи только на растяжение с собственным материалом. В `.fib` они записываются так: материал стежка объявляется как `MATERIAL 1`, а каждая пара — строкой `BOND`:

```text
MATERIAL 1 <E> 0.3 <d> <rho> <eps_break>
BOND <i> <j> 1
```

Директива `BOND` описана в [справочнике формата](../03-reference/file-formats/fib-file.md#основные-директивы).

#### Флаги `guo2019_shot`

Флаги сцены Guo 2019 находятся в разработке. `--stitch=grid` требует пакета 2T или 4T, `--stitch=seam` допустим для любой конфигурации с тканью (1T, A/1T, 1T/A, 2T, 4T). По умолчанию стёжки нет (`--stitch=none`), расчёт прежний.

| Флаг | По умолчанию | Смысл |
|---|---|---|
| `--stitch=none\|grid\|seam` | `none` | Без стёжки, стёжка между слоями по сетке линий шва (`grid`) или шов-строчка внутри слоя (`seam`) |
| `--stitch-tile=N` | 3 | Число патчей вдоль каждой оси сетки стёжки (как `--tile=3x3`) |
| `--stitch-patch=P` | — | Вместо `--stitch-tile`: кусочки по P нитей симметрично от центра полотна, у краёв остаток (1…P нитей); число нитей на P делиться не обязано. Пример: 43 нити (`--fabric-n=43`), P = 5 — кусочки 4 + 7·5 + 4, по 8 линий шва вдоль каждой оси. При нечётном числе нитей P нечётно |
| `--stitch-lines=x\|y\|xy` | xy | Какие линии шва прошивать: вдоль x, вдоль y или обе |
| `--stitch-every=N` | 1 | Прокол на каждой N-й поперечной нити |
| `--stitch-E=<Па>` | 8.5e10 | Модуль Юнга материала стежка (85 ГПа) |
| `--stitch-d=<м>` | 0.2e-3 | Диаметр швейной нити |
| `--stitch-eps-break=<>` | 0.03 | Деформация разрыва стежка |

Остальные флаги `--stitch-*` действуют в обоих режимах; без `--stitch=grid|seam` они дают ошибку, в `shot.txt` пишется `stitch=grid` или `stitch=seam` и `n_stitch`.

#### Метрики стежков в мониторе

При наличии стежков в `monitor.csv` добавляются столбцы `n_stitch`, `n_stitch_broken`, `F_stitch_max`, `F_stitch_sum`, `slip_mean`, `gap_mean`; в сводку — `n_stitch_broken_end` и `slip_mean_end`. Для каждой исходной пары запоминается начальный вектор `r0 = x_j − x_i` и его длина.

- `slip_mean` — среднее по исходным парам плоской (x, y) нормы `r(t) − r0`. Для вертикальных пар `grid` начальный сдвиг в плоскости нулевой, и это просто взаимный сдвиг слоёв; для `seam` — изменение плоского вектора между проколами.
- `gap_mean` — среднее по исходным парам `|r(t)| − |r0|`, то есть удлинение пары. Для пар `grid` это изменение расстояния между слоями.
- `F_stitch_max`, `F_stitch_sum` — максимум и сумма сил по целым стежкам.

#### Ограничения модели

- Стежок работает только на растяжение: при сжатии силы нет. Разрыв наступает при `l > (1 + eps_break)·l0`.
- Масса швейной нити не учитывается, масса бусин не меняется.
- Повреждение нитей иглой не моделируется.
- Скольжение швейной нити вдоль нитей не моделируется: стежок закреплён в бусинах. Вариант с отдельной швейной нитью, которая проскальзывает по поверхности слоёв, отложен до следующего этапа.
- Прямой экспериментальной проверки нет: опыты Guo 2019 проводились на непрошитых пакетах. Сравнение возможно только по тенденциям из литературы.

#### Мотивация из литературы

- Bilisik, Turhan, *Textile Research Journal* 79(14), 2009: многонаправленно прошитые пакеты Kevlar. Поглощение энергии почти не меняется, но глубина вмятины на тыльной стороне меньше. Стёжка не даёт слоям свободно сдвигаться.
- Karahan, Kuş, Eren, *Int. J. Impact Eng.* 35(6), 2008: панели Twaron CT 710 с тремя типами стёжки. Число слоёв и тип стёжки заметно влияют на глубину и диаметр вмятины.
- Li, Zhang, Min, Zhou, Sun, *Defence Technology* 24, 2023: прошитые арамидные ткани поглощают больше непрошитых (до ~135 % для одного слоя и ~156 % для многослойной). Механизм связан с ограничением подвижности нитей и ростом трения. При слишком плотной стёжке поглощение снова падает.

## Примеры

### Генерация тестовой ткани (быстро)

```bash
./build/plain_weave_gen --preset=test --out=test.fib
```

Результат:
- 8 нитей (4×4)
- 136 бусин
- Время: несколько мс

### Генерация ткани Twaron с зажимом

```bash
./build/plain_weave_gen --preset=twaron_ct717 --out=twaron.fib
```

Результат:
- 204 нити (102×102)
- 86496 бусин, 3264 из них зажаты
- Толщина полотна: 0,78 мм
- Поверхностная плотность: 0,327 кг/м²
- Время: ≈0,1 с

### Свободная ткань с собственными параметрами

```bash
./build/plain_weave_gen --d=0.3e-3 --pitch=1.5e-3 --amp=0.15e-3 \
                        --nx=50 --ny=50 --seg=4 \
                        --out=custom.fib
```

Генератор выведет в `stdout` сводку: число нитей, бусин, связей, min/max l₀, толщину и поверхностную плотность.
