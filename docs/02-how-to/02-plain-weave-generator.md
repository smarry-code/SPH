# Генератор полотняного переплетения

Генератор `plain_weave_gen` создаёт ткань полотняного переплетения в формате файла нитей (`.fib`), который загружается в симулятор как отдельная геометрия. Устройство тканей (полотно, одеяло, стёжка, мозаика) объясняет страница [«Ткани»](../04-explanation/models/07-fabrics.md); ключи сцены Guo 2019 — [справочник `guo2019_shot`](../03-reference/guo2019-shot.md); формат раскройки — [`.cut.json`](../03-reference/file-formats/cut-json.md).

## Сборка

```bash
cmake --build <build> --target plain_weave_gen
```

Например:

```bash
cmake --build build --target plain_weave_gen
```

## Основные концепции

Генератор строит ткань в плоскости x–y с толщиной по оси z. **Основа** (warp) идёт вдоль оси x, **уток** (weft) вдоль оси y. В каждом пересечении нити контактируют волнистостью — основа и уток чередуют верхнее и нижнее положение.

Сгенерированный файл содержит:
- **`.fib`** — директива `MATERIAL 0 E ν d ρ ε_break [μ_ff [μ_fs]]` (поля трения пишутся, только если `--mu-ff`/`--mu-fs` не нулевые), по директиве `FIBER 0 <n>` с координатами бусин на каждую нить и, при зажиме, директивы `CLAMP_BOX`. В шапке-комментарии — командная строка, параметры и сводка
- **`.layout.txt`** — раскладка: метаданные о каждой нити

Коды выхода: `0` — успех (и `--help`); `2` — ошибка аргументов (неизвестный ключ, не число, нет `--out`, неизвестный пресет, `--patch` без `--tile` и наоборот, `--patch`/`--tile` или `--random-cut` вместе с `--nx`/`--ny`, `--random-cut` с `--patch`/`--tile`, ключи раскройки без `--random-cut`, `--allow-odd-patch` без `--patch`/`--tile`, отрицательный выступ); `1` — ошибка геометрии (например, `p < d` без `--allow-penetration`, `c_e` вне допустимого диапазона) или записи файла. Предупреждения (`WARN ...`, в том числе при `--allow-penetration`) выводятся в `stderr` и дублируются комментариями в `.fib`.

## Дискретизация

Бусины ставятся точно в каждое пересечение, между пересечениями — равные хорды:

- **На полуволне:** ровно **k** сегментов (связей) одинаковой длины, бусины стоят в вершинах (пересечениях).
- **Выступ:** при `e > 0` делится на `max(1, round(e/(p/k)))` сегментов, отдельно по направлениям; при `e = 0` выступа нет ([`overhang_chords`](../../include/fiber/plain_weave.hpp:371)).
- Длины связей l₀ в пределах полуволны (и выступа) совпадают до ~10⁻¹⁵ относительно. Это равные хорды, а не равные дуги: в модели связь — хорда.

## Зажим (CLAMP_BOX)

Параметр `--clamp` задаёт, какие нити закреплены с обоих концов:

- `--clamp=x` — нити вдоль x (горизонтальные)
- `--clamp=y` — нити вдоль y (вертикальные)
- `--clamp=xy` — обе группы
- `--clamp=none` — нет зажима (по умолчанию)

При `--clamp ≠ none` **обязателен** параметр `--clamp-edge=<м>` (граница зажима c_e). Генератор пишет две директивы `CLAMP_BOX` в `.fib`, по одной на каждый конец, с полным охватом по осям (допуск d); при `--clamp=xy` — четыре директивы (по две на каждую ось).

Допустимый диапазон c_e:
- Нижняя граница: `c_e ≥ (n_поперечных - 1) / 2 · p + d/2` (не попасть в пересечения)
- Верхняя граница: `c_e ≤ (n_поперечных - 1) / 2 · p + e` (хотя бы одна зажатая бусина на конце)

Если бусина попадает в зажим близко к границе c_e (в пределах 10⁻⁹·p), печатается предупреждение.

## Формат раскладки

Файл `<out>.layout.txt` содержит одну строку на нить:

```
object_id direction index offset clamped first_bead last_bead n_clamp_lo n_clamp_hi
```

- `object_id` — номер нити (0..nx-1 основа, nx..nx+ny-1 уток)
- `direction` — `x` (основа) или `y` (уток)
- `index` — индекс в направлении (0..nx-1 или 0..ny-1)
- `offset` — координата, перпендикулярная направлению (м)
- `clamped` — 1 если нить зажата, иначе 0
- `first_bead`, `last_bead` — глобальные индексы первой и последней бусин в файле `.fib`
- `n_clamp_lo`, `n_clamp_hi` — число зажатых бусин у начала и конца нити

## Известные ограничения

1. **Толщина полотна:** круглое сечение даёт толщину ≈2A + d, не реальную. Для пресета `twaron_ct717` это ≈0,78 мм против 0,4 мм в статье.

2. **Контакт в узлах при касании:** при 2A = d оси нитей в модели — хорды соседних бусин, а не гладкие кривые, и у узла хорды сближаются меньше чем на d. На исходной геометрии уже есть контакты: на геометрии Twaron 4 контакта (пары сегментов) на пересечение, проникание ≈9,6% d при k=2 и ≈3,8% d при k=4. При A = 0,6·d контактов на исходной геометрии нет (проверки 7/7б в `tests/test_plain_weave.cpp`).

3. **Плотность twaron_ct717:** 0,327 кг/м² против номинала 0,292 (статья: 0,28). Превышение складывается из удлинения нити волнистостью (хорды полуволны на ≈6% длиннее p) и выступов утка по 5 мм (+0,015 кг/м², ≈5%).

## Одеяло из патчей

Ткань-«одеяло» — прямоугольная сетка из `tile_x × tile_y` одинаковых патчей, каждый патч состоит из `patch_nx × patch_ny` нитей. Нити непрерывны через стыки патчей: соседние патчи не сшиваются отдельными связями, а образуют одну ткань. Геометрически результат совпадает с обычной тканью с `nx = tile_y·patch_nx` нитями основы и `ny = tile_x·patch_ny` нитями утка; шаг, профиль, выступы и зажим задаются так же, как для полной ткани.

Патчи одинаковы по построению. Сдвиг на один патч сохраняет фазу волны, если `patch_nx` и `patch_ny` чётны (см. правило нечётного патча ниже).

### Ключи

| Ключ | Смысл |
|---|---|
| `--patch=NXxNY` | Патч: `NX` нитей основы × `NY` нитей утка, например `34x34`. Размер патча вдоль x равен `NY·p`, вдоль y равен `NX·p` |
| `--tile=TXxTY` | Число патчей: `TX` вдоль x, `TY` вдоль y, например `3x3`. Ключи `--patch` и `--tile` задаются вместе |
| `--allow-odd-patch` | Разрешить нечётный размер патча при `tile > 1`. Без флага такой запуск завершается ошибкой, с флагом выводится предупреждение |

Ключи `--patch` и `--tile` несовместимы с `--nx` и `--ny`: при их наличии генератор выдаёт ошибку, потому что число нитей задаётся произведением `--tile` на `--patch`. `--allow-odd-patch` без `--patch` и `--tile` тоже ошибка. Остальные ключи (`--preset`, `--d`, `--pitch`, `--amp`, `--seg`, `--overhang-*`, `--clamp`, `--clamp-edge`, материал) действуют как обычно.

### Пример

```bash
./build/plain_weave_gen --preset=twaron_ct717 --patch=34x34 --tile=3x3 --out=quilt.fib
```

Три патча по 34 нити дают 3 · 34 = 102 нити в каждом направлении, то есть ту же ткань, что `--preset=twaron_ct717` без патчей. Шаг 1,18 мм, окно 101 · 1,18 = 119,18 мм. Размер одного патча 34 · 1,18 = 40,12 мм.

Генератор пишет три файла:

- `quilt.fib` — ткань целиком в формате `.fib` (одна `MATERIAL 0`, по блоку `FIBER` на нить);
- `quilt.fib.layout.txt` — раскладка нитей, тот же формат, что у обычной ткани (см. «Формат раскладки»);
- `quilt.fib.patches.txt` — принадлежность бусин патчам.

### Формат `.patches.txt`

Первые две строки — комментарии (`#`):

```text
# патчей 3x3 по 34x34 нитей (patch_nx x patch_ny); id патча = ty*tile_x + tx
# object_id direction index first_bead last_bead n_ranges {patch:first:last}...
```

Далее одна строка на нить, в порядке блоков `FIBER` в `.fib`:

```text
object_id direction index first_bead last_bead n_ranges patch:first:last [patch:first:last ...]
```

- `object_id`, `direction` (`x` — основа, `y` — уток), `index` — как в `.layout.txt`;
- `first_bead`, `last_bead` — глобальные индексы первой и последней бусины нити (с нуля, сквозной счёт по всему файлу);
- `n_ranges` — число отрезков нити, идущих подряд внутри одного патча;
- каждая тройка `patch:first:last` — id патча и глобальные индексы первой и последней бусины отрезка. Отрезки идут вдоль нити без пропусков и вместе покрывают все её бусины.

Идентификатор патча: `id = ty*tile_x + tx`, где `tx` — номер патча вдоль x (0 … TX−1), `ty` — вдоль y (0 … TY−1). Нить основы пересекает `TX` патчей (`n_ranges = TX`), нить утка — `TY` патчей.

Структура строки для нити основы в ряду `ty = 0` при `TX = 3`:

```text
0 x 0 <first> <last> 3 0:<a>:<b> 1:<b+1>:<c> 2:<c+1>:<last>
```

### Принадлежность бусин патчам (стыки)

Стык между патчами `t−1` и `t` вдоль x лежит посередине полуволны между вершинами `t·P − 1` и `t·P`, где `P = patch_ny`. Вдоль y — то же с `P = patch_nx`. Координата стыка:

```text
seam = c + (t·P − 1/2 − (n − 1)/2)·p,   n = ny (вдоль x) или nx (вдоль y)
```

Правила отнесения бусины к патчу:

- **Ряд вдоль нити** определяется координатой бусины относительно стыков. Бусина ровно на стыке (допуск `10⁻⁹·p`) относится к патчу с меньшим индексом. На стыке бусина есть только при чётном `seg`: это точка полуволны с `z = cz`.
- **Выступы** за крайние нити относятся к крайним патчам.
- **Ряд поперёк нити** определяется номером нити: нить основы `j` лежит в ряду `floor(j / patch_nx)` вдоль y, нить утка `i` — в ряду `floor(i / patch_ny)` вдоль x.

### Нечётный патч

Если `patch_ny` нечётно при `tile_x > 1` (или `patch_nx` нечётно при `tile_y > 1`), сдвиг на один патч меняет фазу волны на противоположную: соседний патч получается зеркальным, а не сдвинутым. Ткань остаётся корректной, так как нити непрерывны, но патчи не тождественны. Поэтому без `--allow-odd-patch` генератор выдаёт ошибку, с флагом печатает предупреждение `WARN plain_weave_quilt: ...`.

### Сверка с SCL-скриптом LS-PrePost

Скрипт `patch_60x60.scl` строит патч в LS-PrePost и тиражирует его с склейкой узлов. Его геометрия:

- основа вдоль x, уток вдоль −z, толщина по y;
- профиль — полуэллипсы, что в генераторе соответствует `--profile=arcs`;
- расчёты Guo 2019 используют профиль `cos`, поэтому сравнивать можно только вершины (пики и нули волны). SCL делит дугу элементами `elgenerate beam bycurve`, генератор — хордами равной длины.

Соответствие осей (из плана `fiber/plan-quilt-fabric.md`, раздел 6):

```text
x_gen = x_scl,   y_gen = −z_scl,   z_gen = y_scl
```

Возможны сдвиг начала координат и зеркало по z; знак фазы выясняется по первому пересечению.

Размер патча нужно проверить до сравнения. В имени скрипта указано 60×60, а `--patch=34x34` даёт 40,12 мм. Если в SCL другой размер патча, сравниваются только совпадающие по геометрии элементы.

Скрипт SCL ещё не проверен в LS-PrePost. Нужно подтвердить порядок фаз (основа и уток в противофазе в каждом пересечении) и накопление копий при `translate_model ... copy N`. Путь сверки: экспорт `.k` из LS-PrePost и импорт по [инструкции](03-ls-prepost-to-calculation.md), затем сравнение узлов.

### Сетка стёжки слоёв

Модель и обоснование стёжки описаны на странице [«Ткани»](../04-explanation/models/07-fabrics.md), ключи и файлы сцены Guo 2019 — в [справочнике `guo2019_shot`](../03-reference/guo2019-shot.md). Здесь только то, что нужно для запуска.

Стёжка бывает двух видов. Режим `grid` связывает соседние слои пакета поперёк слоёв (пакет `<k>T`, k = 1..64, при k ≥ 2: сетке нужно не меньше двух слоёв). Режим `seam` (шов-строчка) идёт вдоль линии шва внутри каждого слоя и работает при любой конфигурации с тканью, в том числе для одного слоя (1T). Линии шва совпадают с границами патчей (внутренние стыки `seam_x` и `seam_y`).

!!! note "Где пишутся стежки"
    `plain_weave_gen --patch/--tile` пишет **один слой без стежков**: `.fib`, `.layout.txt`, `.patches.txt`. Стежки в `.fib` пишут только `guo2019_shot` (`--stitch=grid|seam` и мозаика) и `plain_weave_gen --random-cut`.

Функция `build_quilt_stitches` (`include/fiber/plain_weave_quilt.hpp`) строит список пар бусин:

- **Проколы.** Стежок ставится на бусину, которая лежит на линии шва. Линию `x = s` прокалывают нити основы, линию `y = s` — нити утка. Для этого нужна бусина на линии, то есть чётный `seg`; при нечётном `seg` функция выдаёт ошибку. В пересечении двух линий шва прокола нет (там нет нити).
- **Шаг вдоль линии.** `every = N` оставляет прокол на каждой N-й поперечной нити (номер нити кратен N). Номер считается **от края** (нить 0 — крайняя), а не от центра, поэтому при чётном числе нитей и N > 1 проколы несимметричны. По умолчанию `N = 1`.
- **Пары.** Для каждого прокола и каждой пары соседних слоёв `(k, k+1)` строится связь между бусинами одной вертикали (длина покоя `l0 = Δ_ply`). Слои должны совпадать в плане (до `10⁻¹²·p`). Пакет из N слоёв даёт N − 1 связей на прокол.
- **Глобальные индексы.** Бусины нумеруются сквозным счётом по слоям, затем по нитям и бусинам, в том же порядке, в каком `.fib` пишется слой за слоем.

#### Шов-строчка (`seam`)

Функция `build_quilt_seam_stitches` (тот же заголовок, те же `QuiltStitchParams` и проверки) прошивает каждый слой независимо:

- **Проколы.** Как в `grid`; нет бусины на линии (нечётный `seg`) — ошибка `std::invalid_argument`.
- **Пары.** Проколы сортируются вдоль линии (по y у основы, по x у утка), и соседние проколы соединяются стежком горизонтальной связью; начальная длина `l0 = N·p` (N = `every`), обе бусины на `z = c_z` слоя. Слои между собой не связаны.
- **Индексы.** Глобальные, в том же порядке, что у `build_quilt_stitches`; материал и запись в `.fib` те же (`MATERIAL 1`, `BOND i j 1`).

#### Число стежков

Пусть `L_x`, `L_y` — число линий шва (после `--stitch-lines`), `n_x`, `n_y` — число нитей основы и утка (`nx`, `ny`), `N` — `--stitch-every`, `N_pl` — число слоёв:

$$
N_{grid} = (N_{pl} - 1)\left(L_x \left\lceil \frac{n_x}{N} \right\rceil + L_y \left\lceil \frac{n_y}{N} \right\rceil\right),
$$

$$
N_{seam} = N_{pl}\left(L_x \left(\left\lceil \frac{n_x}{N} \right\rceil - 1\right) + L_y \left(\left\lceil \frac{n_y}{N} \right\rceil - 1\right)\right).
$$

Примеры: 1T на уровне smoke (12×12 нитей, `--stitch-tile=3`: 2 линии x и 2 линии y), `seam` — 1·(2·11 + 2·11) = 44 стежка, для base (102 нити) — 4·101 = 404. Для `grid` значения 11 696 стежков (43 нити, `--stitch-patch=5`, 18T) и 6 192 (`--stitch-patch=9`, 19T) совпадают с формулой (`experiments/2026-11-14-fabric-kT-w50-ball1g-v550/README.md`).

Стежки — связи только на растяжение с собственным материалом. В `.fib` они записываются так: материал стежка объявляется как `MATERIAL 1`, а каждая пара — строкой `BOND`:

```text
MATERIAL 1 <E> 0.3 <d> <rho> <eps_break>
BOND <i> <j> 1
```

Порядок записи и директива `BOND` описаны в [справочнике формата](../03-reference/file-formats/fib-file.md#основные-директивы).

#### Флаги `guo2019_shot`

`--stitch=grid` работает для пакета `<k>T` при k ≥ 2, `--stitch=seam` допустим для любой конфигурации с тканью (1T, A/1T, 1T/A, `<k>T`). По умолчанию стёжки нет (`--stitch=none`), расчёт прежний.

| Флаг | По умолчанию | Смысл |
|---|---|---|
| `--stitch=none\|grid\|seam` | `none` | Без стёжки, стёжка между слоями по сетке линий шва (`grid`) или шов-строчка внутри слоя (`seam`) |
| `--stitch-tile=N` | 3 | Число патчей вдоль каждой оси сетки стёжки (1..1000, как `--tile=3x3`). `nx` и `ny` ткани должны делиться на N, иначе ошибка (код 2). Линии шва — посередине полуволны между нитями `tP − 1` и `tP`, P = n/N (для линий x — n = ny, для линий y — n = nx) |
| `--stitch-patch=P` | — | Вместо `--stitch-tile` (вместе — ошибка): центрированные кусочки по P нитей симметрично от центра полотна, у краёв остаток (1…P нитей); число нитей на P делиться не обязано. Пример: 43 нити (`--fabric-n=43`), P = 5 — кусочки 4 + 7·5 + 4, по 8 линий шва вдоль каждой оси; 43 нити, P = 9 — 8 + 9 + 9 + 9 + 8, 4 линии. Требуется P < n; при нечётном n и чётном P — ошибка (код 2); при чётном n и нечётном P линия шва проходит через центр |
| `--stitch-lines=x\|y\|xy` | xy | Какие линии шва прошивать: `x` — линии x = const (проходят вдоль y, прокалывают нити основы), `y` — линии y = const (вдоль x, нити утка) или обе |
| `--stitch-every=N` | 1 | Прокол на каждой N-й поперечной нити (счёт от края) |
| `--stitch-E=<Па>` | 8.5e10 | Модуль Юнга материала стежка (85 ГПа) |
| `--stitch-d=<м>` | 0.2e-3 | Диаметр швейной нити |
| `--stitch-eps-break=<>` | 0.03 | Деформация разрыва стежка |

Остальные флаги `--stitch-*` действуют в обоих режимах и в мозаике; без `--stitch=grid|seam` (и без `--random-cut`) они дают ошибку (код 2). `--eps-break`, `--fiber-E` и `--fiber-inelastic` относятся только к материалу 0, стежок остаётся упругим со своими параметрами. Коэффициент Пуассона и плотность стежка из командной строки не задаются (0,3 и 1440 кг/м³).

Поля `shot.txt` при стёжке: `stitch` (`grid` или `seam`), `stitch_patch` или `stitch_tile`, `stitch_lines`, `stitch_every`, `stitch_E`, `stitch_d`, `stitch_eps_break`, `n_stitch`. Файл `scene_id.txt` (пишется при `--checkpoint`) содержит строку `stitch=… patch=|tile=… lines=… every=… E=… d=… eps_break=… n_stitch=…`; `--restart` с другой стёжкой отклоняется.

!!! warning "Имя каталога без тега стёжки"
    Имя каталога выстрела `<cfg>_<level>[_nz][_bD…][_fN<n>ce<мм>ey<мм>][_rc…]_v<V0>_r<rep>` **не содержит тега стёжки**. Прогоны со стёжкой и без неё (и с разными `--stitch-*`) в одном `--out` с теми же остальными параметрами попадут в один каталог. Разводите их разными `--out`.

#### Метрики стежков в мониторе

При наличии стежков в `monitor.csv` добавляются столбцы `n_stitch`, `n_stitch_broken`, `F_stitch_max`, `F_stitch_sum`, `slip_mean`, `gap_mean`; в сводку — `n_stitch_broken_end` и `slip_mean_end` (только при пакете из двух и более слоёв). Для каждой исходной пары запоминается начальный вектор `r0 = x_j − x_i` и его длина.

- `slip_mean` — среднее по исходным парам плоской (x, y) нормы `r(t) − r0`. Для вертикальных пар `grid` начальный сдвиг в плоскости нулевой, и это просто взаимный сдвиг слоёв; для `seam` — изменение плоского вектора между проколами.
- `gap_mean` — среднее по исходным парам `|r(t)| − |r0|`, то есть удлинение пары. Для пар `grid` это изменение расстояния между слоями.
- `F_stitch_max`, `F_stitch_sum` — максимум и сумма сил по целым стежкам.

#### Ограничения модели

- Стежок работает только на растяжение: при сжатии силы нет. Разрыв наступает при `l > (1 + eps_break)·l0`.
- Масса швейной нити не учитывается, масса бусин не меняется.
- Повреждение нитей иглой не моделируется.
- Скольжение швейной нити вдоль нитей не моделируется: стежок закреплён в бусинах. Вариант с отдельной швейной нитью, которая проскальзывает по поверхности слоёв, отложен до следующего этапа.
- Прямой экспериментальной проверки нет: опыты Guo 2019 проводились на непрошитых пакетах. Сравнение возможно только по тенденциям из литературы.

#### Мотивация из литературы

- Bilisik, Turhan, *Textile Research Journal* 79(14), 2009: многонаправленно прошитые пакеты Kevlar. Поглощение энергии почти не меняется, но глубина вмятины на тыльной стороне меньше. Стёжка не даёт слоям свободно сдвигаться.
- Karahan, Kuş, Eren, *Int. J. Impact Eng.* 35(6), 2008: панели Twaron CT 710 с тремя типами стёжки. Число слоёв и тип стёжки заметно влияют на глубину и диаметр вмятины.
- Li, Zhang, Min, Zhou, Sun, *Defence Technology* 24, 2023: прошитые арамидные ткани поглощают больше непрошитых (до ~135 % для одного слоя и ~156 % для многослойной). Механизм связан с ограничением подвижности нитей и ростом трения. При слишком плотной стёжке поглощение снова падает.

## Случайная раскройка

Режим `--random-cut=N` строит ткань из N фрагментов полотняного переплетения, вырезанных по случайной диаграмме Вороного, а не из одной сетки. Модель и обоснование — на странице [«Ткани»](../04-explanation/models/07-fabrics.md); постановка — в `fiber/tz-random-cut-quilt.md`, код — в `include/fiber/plain_weave_random_cut.hpp`. Мозаика в сцене Guo 2019 описана ниже в разделе «Мозаика в `guo2019_shot`» и в [справочнике](../03-reference/guo2019-shot.md). Формат `.cut.json` — на [отдельной странице](../03-reference/file-formats/cut-json.md).

### Идея

- Прямоугольник W × H с центром `--center` замащивается диаграммой Вороного из N ячеек: N случайных центров и одна итерация Ллойда (центры переносятся в центроиды ячеек, ячейки считаются заново).
- У каждого фрагмента свой поворот сетки нитей `theta` и свой сдвиг фазы. Фрагменты разделены зазором `gap`. Нити обрезаны по границе фрагмента, выступов за край нет, нити не центрируются на `(nx − 1)/2`.
- Общих нитей у фрагментов нет. Они взаимодействуют контактом нить–нить, который считает ядро; генератор контакт в `.fib` не пишет.
- Фрагменты прошиты через швы стежками: связями `BOND` материала 1 между бусинами по обе стороны шва.

### Ключи

Единицы — метры и градусы. Ключи режима без `--random-cut` дают ошибку. Режим несовместим с `--nx`, `--ny`, `--patch`, `--tile`.

| Ключ | Умолчание | Смысл |
|---|---|---|
| `--random-cut=N` | — | Число фрагментов, 1 ≤ N ≤ 10000; включает режим |
| `--size=WxH` | 0.05x0.05 | Размер прямоугольника ткани, например `--size=0.05x0.05` (50 × 50 мм); оба размера > 0 |
| `--seed=S` | 1 | Зерно генератора случайных чисел |
| `--gap=<м>` | `d` | Зазор между фрагментами. Меньше `d` — ошибка, разрешить: `--allow-penetration` |
| `--rot-max=<град>` | 25 | Поворот сетки фрагмента равномерно в [−rot_max, +rot_max]; допустимо 0…180, 0 отключает поворот |
| `--stitch-step=<м>` | 2.4e-3 | Шаг стежков вдоль шва; 0 — без стежков |
| `--stitch-E=<Па>` | 5e9 | Модуль Юнга материала стежка (**заглушка**) |
| `--stitch-nu=<>` | 0.3 | Коэффициент Пуассона стежка (**заглушка**) |
| `--stitch-d=<м>` | 0.2e-3 | Диаметр швейной нити (**заглушка**) |
| `--stitch-rho=<кг/м³>` | 1000 | Плотность материала стежка (**заглушка**) |
| `--stitch-eps-break=<>` | 0.2 | Деформация разрыва стежка (**заглушка**) |
| `--rc=<м>` | 0.9e-3 | Радиус контакта, только для диагностики в `.cut.json` |
| `--layers=L` | 1 | Число слоёв пакета, 1 ≤ L ≤ 10000 |
| `--layers-per-cut=k` | L | Слоёв на одну раскройку, 1 ≤ k ≤ L |
| `--ply-pitch=<м>` | 2A + d + 1 мкм | Шаг слоёв по z (> 0) |

Значения стежка в генераторе (`--stitch-E`, `--stitch-nu`, `--stitch-d`, `--stitch-rho`, `--stitch-eps-break`) — заглушки, их задаст заказчица (ТЗ §9, материал стежка). В `guo2019_shot` материал стежка другой (см. ниже). Диапазон `rot_max` в генераторе [0, 180], а в `guo2019_shot` ключ `--cut-rot-max` ограничен 0…90.

Зажим по умолчанию `none`, в том числе у пресета `twaron_ct717`. Для зажима нужен явный `--clamp=x|y|xy` вместе с `--clamp-edge`. Боксы строятся по ограничивающему параллелепипеду бусин ± d; для `--clamp=y` это `[cy + c_e, hi]` и `[lo, cy − c_e]` (для x аналогично). Зажимаются **все** бусины всех нитей в боксе независимо от направления нити. Попадание c_e между нитями не проверяется; ошибка возникает, только если не зажато ничего.

Проверки (ошибка, с `--allow-penetration` — предупреждение `WARN`): `p < d`; `2A < d`; `gap < d`; при `L > 1` — `ply_pitch < 2A + d`. Защита от переполнения: оценка числа бусин $[2WH/(p h) + 8N(W+H)/p]\,L$ (здесь $h = p/seg$) не должна превышать $5\cdot10^7$.

### Алгоритм раскройки

Один вызов `make_cut` на группу слоёв; все группы берут числа из одного потока `mt19937_64(seed)`. Вещественные числа в [0, 1) строятся вручную как `(g() >> 11)·2⁻⁵³`, поэтому результат не зависит от стандартной библиотеки.

1. **Центры.** Равномерно в прямоугольнике с минимальным расстоянием между центрами `0,55·W/√N` (учитывается только W). После 10⁴ подряд отвергнутых кандидатов минимальное расстояние умножается на 0,97.
2. **Одна итерация Ллойда.** Центр переносится в центроид ячейки (прямоугольник ∩ полуплоскости биссектрис). При N = 1 центр — центр прямоугольника.
3. **Ячейки.** Ячейка `cell` — без сжатия; рабочий многоугольник `polygon` — каждая биссектриса сдвинута внутрь на `gap/2`. Края прямоугольника не сдвигаются: ткань доходит до края.
4. **Поворот и фаза.** После всех ячеек, по фрагментам подряд: три числа `θ = (2u − 1)·rot_max·π/180`, `fx`, `fy ∈ [0, 1)`.
5. **Швы.** Для каждой пары `i < j` берётся биссектриса ячеек, обрезается прямоугольником и остальными **несжатыми** биссектрисами ячейки `i`; шов существует, если его длина больше 10⁻⁹ м. Точки стежков: `ns = max(1, floor(L_seam/step))`, середины `ns` равных частей шва.

Порядок использования RNG: центры раскройки 0 (включая отказы), затем `θ` и фазы раскройки 0, затем раскройка 1 и т. д. Поэтому при `L = 1` результат совпадает с однослойным, а раскройка 0 пакета — с однослойным прогоном.

### Геометрия фрагмента

Для фрагмента с центром `c` и ортами `u = (cos θ, sin θ)`, `v = (−sin θ, cos θ)`:

- основа `j`: `c + (j + fx)·p·v + t·u`;
- уток `i`: `c + (i + fy)·p·u + t·v`.

Индексы `i`, `j` локальные и могут быть отрицательными. Вершины (пересечения) вдоль основы лежат на `t = (m + fy)·p`, вдоль утка — на `t = (m + fx)·p`. Фаза учитывается и вдоль нити, иначе вершины не совпали бы с поперечными нитями.

- Линия обрезается полуплоскостями фрагмента и **отбрасывается**, если результат пуст или короче `h/4`.
- Бусины: вершины и по `seg − 1` бусин равных хорд между ними, как в обычной ткани. Концевые бусины стоят точно на границе обрезки, если трёхмерная хорда до соседней бусины не меньше 0.2·h (h = p/seg). Иначе концевая бусина не добавляется. Нить из менее чем 2 бусин отбрасывается.
- Знак z: основа `(−1)^j`, уток `−(−1)^i`. В пересечении основа и уток разнесены по z на 2A.
- Фаза между фрагментами не согласуется.
- После построения проверяется минимальное расстояние в плане между бусинами разных фрагментов одного слоя: оно должно быть не меньше `gap − 10⁻⁹·p`, иначе `runtime_error`.

### Многослойный пакет

Слой `l` стоит на `c_z − l·ply_pitch`; слой 0 — верхний (лицевой), остальные ниже по z. Слои одной группы `g = l / k` (k = `--layers-per-cut`) делят одну раскройку: одинаковые многоугольники, поворот и фаза, слои сдвинуты только по z.

- Пример: 6 слоёв при `--layers-per-cut=2` дают три раскройки (слои 0–1, 2–3, 4–5; нумерация с нуля).
- Если L не делится на k, последняя группа короче (L = 3, k = 2 — раскройки слоёв `{0, 0, 1}`).
- По умолчанию k = L: одна раскройка на весь пакет.

Открытый вопрос ТЗ §9 о многослойности («пока один слой») закрыт: пакет из L слоёв и группировка k реализованы.

### Стёжка

Стёжка состоит из двух видов связей:

- **В слое (через шов).** В каждом слое берутся только швы его раскройки. Для каждой точки шва между ячейками `i` и `j` ставится `BOND` между ближайшей **в плане** бусиной фрагмента `i` и ближайшей бусиной фрагмента `j` того же слоя. При равенстве расстояний выбирается меньший индекс. Максимальную длину стежка генератор не ограничивает (в тестах она не больше `gap + 2p`).
- **Сквозная.** Для каждой пары соседних слоёв `(l, l+1)` и каждой точки швов **всех** раскроек пакета ставится `BOND` между ближайшими в плане бусинами любого фрагмента слоя `l` и слоя `l+1`. При одной общей раскройке стежок строго вертикален. Число сквозных стежков не больше `(L − 1)·Σ точек швов`.

Стежок привязан к ближайшей бусине, а не к нити или пересечению. Дубликаты пар убираются глобальным множеством. Порядок: сначала стежки в слоях, затем сквозные. Стежки работают только на растяжение, `l0` берётся по начальным координатам. Масса бусин швейной нитью не меняется.

### Выходные файлы

- **`<out>.fib`** — три строки комментария о раскройке; `MATERIAL 0`; при наличии стежков сразу после него `MATERIAL 1`; далее блоки `FIBER` в порядке слой → фрагмент → основа → уток; комментарий `# стёжка: N стежков (материал 1)`; строки `BOND i j 1`; при зажиме `CLAMP_BOX`. В шапке `nx`/`ny` — число нитей основы и утка по всему пакету, поверхностная плотность приведена к площади W × H.
- **`<out>.layout.txt`** — раскладка в прежнем формате (см. «Формат раскладки»).
- **`<out>.cut.json`** — данные для графика и проверок (формат `random_cut_v1`); поля описаны в [справочнике](../03-reference/file-formats/cut-json.md).
- **Сводка в stdout** — число фрагментов, швов, нитей, бусин, стежков, контактов, min/max `l0`, площади фрагментов и их сумма.

### Пример

```bash
./build/plain_weave_gen --preset=twaron_ct717 --random-cut=9 --size=0.05x0.05 --seed=3 --out=rc.fib
```

Результат: ≈14,4 тыс. бусин, 77 стежков; построение ≈0,01 с, с записью файлов ≈0,05 с.

Пакет из четырёх слоёв с раскройкой на два слоя:

```bash
./build/plain_weave_gen --preset=twaron_ct717 --random-cut=9 --size=0.05x0.05 --seed=3 \
                        --layers=4 --layers-per-cut=2 --out=rc4.fib
```

### Мозаика в `guo2019_shot`

`--random-cut=N` в `guo2019_shot` заменяет сплошную ткань уровня мозаикой (база — пресет `twaron_ct717`, `A = 0,6·d`, зажим `y`, `μ_ff = μ_fs = μ`).

| Ключ | Умолчание | Смысл |
|---|---|---|
| `--random-cut=N` | — | Число фрагментов, 1..10000 |
| `--cut-seed=S` | 1 | Зерно, S ≥ 0 |
| `--layers-per-cut=k` | 0 (весь пакет) | Слоёв на раскройку, 1..64; 0 — одна раскройка на весь пакет |
| `--cut-gap=<м>` | `d` | Зазор между фрагментами (> 0) |
| `--cut-rot-max=<град>` | 25 | Максимальный поворот, 0..90 |
| `--cut-stitch-step=<м>` | `p` | Шаг стежков вдоль шва (≥ 0; 0 — без стежков); по умолчанию прокол на каждую нить |
| `--cut-size=WxH` | поле уровня | Своё поле, м; оба размера > 0; центр (0, 0) |
| `--cut-clamp-edge=<м>` | c_e уровня | Граница зажима: зажаты бусины с `\|y\| ≥ c_e`; требуется `c_e < H/2` |

Поле по умолчанию — габарит сплошной ткани уровня: `W = (ny − 1)·p + 2·(p/2)` по x, `H = (nx − 1)·p + 2·e_y` по y (для `base` 120,36 × 129,18 мм); оно учитывает `--fabric-*`. Свой размер поля задаётся только парой `WxH`; своё поле меняет окно плотности на `(W − p) × (2c_e − p)`.

Материал стежка берётся из `StitchSpec` сцены (`E = 8,5·10¹⁰ Па`, `ν = 0,3`, `d = 0,2·10⁻³ м`, `ρ = 1440 кг/м³`, `ε_break = 0,03`), а не из заглушек генератора. Из командной строки меняются `--stitch-E`, `--stitch-d`, `--stitch-eps-break`; они работают и с `--random-cut`.

Ошибки (код 2): `--cut-*` или `--layers-per-cut` без `--random-cut`; `--random-cut` вместе с `--stitch=grid|seam`; `--random-cut` с `--config=A` (нужна ткань).

Имя каталога получает тег `_rc<N>s<S>k<k>` (k = 0, если ключ не задан); при `--cut-size` или `--cut-clamp-edge` — ещё `_f<W>x<H>c<ce>` (в мм; незаданная часть записывается как `L`, «значение уровня»). Примеры: `2T_base_rc30s1k2_v147.0_r0`, `…_rc7s1k0_f50x70c25_…`.

Файл `shot.txt` дополняется полями `random_cut`, `cut_seed`, `layers_per_cut`, `cut_count` (число раскроек), `cut_size`, `cut_clamp_edge`, `cut_gap`, `cut_rot_max`, `cut_stitch_step`, `cut_min_cross_dist`, `stitch_E`, `stitch_d`, `stitch_eps_break`, `n_stitch`, `n_stitch_in`, `n_stitch_through`. В `scene_id.txt` (с `--checkpoint`): `random_cut`, `seed`, `layers_per_cut`, `gap`, `rot_max`, `step`, `E`, `d`, `eps_break`, `n_stitch` и при своём поле `field=WxH clamp_edge=…`; `--restart` с другой сценой отклоняется. Рядом пишется `guo2019_fabric.cut.json`. В мониторе `slip_mean` и `gap_mean` усредняются только по сквозным стежкам.

### Ограничения и открытые вопросы

1. **Параметры стежка** генератора (E, d, ρ, ε_break, шаг) — заглушки до решения заказчицы (ТЗ §9); в `guo2019_shot` используется `StitchSpec`.
2. **Привязка стежков:** стежки соединяют ближайшие бусины, а не определённые нити или пересечения.
3. **Мелкие фрагменты** не объединяются с соседями.
4. **Нити через швы** не проходят: фрагменты разделены только стежками.
5. **Сетка стёжки** `build_quilt_stitches` для одинаковых слоёв здесь не используется: сквозная прошивка строится по ближайшим бусинам слоёв.
