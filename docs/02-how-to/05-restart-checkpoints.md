# Рестарт расчёта из чекпоинта

Длинные расчёты (выстрелы Guo 2019 идут часами) можно сохранять в **чекпоинт** и
продолжать с него после обрыва: нехватки диска, остановки сервера, снятия задачи.
Продолжение даёт то же состояние, что и непрерывный прогон (проверено побитово на
малой сцене, см. [«Что гарантируется»](#что-гарантируется)).

Модуль — [`include/checkpoint.hpp`](../../include/checkpoint.hpp),
[`src/checkpoint.cpp`](../../src/checkpoint.cpp); хуки в цикле — в
[`src/time_integration.cpp`](../../src/time_integration.cpp). Чекпоинты пишет и читает
перегрузка `time_integration(cfg, fiber::Model&, ...)`; перегрузка только для твёрдого тела
чекпоинтов не поддерживает. Из командной строки они доступны в `guo2019_shot`; основной
исполняемый файл `SPH` аргументов не принимает.

## Быстрый старт

```bash
# 1. Расчёт с чекпоинтом каждые 5000 шагов
guo2019_shot --config=1T --level=base --v0-list=100 --out=run1 \
    --checkpoint-every=5000

# 2. Расчёт оборвался -> продолжить с последнего чекпоинта (те же ключи физики!)
guo2019_shot --config=1T --level=base --v0-list=100 --out=run1 \
    --checkpoint-every=5000 --restart
```

Чекпоинт лежит в каталоге выстрела `<out>/<config>_<level>_v<V0>_r<повтор>/` (например,
`run1/1T_base_v100.0_r0/checkpoint.ckpt`; при `--plate-nz=N` в имя добавляется `_nzN` после уровня),
предыдущий — рядом в `checkpoint.ckpt.prev`.

## Ключи `guo2019_shot`

| Ключ | Действие |
|---|---|
| `--checkpoint` | Включить чекпоинты. Период по умолчанию — 10000 шагов |
| `--checkpoint-every=<N>` | Период в **шагах интегрирования**, `N >= 1`. Сам включает чекпоинты |
| `--restart` | Продолжить выстрел с `checkpoint.ckpt` (при повреждении — с `.prev`; если основного файла нет, а `.prev` есть, берётся он). Нет обоих файлов — ошибка, молчаливого старта с нуля нет |
| `--force` | Разрешить менять физические настройки при рестарте. Только вместе с `--restart` (иначе код выхода 2) |

Без этих ключей поведение расчёта прежнее, чекпоинты не пишутся.

## Что сохраняется

- Состояние цикла: `time`, `dt`, номер шага, `next_output_time`.
- Твёрдое тело: все поля частиц на реальных частицах (положения, скорости, плотность,
  энергия, напряжения, `hsml`, пластичность и повреждённость и т. д.).
- Поля частиц модели Джонсона–Кука: температура `T`, скорость деформации `edot` и
  начальный радиус `r0`, нужный для веса энергии в 2D осесимметрии.
- **Версия формата.** Чекпоинт нужен для быстрого рестарта той же сборкой, а не для хранения:
  читается только файл текущей версии формата, совместимости со старыми нет. Сообщение об
  ошибке называет версию файла и ожидаемую. После обновления кода, сменившего формат, расчёт
  начинается заново.
- Нити: положения и скорости бусин, `object_id`, топология (включая порядок связей,
  `version`), полное состояние связей (`BondState`: пластика, вязкость, повреждённость,
  работа), материалы, зажимы.
- История предиктора–корректора (`f^{n-1}`) и признак первого шага.
- Счётчики `RunGuard` (число шагов, `dt_first`, `dt_min`).
- При сборке с `SPH_ENERGY_LOG` — накопители энергии и база `E_mech0`.
- **Настройки запуска** (`SimulationConfig` целиком).

Геометрию и материалы сцена строит заново из аргументов; чекпоинт накладывается поверх
неё и **проверяет** совпадение размеров (число частиц, бусин, связей).

## Правила работы с рестартами

1. **Одна сцена — один набор аргументов.** При `--restart` указывайте те же `--config`,
   `--level`, `--v0-list`, `--mu`, `--fs-contact`/`--ff-contact`, `--dt-scale`, `.fib` и т. д., что и в первом запуске.
   Сцена собирается из аргументов, и расхождение размеров прервёт рестарт ошибкой, а
   расхождение настроек — отказом (см. п. 2).
2. **Физику при рестарте менять нельзя.** Свободно меняются только настройки запуска:
   `t_total`, `save_t`, `print_step`, `num_threads`, `energy_log_*`, `contact_stats_*`.
   Любое другое отличие (`CFL`, `dt_scale`, `ode_solver`, законы и параметры контактов,
   `alpha`/`beta`/`epsilon`, `sle`/`skf`/`nnps`, материалы, `maxn` и т. п.) — отказ со списком
   полей. Обход — только `--force`.
3. **`--max-steps` при рестарте — общий счётчик.** Счётчик шагов `RunGuard` восстанавливается
   из чекпоинта, поэтому чтобы досчитать 5 шагов после чекпоинта на шаге 10, укажите
   `--max-steps=15`. Лимит по стенному времени (`--time-limit`) отсчитывается заново.
4. **Не удаляйте `.prev`.** Если основной файл повреждён (обрыв во время записи,
   диск), рестарт автоматически пробует `checkpoint.ckpt.prev` и пишет предупреждение.
   Запись атомарная: сначала во временный файл, потом `rename`, поэтому полузаписанного
   `checkpoint.ckpt` не бывает; `.prev` отстаёт от основного на один период.
5. **Один каталог — один выстрел.** Рестарт перезаписывает кадры и CSV в каталоге выстрела
   с шага рестарта. Не запускайте два процесса в одном каталоге.
6. **Версия и сборка должны совпадать.** Чекпоинт хранит версию формата, `SPH_DIM` и флаги
   сборки (`SPH_ENERGY_LOG`, `SPH_CONTACT_STATS`). Несовпадение — ошибка. Бинарник
   можно пересобрать, но чекпоинт другой версии формата не читается и не конвертируется:
   после обновления кода, сменившего формат, расчёт начинается заново.

## Риски `--force`

`--force` применяет **новые** значения полей вместо сохранённых и печатает предупреждение.
Принимайте его только осознанно:

1. Траектория перестаёт быть продолжением исходного расчёта: результат нельзя сравнивать с
   непрерывным прогоном.
2. Смена `CFL`/`dt_scale`/`ode_solver` ломает историю предиктора (`f^{n-1}` посчитана другим
   шагом или схемой): возможен скачок и потеря устойчивости.
3. Смена контактов и материалов даёт разрыв по энергии; энергобаланс `EnergyLogger` теряет
   смысл, база `E_mech0` взята от старых настроек.
4. Смена `sle`/`skf`/`nnps`/`alpha`/`beta`: длины сглаживания, напряжения и искусственная
   вязкость несогласованы с новыми параметрами.
5. Смена `num_threads` нарушает побитовую воспроизводимость (порядок редукции OpenMP).
   Без `--force` она допускается, но результат уже не будет совпадать с непрерывным прогоном до бита.
6. Серия с разными настройками в одном выстреле нарушает вердикт Guo 2019: окно пробития
   подбиралось при других настройках.

Рекомендация: если настройки действительно нужно менять — считайте выстрел заново, а
`--force` оставляйте для отладки и для починки сбойного прогона.

## Рекомендации

- **Период.** Чекпоинт на крупной ткани занимает сотни мегабайт. Выбирайте период так,
  чтобы терять не больше 10–15 минут счёта; для выстрела с шагом ~1e-8 с и 1,5 мс счёта
  это порядка 1e4–1e5 шагов. Диск под два файла (`.ckpt` и `.prev`) на выстрел заложите
  заранее: на сервере диск уже заполнялся.
- **Потоки.** Побитовое совпадение с непрерывным прогоном гарантируется при том же числе
  потоков OpenMP. При другом `--threads` рестарт допустим без `--force`, но различия будут в
  младших разрядах; для сверки с эталоном используйте `OMP_NUM_THREADS=1`.
- **Окончание расчёта.** При штатном завершении и при останове сторожем (`RunGuard`) пишется
  финальный чекпоинт, поэтому расчёт можно продлить: увеличьте `t_total` и запустите
  с `--restart`. Если чекпоинт записан ровно при `time >= t_total`, а `t_total` не увеличен,
  рестарт сделает ноль шагов и один раз перезапишет файл.
- **Вердикт по шару и монитор.** Состояние `GuoShotMonitor` пока **не** сохраняется. После
  `--restart` монитор стартует заново: `monitor.csv` перезаписывается с шага рестарта,
  вердикт «пробит / не пробит» по шару и поля `steps`, `dt_mean`, `wall_s` в `shots.csv`
  неполные. Выстрел печатает об этом предупреждение. Не используйте рестартованный выстрел как
  точку в подборе окна пробития, пока состояние монитора не добавлено; итоговые кадры
  (`sph_output_*`, `fiber_output_*`) при этом верны.
- **Лог энергии.** При рестарте CSV `EnergyLogger` дозаписывается без второго заголовка и без
  повторной строки шага 0; после рестарта он совпадает с непрерывным (проверено тестом).
- **Код выхода.** `guo2019_shot` возвращает 0 даже если выстрел бросил исключение (в том
  числе `--restart` без файла): ищите в выводе `ОШИБКА` и `ВНИМАНИЕ: выстрелов с исключением`.
- **Диагностика.** Ошибки чтения называют причину: неверная сигнатура, версия формата,
  `SPH_DIM`, контрольная сумма (CRC), обрезанный файл, несовпадение размеров, список
  запрещённых отличий настроек вида `поле: было -> стало`.

## Что гарантируется

Проверено тестами ([`tests/test_checkpoint.cpp`](../../tests/test_checkpoint.cpp)) на малой
сцене (32 частицы твёрдого тела и две нити по 4 бусины, пластичность, повреждённость, разрыв):

- прогон 2N шагов и «N шагов, чекпоинт, рестарт, ещё N шагов» совпадают побитово (поля
  твёрдого тела и нитей, топология, `BondState`, `time`, `dt`) для решателей
  предиктор–корректор и Эйлера, в том числе когда связи рвутся до чекпоинта;
- порча байта, обрезание файла, неверная сигнатура приводят к ошибке;
- изменение `CFL`/`dt_scale` без `--force` отвергается, `t_total`/`save_t` проходят;
- период, ротация `.prev`, отсутствие временного файла;
- лог энергии после рестарта идентичен непрерывному;
- CLI: `--force` без `--restart` и `--checkpoint-every=0` дают код 2, разбитый на два запуска
  выстрел даёт те же итоговые кадры.

**Не проверено** (учитывайте при критичных расчётах): многопоточные прогоны на побитовость;
контакты твёрдое тело–нить и нить–нить (в тестовой сцене их нет); другой `SPH_DIM`; санитайзеры.
Для контактов рекомендуется перед длинной серией сделать пробный выстрел: с чекпоинтом на
середине и без, и сравнить итоговые кадры.
